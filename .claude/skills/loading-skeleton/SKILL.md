# โครงจางระหว่างรอข้อมูล — กฎกลาง ใช้ได้ทุกโปรเจกต์

> 🗺️ เปิดคู่กับ — **`offline-resilience`** เรื่องโหลดไม่สำเร็จ · **`web-craft`** เรื่องโครงหน้าจอ
> ตารางเต็มว่างานไหนต้องเปิดสกิลไหน อยู่ที่ `working-with-gun` ข้อ 0.0

> ตั้งขึ้น **27 สิงหาคม 2569** ตามที่พี่กันสั่ง:
> *"หน้าโหลดทุกหน้า ทำ skeleton ไว้ให้หมด และต้องโครงเหมือนกับเว็บ"*
> แล้วสั่งเพิ่มว่า *"ใส่เป็นสกิลกลางเลย ว่าต้องมี skeleton"*
>
> ⚠️ **พี่กันสั่งไว้ด้วยว่าเว็บอื่นยังไม่ต้องใส่** — สกิลนี้เป็นกฎสำหรับงานใหม่
> ส่วนเว็บเดิมที่ยังไม่มี ให้รอพี่กันสั่งทีละเว็บ ห้ามไปไล่ใส่เอง

## 🔴 กฎข้อเดียวที่สำคัญที่สุด

**โครงจางต้องมีรูปร่างเหมือนของจริง**

ตาราง 9 คอลัมน์ต้องได้โครง 9 คอลัมน์ที่กว้างเท่ากันเป๊ะ
ไม่ใช่กล่องสี่เหลี่ยมมั่ว ๆ ที่ไม่เกี่ยวกับหน้านั้น

ถ้ารูปร่างไม่ตรง ตอนข้อมูลมาถึงหน้าจอก็ยังกระโดดอยู่ดี = **ไม่ได้แก้อะไรเลย**

🚨 **วิธีที่รับประกันว่าตรง: ส่งชุดคอลัมน์จริงของหน้านั้นเข้าไป**
อย่าสร้างชุดใหม่ให้ตรงกันเอง เดี๋ยวหลุดกันภายหลังตอนมีคนแก้คอลัมน์

```jsx
skelTable(V.histCols, 9)     // ✅ ส่งของจริง
skelTable(myOwnCols, 9)      // ❌ สร้างเอง เดี๋ยวหลุด
```

## ทำไมต้องมี

ข้อความ "กำลังโหลด..." ลอยกลางที่ว่างมีปัญหา 3 อย่าง

| ปัญหา | ผลที่เกิด |
|---|---|
| ไม่บอกว่ากำลังจะได้อะไรมา | ผู้ใช้เดาไม่ออกว่าหน้านี้หน้าตายังไง |
| หน้าจอกระโดดตอนข้อมูลมาถึง | จากที่ว่างเปล่าเป็นตารางเต็ม ตาต้องหาจุดเริ่มใหม่ |
| ดูเหมือนเว็บค้าง | มากกว่าดูเหมือนกำลังทำงาน |

## 🚨 กฎ 6 ข้อ

### 1. เปิดโหมดดูโครงแล้วต้องไม่มีข้อมูลจริงเหลืออยู่เลย

> พี่กันทัก 27 ส.ค. 2569: *"เปิดโหมดนี้ ไม่โหลดข้อมูลจริงสิ"*

ของเดิมแค่**วาดโครงจางเพิ่ม**เข้าไป ข้อมูลจริงยังอยู่ครบ = ซ้อนกันสองชุด

**ทำที่จุดรวมค่าจุดเดียว** ทุกหน้าได้ผลพร้อมกัน — ถ้าไปดักทีละหน้าจะตกหล่นแน่นอน

```js
// vals/index.js — หลังรวมค่าทุกไฟล์แล้ว
if (app.state.skelDemo) {
  box.histRows = []; box.lotRows = []; box.catRows = [];  // ล้างรายการทุกหน้า
  box.histEmpty = false; box.lotsEmpty = false;           // ปิดธง "ไม่พบรายการ" ด้วย
}
```

🚨 **ต้องปิดธง "ไม่มีข้อมูล" ด้วย** ไม่งั้นจะขึ้นข้อความ "ไม่พบรายการ" ทับโครงจาง

### 2. ซ่อนของจริงทุกชิ้น ไม่ใช่แค่แถวในตาราง

ที่มักลืม — ปุ่ม "ดูเพิ่มอีก 60 รายการ" · ข้อความ "แสดง 60 จาก 84 รายการ" · แถบสรุปท้ายตาราง

```jsx
{V.histTruncated && !V.skelDemo && (...)}   // ✅
```

### 3. หน้าที่มีหัวตารางของตัวเองอยู่แล้ว ห้ามให้โครงจางวาดหัวซ้ำ

หัวจะซ้อนกันสองแถวทันที · ทำตัวเลือก `noHead` ไว้ในตัววาด

### 4. 🚨🔴 ระวังคลาสที่มี `position: sticky`

โครงจางมักใช้คลาสเดียวกับตารางจริงเพื่อให้ความกว้างตรงกัน
**แต่ถ้าคลาสนั้นมี `sticky` หัวจะลอยไปติดขอบบนแล้วไปโผล่กลางแถวจาง**

```jsx
style={s('...;position:static')}   // ✅ เขียนทับ
```

พี่กันเห็นเองแล้วทัก 27 ส.ค. 2569 — ในภาพหัวคอลัมน์อยู่กลางตาราง มีแถวจางทั้งบนและล่าง

### 5. หัวเรื่องที่วาดได้ทันทีต้องเป็นของจริง อย่าจางทั้งหน้า

> พี่กันทัก: *"สรุปควรเป็นหน้านี้เหรอ ต้อง skeleton ทั้งเว็บเหรอ"*

ปุ่มเลือกปีงบ · ชื่อหน้า · ปุ่มส่งออก · สวิตช์ธีม — พวกนี้ไม่ต้องรอเซิร์ฟเวอร์
**จางเฉพาะส่วนที่รอข้อมูลจริง**

### 6. ทุกหน้าที่รอข้อมูลต้องมี ไม่เว้นหน้าต่างซ้อน

> พี่กันทัก: *"รูปสี่ไม่มีโครงอ่ะ"* (หน้าต่างแก้ไขล็อต)

หน้าต่างซ้อนที่ยิงขอข้อมูลตอนเปิดก็ต้องมีโครงจางเหมือนกัน ไม่ใช่แค่หน้าหลัก

## 🎛 สวิตช์ให้พี่กันกดดูเอง

> พี่กันสั่ง: *"ใส่ปุ่มแสดง skeleton ในตั้งค่าด้วย เราจะกดแล้วเทส"*

ปกติโครงจางโผล่แค่เสี้ยววินาที ดูไม่ทันว่าหน้าตาถูกไหม
สวิตช์นี้บังคับให้ค้างไว้ทุกหน้า เดินดูทีละหน้าได้สบาย ๆ

🚨 **ไม่เก็บลงเครื่อง** — เป็นเครื่องมือดูงาน ไม่ใช่การตั้งค่าของผู้ใช้
ปิดเว็บแล้วเปิดใหม่ต้องกลับเป็นปกติเสมอ กันลืมเปิดค้างไว้แล้วเว็บใช้งานไม่ได้

```js
app.toggleSkelDemo = () => app.setState({ skelDemo: !app.state.skelDemo });
```

## 🔴🔴 "โหลดไม่สำเร็จ" ต้องไม่หน้าตาเหมือน "ไม่มีข้อมูล"

**สองสถานะนี้คนละเรื่องกันสิ้นเชิง แต่ถ้าไม่ตั้งใจแยก หน้าจอจะออกมาเหมือนกันเป๊ะ**

| สถานะ | ความจริงคือ | ผู้ใช้ควรทำอะไร |
|---|---|---|
| **ไม่มีข้อมูล** | ยังไม่มีใครบันทึกอะไร | กรอกข้อมูลได้เลย |
| **โหลดไม่สำเร็จ** | มีข้อมูลอยู่ แต่ดึงมาไม่ได้ | ลองใหม่ · เช็คเน็ต · **ห้ามเชื่อตัวเลขบนจอ** |

### 🔴🔴🔴 หน้าที่รายงานตัวเลข ต้องไม่วาดตัวเลขเลยตอนโหลดไม่สำเร็จ

> *"**หน้าสรุปหนักสุด** — เดิมเซิร์ฟเวอร์ล่มแล้ววาด **฿0.00 ทุกช่อง** เงียบ ๆ
>  ซึ่งเป็นหน้าที่เอาไปเสนอผู้บริหาร"*

**฿0.00 ไม่ใช่ "ไม่มีข้อมูล" แต่มันดูเหมือนตัวเลขจริง**
คนที่เปิดดูจะอ่านว่า "เดือนนี้ไม่มียาคืนเลย" แล้วเอาไปรายงานต่อ

🚨 **ขึ้นกล่องแจ้งเตือนไว้ข้างบนแล้วยังวาดตัวเลขข้างล่างอยู่ = ยังผิด**
เพราะคนกวาดตาผ่านจะเห็นแต่ตัวเลข **ต้องไม่วาดตัวเลขเลย**

ส่วนหน้าประวัติเคยขึ้นว่า *"ไม่พบรายการตามเงื่อนไขนี้"* **ทั้งที่ความจริงคือเน็ตหลุด**
ผู้ใช้จะไปไล่เปลี่ยนช่วงวันที่ ทั้งที่ปัญหาอยู่คนละที่

### วิธีทำ

**ต้องมีธงแยกต่างหาก ห้ามเดาจากผลลัพธ์ที่ว่าง**

```js
if (state.loadErr) → วาดหน้าโหลดไม่สำเร็จ (มีปุ่มลองใหม่)
else if (rows.length === 0) → วาด "ยังไม่มีรายการ"
else → วาดข้อมูล
```

🔑 **ใช้ตัววาดกลางตัวเดียวทุกหน้า** เพื่อให้หน้าตาเหมือนกันหมดและแก้ที่เดียว
(เว็บยาคืนใช้ `pages/loadfail.jsx` กับทั้ง 5 หน้า)

### 🧩 หลักการเดียวกันนี้ใช้กับสถานะอื่นด้วย

**บั๊กที่เจอซ้ำที่สุดในเว็บยาคืนคือ "สถานะที่หน้าตาเหมือนกันแต่คนละความหมาย"**

| คู่ที่สับสนกัน | เกิดอะไร |
|---|---|
| โหลดไม่สำเร็จ ↔ ไม่มีข้อมูล | หน้าสรุปวาด ฿0.00 |
| ยังหาไม่เจอ ↔ เลือกไปแล้ว | กดเลือกยาสำเร็จแล้ว แต่กล่อง **"ไม่พบยาชื่อนี้"** ยังค้าง |
| โค้ดพัง ↔ ไม่มีอะไรให้เรียก | ทั้งคู่ไม่มีอะไรเกิดขึ้น แยกไม่ออกว่าอันไหน |

🚨 **ทุกคู่แก้ด้วยหลักเดียวกัน — แยกด้วยธงต่างหาก ห้ามเดาจากความยาวหรือความว่างของผลลัพธ์**
