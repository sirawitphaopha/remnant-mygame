## 0 · ทำไมสกิลนี้ถึงต้องมี — เรื่องจริงที่เกิดแล้ว

เว็บ warfarin 21 ก.ย. 2569 · กดปุ่มบันทึก **หน้าจอขึ้นว่าสำเร็จทุกครั้ง**
แต่ผลแลป บันทึกแพทย์ วันนัด และการเปลี่ยนยา **ไม่เคยถูกส่งไปฐานเลย**
สาเหตุคือรายการที่ฟังก์ชันบันทึกเฝ้าดูไม่ครบ มันจึงส่งของชุดเก่าไปทุกครั้ง

🔴 **ไม่มีใครจับได้ เพราะทุกอย่างบนจอบอกว่าสำเร็จ** — จับได้ตอนเปิดฐานดูด้วยตาเท่านั้น

พี่กันถามตรง ๆ หลังรู้เรื่อง

> *"สิ่งสำคัญของเว็บคือการกรอกที่กรอกไปต้องบันทึกลง แต่เธอกลับเจอปัญหาว่ามันไม่บันทึก
>  ดังนั้นเราจะมั่นใจได้ยังไงว่ามันจะตกหล่นที่อื่น และควรมีระบบที่เอาไว้ตรวจการส่งข้อมูลไหม"*

**คำตอบของสกิลนี้** — ข้อความว่า "สำเร็จ" บนหน้าจอ **ไม่ใช่หลักฐาน**
ต้องมีชั้นที่พิสูจน์จากฝั่งฐาน และชั้นที่บอกคนกดตามจริงเมื่อของยังไม่ถึง

## 1 · 🔴🔴 ห้าชั้นบังคับ — เว็บที่มีปุ่มส่งข้อมูลต้องมีครบทุกชั้น

| ชั้น | ทำอะไร | บังคับไหม |
|---|---|---|
| ① **ปุ่มเปลี่ยนสถานะทันทีที่กด** | ขึ้น "กำลังบันทึก…" + ล็อกไม่ให้กดซ้ำ + ล็อกปุ่มยกเลิกข้าง ๆ ด้วย | 🔴 บังคับ |
| ② **แถบบอกผลหลังกด** | บอกชัดว่า **เข้าระบบ** หรือ **ยังไม่เข้าระบบ** · เห็นได้โดยไม่ต้องเลื่อนหา | 🔴 บังคับ |
| ③ **ลองส่งซ้ำเองเมื่อเน็ตสะดุด** | ลองซ้ำเฉพาะกรณีที่ยังไม่รู้ว่าถึงเซิร์ฟเวอร์ไหม | 🔴 บังคับ |
| ④ **คิวรอส่งในเครื่อง + แถบบอกว่ามีของค้าง** | เน็ตไม่ถึง = เก็บไว้ ปิดหน้าต่างได้ ส่งให้เองเมื่อเชื่อมต่อได้ | 🔴 บังคับเมื่อเป็นเว็บที่ใช้ในโรงพยาบาล |
| ⑤ **ชุดทดสอบส่งจริงแล้วอ่านกลับจากฐาน** | ส่ง → อ่านทุกคอลัมน์กลับมาเทียบ → ส่งซ้ำแล้วผลต้องเท่าเดิม | 🔴 บังคับ |

🚨 **ชั้น ⑤ คือชั้นเดียวที่จับบั๊ก "จอบอกว่าสำเร็จแต่ของไม่เข้า" ได้**
อีกสี่ชั้นเชื่อคำตอบของเซิร์ฟเวอร์ทั้งหมด ถ้าเซิร์ฟเวอร์ตอบ 200 โดยที่หน้าเว็บส่งของไม่ครบ ทุกชั้นจะบอกว่าสำเร็จหมด

### 🔑 ชั้นเสริมที่ควรมีในเว็บที่กรอกทีละหลายสิบเคส

| ของเสริม | เอามาจากเว็บไหน |
|---|---|
| ร่างอัตโนมัติ (เก็บสิ่งที่พิมพ์ไว้ในเครื่องระหว่างกรอก) | HCV · ME-DRP (0.12 วินาทีต่อครั้ง) |
| รหัสประจำการกดส่ง กันบันทึกซ้ำตอนเน็ตค้าง | HCV · ME-DRP (รหัสซ้ำ = ถือว่าสำเร็จ) |
| ตรวจว่าคำตอบเป็น JSON จริงก่อนอ่าน | HCV (Cloudflare ตอบหน้า HTML มาแล้วเว็บพัง) |
| ปิดบัง HN ก่อนเขียนร่องรอยข้อผิดพลาด | HCV (`logFail` + `maskHn`) |
| สั่นเครื่องเบา ๆ ตอนสำเร็จ | ยาคืน (ใช้เฉพาะเว็บที่ใช้บนมือถือ) |

## 2 · ปุ่มส่งข้อมูล — 4 สถานะ ต้องมีครบ

| สถานะ | หน้าตา | กฎ |
|---|---|---|
| ① กดได้ตามปกติ | ปุ่มทึบสีหลัก | — |
| ② กำลังบันทึก | ข้อความเปลี่ยนเป็น "กำลังบันทึก…" · กดไม่ได้ | 🔴 **ปุ่มยกเลิกข้าง ๆ ต้องล็อกด้วย** ไม่งั้นกดยกเลิกแล้วคำขอยังวิ่งอยู่ (ยกจาก ME-DRP) |
| ③ กดไม่ได้เพราะโหมด/สิทธิ์ | ปุ่มจาง + **เหตุผลติดข้างปุ่ม** | 🔴 ห้ามจางเฉย ๆ แล้วปล่อยให้เดาเอง |
| ④ กดไม่ได้เพราะกรอกไม่ครบ | ปุ่มจาง + **บอกว่าขาดช่องไหน** | 🔴 บอกชื่อช่องที่ขาด ไม่ใช่ "กรอกไม่ครบ" ลอย ๆ |

## 3 · แถบบอกผลหลังกด — กติกาที่ห้ามแก้เอง

| กฎ | เหตุผล | มาจาก |
|---|---|---|
| 🔴 **สำเร็จหายเอง · ผิดพลาดไม่หายเอง** | ข้อความผิดพลาดที่หายเองคือข้อความที่คนกรอกอาจไม่ทันอ่าน แล้วเข้าใจว่าบันทึกไปแล้ว | เว็บยาคืน |
| 🔴 **บรรทัดเดียวจบ** | พี่กันสั่ง 21 ก.ย. 2569 *"ไม่ต้องเอารายละเอียดผู้ป่วย เอาแค่บรรทัดแรก"* · ของที่ลงไปจริงไปดูที่แฟ้มผู้ป่วยได้ | warfarin |
| 🔴 **ลอยกลางล่างจอ ไม่ใช่กลางจอ** | คนกรอกนั่งกรอกติดกัน 20-29 เคส หน้าต่างที่ต้องกดปิดทุกครั้ง = งานเพิ่มหนึ่งคลิกต่อเคส | warfarin · DM |
| 🔴 **เห็นได้โดยไม่ต้องเลื่อนหา** | ปุ่มอยู่กลางหน้า พอกดแล้วข้อความอยู่ใต้ปุ่ม จอเลื่อนไปที่อื่นก็ไม่เห็นอะไรเลย | ME-DRP เคยโดน *"เรากดบันทึกการแก้ไข ทำไมมันไม่เปลี่ยนหน้าล่ะ"* |
| 🔴 **ปิดเองได้เสมอ** | กรณีผิดพลาดนี่คือทางเดียวที่แถบจะหายไป | ยาคืน |

### ข้อความบนแถบ — เขียนยังไง

🔴 **ต้องมีคำว่าเข้าระบบหรือไม่เข้าระบบเสมอ** ห้ามเขียนแค่ "สำเร็จ" หรือ "ผิดพลาด"

| กรณี | เขียนแบบนี้ |
|---|---|
| สำเร็จ | `บันทึกเคสใหม่แล้ว · <ชื่อคน>` |
| เซิร์ฟเวอร์ปฏิเสธ | `บันทึกไม่สำเร็จ — ข้อมูลยังไม่เข้าระบบ` + บรรทัดบอกว่าต้องทำอะไรต่อ |
| เน็ตไม่ถึง | `เชื่อมต่อระบบไม่สำเร็จ — บันทึกเคสนี้ไว้ในเครื่องแล้ว` + บอกว่าปิดหน้าต่างได้ |

### 🔴🔴 ภาษาบนแถบต้องเป็นภาษาทางการ

พี่กันด่าเต็ม ๆ 21 ก.ย. 2569 ตอนเจอคำว่า "เน็ตไม่ถึงระบบ" บนหน้าจอ

> *"เน็ตไม่ถึระบบคือคำเหี้ยไรรรรรรร ทางการเเล้วเหรอออ"*

| ❌ คำพูดกันเอง | ✅ คำที่ใช้บนจอ |
|---|---|
| เน็ตไม่ถึงระบบ · เน็ตหลุด | เชื่อมต่อระบบไม่สำเร็จ |
| เมื่อเน็ตกลับมา | เมื่อเชื่อมต่อได้ |
| ค้างส่ง | รอส่ง |
| ขึ้นระบบแล้ว | เข้าระบบแล้ว |
| ส่งเดี๋ยวนี้ | ส่งทันที |
| ปิดแท็บได้ | ปิดหน้าต่างได้ |

🔑 คำในคอมเมนต์โค้ดพูดบ้าน ๆ ได้ **แต่ทุกคำที่โผล่บนจอห้าม**

### 🔴 ข้อความไทยหลายท่อน ต้องแยกเป็นบรรทัดจริง

ภาษาไทยไม่มีช่องว่างคั่นคำ เบราว์เซอร์จึงตัดบรรทัดตรงไหนก็ได้

## 4 · แถบรายการรอส่ง — ของที่ยังไม่เข้าระบบห้ามค้างเงียบ

กลไกคิว (เก็บที่ไหน · อายุ · กันซ้ำ) อยู่ใน **`offline-resilience`** — ที่นี่คุมเฉพาะ **สิ่งที่คนเห็น**

| กฎ | รายละเอียด |
|---|---|
| 🔴 เห็นทุกหน้า | อยู่ใต้แถบเมนูบน ไม่ใช่เฉพาะหน้าที่กรอก |
| 🔴 บอกจำนวนและชื่อ | `รอส่ง 2 เคส — ยังไม่เข้าระบบ` + ไล่ชื่อคนกับวันที่ |
| 🔴 บอกว่าของไม่หาย | "บันทึกไว้ในเครื่องนี้แล้ว ปิดหน้าต่างได้ · ระบบจะส่งให้อัตโนมัติเมื่อเชื่อมต่อได้" |
| 🔴 มีปุ่มส่งทันที | สำหรับคนที่ไม่อยากรอ |
| 🔴 ส่งครบแล้วต้องยืนยัน | เปลี่ยนเป็นแถบเขียว "ส่งเข้าระบบแล้ว N เคส" ไม่ใช่หายไปเฉย ๆ |
| 🔴 ส่งให้เองเมื่อ | เปิดเว็บ · เชื่อมต่อได้ · กลับมาที่หน้าต่างนี้ · กดปุ่มส่งทันที |

🚨 **ข้อมูลผู้ป่วยจริงที่เก็บในเครื่อง = ต้องมีแถบนี้เสมอ** ไม่มีแถบ = คนกรอกเข้าใจว่าบันทึกแล้วทั้งที่ยังไม่เข้า

## 5 · ลองส่งซ้ำ — ซ้ำได้เฉพาะตอนที่ยังไม่รู้ผล

| คำตอบที่ได้ | ลองซ้ำไหม | เข้าคิวไหม |
|---|---|---|
| เน็ตไม่ถึง · รอจนหมดเวลา | ✅ ซ้ำ | ✅ เข้าคิว |
| เซิร์ฟเวอร์ตอบว่าไม่ผ่าน (กรอกไม่ครบ · ไม่มีสิทธิ์ · ยังไม่มีทะเบียน) | ❌ ห้ามซ้ำ | ❌ ห้ามเข้าคิว |
| รหัสซ้ำ (ส่งไปแล้วรอบก่อน) | ❌ | ถือว่า **สำเร็จ** (ยกจาก ME-DRP) |

🔴 **ห้ามเอาคำตอบที่เซิร์ฟเวอร์ปฏิเสธเข้าคิว** เพราะส่งอีกกี่รอบก็ได้คำตอบเดิม แล้วจะค้างในเครื่องไปตลอด

## 6 · 🔴🔴 พิสูจน์ว่าเข้าฐานจริง — สองอย่างที่ต้องมีในทุกเว็บ

### ① ชุดทดสอบส่งจริงแล้วอ่านกลับ

```
ลงทะเบียนคนทดสอบ → ส่งข้อมูลที่กรอกครบทุกช่อง → อ่านทุกคอลัมน์กลับจากฐานมาเทียบทีละช่อง
→ ส่งซ้ำอีกรอบด้วยของชุดเดิม ผลต้องเท่าเดิม (ไม่เพิ่มแถวซ้ำ ไม่หายไปไหน) → ลบคนทดสอบทิ้ง
```

- 🔴 **เทียบทีละช่อง ไม่ใช่เช็คว่าตอบ 200** — บั๊กที่เจอคือเซิร์ฟเวอร์ตอบ 200 แต่ของไม่ครบ
- 🔴 **ต้องเทียบค่าที่ฐานตัดแต่งแล้วด้วย** เช่นฝั่งเซิร์ฟเวอร์ตัดช่องว่างหัวท้าย ก็ต้องเทียบกับของที่ตัดแล้ว
- 🔴 HN ที่ใช้ทดสอบขึ้นต้นด้วย **999** เสมอ และต้องลบทิ้งทุกครั้งที่จบ
- เว็บ HCV มี 3 ตัว — ตัวแปลงข้อมูลก่อนส่ง · ยิงบันทึกจริง · กดส่งซ้ำ

## 7 · ของจริงจาก 5 เว็บพี่น้อง — อะไรเอามา อะไรไม่เอา

พี่กันสั่งให้ไปอ่านโค้ดทุกเว็บก่อนออกแบบ *"ย้ำว่าดูให้ละเอียด ห้ามดูคร่าว ๆ แล้วเดาเอง"*

| เว็บ | มีอะไร | เอามาไหม |
|---|---|---|
| **HCV** | ป๊อปกลางจอ 1.1 วิ + แถบมุมขวา 3 วิ · รหัสประจำการกดส่ง · ตรวจว่าได้ JSON จริง · `logFail` ปิดบัง HN · ร่างอัตโนมัติ · ชุดทดสอบ 3 ตัว | ✅ เอาทุกอย่าง **ยกเว้นป๊อปกลางจอ** — มันบังหน้าจอตอนกรอกติดกันหลายเคส |
| **ME-DRP** | ปุ่ม "กำลังบันทึก…" + ล็อกปุ่มยกเลิก · ลองซ้ำ 3 รอบ รอบละ 9 วิ · คิวค้างส่งในเครื่อง · รหัสซ้ำ = สำเร็จ · ร่างอัตโนมัติ 0.12 วิ | ✅ เอาทั้งหมด (รอบ/เวลาปรับตามเว็บได้) |
| **ยาคืน** | ข้อความเด้งมีตัวเลขประกอบ · สำเร็จหายเอง 4 วิ · ผิดพลาดไม่หายเอง · สั่นเครื่องเบา ๆ | ✅ เอากติกาหายเอง/ไม่หายเอง · สั่นเครื่องเฉพาะเว็บที่ใช้บนมือถือ |
| **TB** | กล่องกลางจอต้องกด "ตกลง" 3 สี | ❌ ไม่เอา — เพิ่มงานอีกหนึ่งคลิกต่อเคส |
| **DM** | ข้อความเด้งกลางล่างแบบสำเร็จรูป (ยังไม่มีสถานะกำลังบันทึก) | ✅ เอาตำแหน่งกลางล่าง · ❌ แต่ต้องมีสถานะกำลังบันทึกเพิ่ม |

🔑 **เว็บที่คนกรอกนั่งรวดเดียวหลายสิบเคส ห้ามใช้อะไรที่ต้องกดปิด** —
ป๊อปกลางจอและกล่องที่ต้องกดตกลง ตกรอบด้วยเหตุผลเดียวกัน

## 8 · ✅ เช็กลิสต์ก่อนบอกว่าเสร็จ

- [ ] ลองซ้ำเฉพาะกรณีเน็ต · คำตอบที่ปฏิเสธไม่เข้าคิว
