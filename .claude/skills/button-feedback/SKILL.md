# ปุ่มต้องตอบสนอง — กฎกลาง ใช้ได้ทุกโปรเจกต์

> 🗺️ เปิดคู่กับ — **`web-craft`** เรื่องหน้าจอรวม · **`form-input`** เรื่องปุ่มในฟอร์ม
> ตารางเต็มว่างานไหนต้องเปิดสกิลไหน อยู่ที่ `working-with-gun` ข้อ 0.0

> ตั้งขึ้น **27 สิงหาคม 2569** ตามที่พี่กันสั่ง: *"ใส่เรื่องปุ่มเปลี่ยนสี เป็นสกิลกลางด้วย"*
>
> ต้นเรื่องคือกฎที่พี่กันตั้งไว้ 26 ส.ค. 2569:
> *"เอาจริง ๆ นะ ทุกปุ่มควรเปลี่ยนสีตอนเอาเมาส์ไปชี้ ตั้งเป็นกฎการออกแบบ
>  เราขี้เกียจสั่งเธอให้ทำอันนี้แล้ว"*
>
> ทำเป็นสกิลกลางเพราะเว็บของพี่กันมีหลายตัว และเรื่องนี้พลาดซ้ำมาแล้วหลายรอบในเว็บเดียว


## 🛑 ด่านตรวจก่อนบอกว่าหน้าไหนเสร็จ — ชี้ปุ่มจริงก่อนดูอย่างอื่น

> เพิ่ม **23 กันยายน 2569** หลังเจ้าของงานเปิดหน้าคลังวิธีบริหารยาแล้วเจอเองใน 5 วินาที
> ว่าปุ่มไม่เปลี่ยนสี **ถามซ้ำหลายรอบว่ายังขาดอะไร แคลร์ตอบไม่ได้สักรอบ**
> พออ่านสกิลครบแล้วไล่เทียบ พบว่า **25 จาก 29 ปุ่มในหน้านั้นชี้แล้วไม่เปลี่ยนอะไรเลย**

### 🔴🔴🔴 ของที่ "ขาด" ไม่มีวันโผล่ตอนไล่อ่านโค้ด

โค้ดปุ่มทั้ง 25 ตัว **ถูกทุกบรรทัด** ไม่มีอะไรผิดให้เห็น สิ่งที่ผิดคือของที่ไม่เคยถูกเขียน

| วิธีตรวจ | เจอของที่ขาดไหม |
|---|---|
| อ่านโค้ด · `grep` หาคำ | ❌ เจอได้แต่สิ่งที่เขียนไว้แล้ว |
| **ไล่เช็คจากรายการว่าต้องมีอะไรบ้าง** | ✅ **ทางเดียวที่จับได้** |

🚨 **ถูกถามว่า "ยังขาดอะไรไหม" ห้ามตอบจากความจำ** เปิดสกิลอ่านให้จบก่อน แล้วไล่เช็คทีละข้อ

### 🔴🔴🔴 เริ่มตรวจจากของที่นิ้วคนแตะก่อนเสมอ

คนใช้เปิดหน้ามาแล้วเอาเมาส์ชี้ปุ่มเป็นอย่างแรก **ไม่มีใครเริ่มจากโครงสร้างหน้า**
ตรวจตามลำดับที่คนใช้จริงแตะ — ปุ่ม · ชิป · ช่องกรอก · ลิงก์ แล้วค่อยไปเรื่องลึก

```js
// ชี้จริงแล้ววัดก่อนและหลัง ไม่ใช่อ่านว่าเขียนกฎไว้ไหม
const g = getComputedStyle(ปุ่ม);
// hover แล้ววัดซ้ำ — ได้ค่าเท่าเดิมทุกช่อง = ปุ่มนั้นไม่ตอบสนอง
```

🔑 **จับปุ่มที่ตกหล่นทั้งหน้าในคำสั่งเดียว** — หาปุ่มที่ไม่มีกฎ `:hover` ตรงกับมันเลยสักข้อ

```js
const rules = [];
for (const sh of document.styleSheets) {
  try { for (const r of sh.cssRules) if (r.selectorText?.includes(':hover')) rules.push(r.selectorText); } catch (e) {}
}
[...document.querySelectorAll('button,[role="button"]')]
  .filter(b => !rules.some(s => { try { return b.matches(s.replace(/:hover/g, '')); } catch (e) { return false; } }))
  .map(b => b.innerText.trim());   // ต้องได้รายการว่าง
```

### 🔴🔴🔴 โดนชี้ปุ่มไหน ต้องไล่หาพี่น้องของมันในไฟล์เดียวกันทันที

**22 ก.ย. 2569** เจ้าของงานทักว่าปุ่มล้างคำค้นไม่เปลี่ยนสี แคลร์แก้ปุ่มนั้นตัวเดียวจบ
**ไม่ได้ไล่ดูปุ่มอื่นในไฟล์เดียวกันเลย** ทั้งที่ต้นเหตุเดียวกันเป๊ะคือเขียนสีฝังในแท็ก
วันรุ่งขึ้นเจ้าของงานเจออีก 25 ปุ่มที่เป็นโรคเดียวกัน

🚨 **แก้เฉพาะจุดที่ถูกชี้ = งานยังไม่เสร็จ** ทุกครั้งต้องถามว่าต้นเหตุนี้กระทบอีกกี่จุด
**แล้วนับออกมาเป็นตัวเลข** ก่อนบอกว่าแก้แล้ว

🔑 **ตัวเลขบอกความจริง** — หลุดหนึ่งสองตัวคือลืม แต่หลุดเกือบทั้งหน้าแปลว่า
**ตอนสร้างหน้านั้นไม่ได้เปิดสกิลนี้อ่านเลย**

# 🔴 กฎ 8 ข้อ

## 1. ทุกปุ่มต้องเปลี่ยนตอนเอาเมาส์ชี้

ไม่มีข้อยกเว้น **นอกจากปุ่มที่พี่กันสั่งเองว่าไม่ต้อง**

รวมถึงปุ่มที่คนมักลืม:
- ปุ่มที่กดไม่ได้ (ต้องเปลี่ยน แต่เปลี่ยนแบบไม่ทำให้ดูเหมือนกดได้)
- หัวคอลัมน์ที่กดเรียงได้ (เป็นปุ่มชนิดหนึ่ง)
- ชื่อเว็บที่กดกลับหน้าแรกได้
- แถบเตือนที่กดปิดได้
- ฉากรับการกดนอกเมนู **ไม่ใช่ปุ่ม** ไม่ต้องมี

## 2. 🚨 ห้ามใช้กฎกลางครอบทุกปุ่ม

> *"อันนี้งานละเอียด ห้ามสร้างโค้ดแล้วให้ทุกปุ่มเปลี่ยน ต้องแก้มือทุกปุ่มเท่านั้น"*
> *"คิดทุก ๆ ปุ่ม ไม่เอาค่าตั้งต้น ต้องดูทีละปุ่มแล้ววิเคราะห์เท่านั้น"*

```css
/* ❌ ห้าม — ปุ่มพื้นขาวจะแทบไม่เปลี่ยน ปุ่มพื้นเข้มจะสว่างจนตัวหนังสือกลืน */
[role="button"]:hover { filter: brightness(.94); }
```

สีที่ถูกต้องขึ้นกับพื้นของปุ่มนั้น กฎกลางทำให้บางปุ่มดู**จางลง**แทนที่จะเด่นขึ้น

### 🔑 เส้นแบ่ง — กฎนี้ห้ามเฉพาะ "เรื่องที่คำตอบขึ้นกับบริบท" ไม่ได้ห้ามกฎกลางทุกชนิด

**เขียนไว้ 5 ก.ย. 2569** หลังพบว่ากฎข้อนี้ถูกเอาไปใช้ผิดที่ — ที่ ME-DRP กฎ 16px กันไอโฟนซูม
เป็นทางที่ **ถูกต้องแล้ว** ที่จะครอบทุกช่องด้วยกฎเดียว แต่ถ้าอ่านข้อนี้อย่างเดียวจะนึกว่าห้าม

| ประเภท | ใช้กฎกลางครอบได้ไหม | ตัวอย่าง |
|---|---|---|
| **คำตอบเดียวถูกต้องเสมอ ไม่ขึ้นกับบริบท** | ✅ **ครอบได้ และควรครอบ** | ช่องกรอกมือถือต้อง ≥16px (กันไอโฟนซูม) · พื้นที่กด ≥44px · `overscroll-behavior:contain` |
| **คำตอบขึ้นกับของแต่ละชิ้น** | ❌ **ห้ามครอบ ต้องดูทีละตัว** | สีตอนเอาเมาส์ชี้ · ขนาดปุ่ม · ระยะห่าง · ข้อความบนปุ่ม |

**วิธีตัดสิน — ถามว่า "ถ้าครอบทุกตัวด้วยค่าเดียวกัน จะมีตัวไหนแย่ลงไหม"**
- ตอบว่า **ไม่มี** (16px ไม่เคยทำให้ช่องไหนแย่ลง) → ครอบได้ และครอบดีกว่า
  เพราะ**ครอบของที่จะสร้างวันหน้าด้วย** ไม่ต้องมาไล่เติมทีละตัวแล้วลืม
- ตอบว่า **มี** (สีตอนชี้ทำให้ปุ่มพื้นขาวจางลง) → ห้ามครอบ ต้องแก้ทีละตัว

## 3. 🚨 สีตอนชี้ต้องอยู่ในโทนของปุ่มนั้น

> *"กรอบมันสีแดงนะ จุ้มไปต้องสีแดงสิ"*
> *"สีควรเข้ากับปุ่มนั้น ไม่ใช่ใส่แค่สีเทาเข้ม ต้องเข้ากับธีม"*

| ปุ่ม | ชี้แล้วต้องเป็น | ห้ามเป็น |
|---|---|---|
| ปุ่มลบ · ปุ่มทำลาย (แดง) | แดงเข้มขึ้น หรือพื้นแดงจาง | **เขียว** |
| ปุ่มบันทึก · ปุ่มยืนยัน (เขียว) | เขียวเข้มขึ้น | แดง · เทา |
| ปุ่มเตือน (ส้ม/อำพัน) | ส้มเข้มขึ้นในโทนเดิม | น้ำตาลเข้มจนดูคนละปุ่ม |
| ปุ่มพื้นขาว | สีจางของธีมหลัก + ขอบสีธีม | **เทากลาง** |

🚨 **ปุ่มที่ตอนปกติเป็นขาวหรือเทา ต้องตัดสินจากความหมายของปุ่ม ไม่ใช่จากสีพื้น**
ปุ่ม "ทำลาย" ที่พื้นใสตัวหนังสือเทา ก็ยังต้องชี้แล้วเป็นแดง

## 4. 🚨 ห้ามตั้งสีตอนชี้เป็นสีเดียวกับพื้นปุ่มเอง

```css
/* ❌ ปุ่มพื้น #e3f0e8 อยู่แล้ว ชี้แล้วไม่เปลี่ยนอะไรเลย */
.hv-bg-e3f:hover { background: #e3f0e8 !important; }
/* ✅ */
.hv-bg-e3f:hover { background: #cfe6da !important; }
```

เคยพลาดจนมีปุ่ม 24 จุดที่ชี้แล้วไม่มีอะไรเกิดขึ้น

**กฎเดียวกันใช้กับลิงก์** — ลิงก์สีเทล `#2f7d5d` ห้ามตั้งสีตอนชี้เป็น `#2f7d5d`

## 5. 🚨 ปุ่มที่พื้นเข้มอยู่แล้วไม่ต้องเข้มเพิ่มมาก

พี่กันสั่ง *"ปุ่มไหนที่เข้มอยู่แล้วไม่ควรเข้มเพิ่ม"*

ปุ่มพื้นเขียวทึบตัวหนังสือขาว ชี้แล้วเข้มขึ้นนิดเดียวพอ
เข้มมากจะกลายเป็นดำ ตัวหนังสือขาวยังอ่านได้แต่ปุ่มดูตาย

## 6. 🚨 อันที่ทำงานถูกอยู่แล้ว ห้ามไปแก้ให้แย่ลง

> *"อันไหนมันเปลี่ยนสีอยู่แล้วก็อย่าไปแก้ให้มันห่วยขึ้นสิวะ"*
> *"อันไหนดีแล้วก็เอาไว้นะ ไม่ใช่ถอนหมด เอาอันที่เธอเช็คแล้วมันแปลก"*

ก่อนแตะปุ่มไหน ต้องดูก่อนว่ามันเปลี่ยนสีอยู่แล้วหรือเปล่า

## 7. 🚨 ปุ่มที่เปลี่ยนสีตามสถานะ ต้องสลับคลาสตอนชี้ด้วย

```jsx
/* ❌ ตอนอยู่ในถังขยะปุ่มเป็นพื้นเขียวตัวหนังสือขาว
      ชี้แล้วพื้นกลายเป็นขาวนวล ตัวหนังสือขาวกลืนหายไป */
className="hv-bg-f6"
/* ✅ */
className={V.histTrash ? 'hv-teal' : 'hv-bg-f6'}
```

ตระกูลเดียวกับบั๊ก `border-color` เดี่ยวใน hover — เขียนครึ่งเดียวแล้วอีกครึ่งค้างของเก่า

🚨 **เขียน `border` เต็มประโยค ไม่ใช่ `border-color` เดี่ยว**
```css
/* ❌ ความหนากับชนิดเส้นค้างของเดิม กลายเป็นขอบดำหนา */
.x:hover { border-color: rgba(47,125,93,.34) !important; }
/* ✅ */
.x:hover { border: 1px solid rgba(47,125,93,.34) !important; }
```

## 8. 🚨 รายงานเรื่องสีต้องให้พี่กันเห็นของจริง

> *"เรามองเห็นสีเหรอ ตั้งกฎเลย เขียน code สีดีแล้ว แต่เอาสีให้เราเห็นด้วยยยย"*

**ห้ามส่งรหัสสีให้อ่าน** — `#dde0dc` พี่กันมองไม่ออกว่าคือสีอะไร

ใช้อย่างใดอย่างหนึ่ง:
- **มอคอัป HTML ให้กดดู** (ดีที่สุดสำหรับแอนิเมชัน เพราะภาพนิ่งดูไม่ได้)
- **ภาพถ่ายหน้าจอจริง** ทั้งก่อนชี้และตอนชี้
- **เรียกชื่อสีเป็นภาษาคน** — เขียวอ่อน · แดงจาง · ครีมอมเหลือง

| พื้นปุ่มตอนปกติ | ตอนชี้ | ตัวอย่าง (ธีมเขียว) |

## 🚨🔴 ใส่แอนิเมชันได้เฉพาะปุ่มที่พี่กันสั่งเองเท่านั้น

**พี่กันสั่ง 27 ส.ค. 2569: *"ปุ่มไหนอนิเมชั่น เราบอกเอง"***

ห้ามคิดเองว่าปุ่มนี้ควรมี · ห้ามยกชุดจากปุ่มที่พี่กันสั่งไปใส่ปุ่มอื่นที่ดูคล้ายกัน
แม้จะเป็นปุ่มที่ทำหน้าที่คล้ายกันแค่ไหนก็ตาม

**บทเรียน 27 ส.ค. 2569** — พี่กันสั่งแอนิเมชันสั่นให้ปุ่มบันทึกตอนยังไม่เลือกยา
แคลร์เห็นว่าปุ่ม "เพิ่ม" ก็เป็นปุ่มที่กดไม่ได้เหมือนกัน เลยยกชุดครีมอมเหลือง + สั่นไปใส่ด้วย
โดยอ้างกฎ "อะไรที่คล้ายกันต้องทำให้เหมือนกัน" — **พี่กันสั่งเอาออกทันที**

> *"ปุ่มเพิ่ม ไม่เอาอนิเมชั่น ไม่ได้บอก แล้วปุ่มมันจริง ๆ สีเขียว ก็แค่เปลี่ยนสีเขียวปกติ"*

**สองบทเรียนในประโยคเดียว**
1. แอนิเมชันไม่ใช่ของที่ลามไปเองได้ ต้องได้รับคำสั่งรายปุ่ม
2. **ปุ่มที่กดไม่ได้ ต้องใช้สีของปุ่มตัวเองที่จางลง** ไม่ใช่ยกสีจากปุ่มอื่นมา
   ปุ่มเขียว → เขียวจาง · ปุ่มแดง → แดงจาง · ไม่ใช่ครีมของปุ่มที่พี่กันสั่งไว้อีกตัว

## ใช้เมื่อไหร่

| ใช้ | ไม่ใช้ |
|---|---|
| **พี่กันสั่งปุ่มนั้นตรง ๆ** | **ทุกกรณีที่พี่กันไม่ได้สั่ง** |
| | ปุ่มที่ดูคล้ายกับปุ่มที่พี่กันเคยสั่ง |
| | ปุ่มที่กดบ่อยทุกวัน (น่ารำคาญ) |

## กฎ 4 ข้อ (เมื่อได้รับคำสั่งแล้ว)

1. 🚨 **ต้องจางหายเมื่อจบ ห้ามค้าง** — ชั้นที่ค้างอยู่ก็คือการเปลี่ยนสีถาวรนั่นเอง
   ถ้าปุ่มนั้นถูกสั่งว่า "ห้ามเปลี่ยนสี" การใส่ `forwards` เท่ากับละเมิดคำสั่ง
2. 🚨 **ต้องมี `@media (prefers-reduced-motion: reduce)` เสมอ**
   เจ้าหน้าที่บางคนเวียนหัวกับภาพเคลื่อนไหว
   🚨🔴 **ต้องคืนค่าปลายทางด้วย ไม่ใช่ปิดแค่จังหวะ** — ปิด `transition` อย่างเดียว
   ของที่กำลังวิ่งอยู่จะ**ค้างอยู่ในสภาพกลางทาง** (ปุ่มค้างเล็ก · กล่องค้างเอียง · แถบค้างครึ่งจอ)
   ```css
   @media (prefers-reduced-motion: reduce) {
     * { transition: none !important; animation: none !important; }
     button:active { scale: 1; }        /* คืนค่าปลายทางให้ทุกตัวที่เคยขยับ */
   }
   ```
   🚨 **กวาดให้ครบทุกอย่างที่ขยับ** ไม่ใช่แค่ปุ่ม — ป๊อปที่เลื่อนขึ้น · แถบที่ไถลเข้า ·
   ตัวเลขที่วิ่งนับ · โครงจางที่กะพริบ ทุกตัวต้องมีสภาพจบให้
3. 🚨 **ห้ามบังตัวหนังสือ** — ชั้นซ้อนต้องจางพอที่ยังอ่านออก
   หรือใส่ `z-index` ให้เนื้อหาอยู่บน (`.x > * { position: relative; z-index: 1 }`)
4. 🚨 **ทำด้วยชั้นซ้อน `::before` / `::after` ไม่แตะสีจริงของปุ่ม**
   ต้องใส่ `position: relative` กับ `overflow: hidden` ที่ตัวปุ่มด้วย

## 🔴 ห้ามใช้ `width` คงที่กับปุ่มที่มีข้อความ ใช้ `min-width` เสมอ

**ย้ายมาจากบันทึกคำด่า 5 ก.ย. 2569** — เดิมอยู่ในไฟล์ที่เก็บว่าแคลร์ทำอะไรผิด
ซึ่งไม่ใช่ที่ที่คนจะเปิดหากฎการออกแบบปุ่ม

> พี่กันด่าไว้ 1 ก.ย. 2569: *"ทำเหี้ยไรมา น่าเกลียด"*

แคลร์แก้ปุ่มในหน้าต่างล็อตค้างให้ตรงแนวกัน ด้วยการตั้ง `width` คงที่

🚨 **แก้ปุ่มที่มีทั้งฝั่งคอมและมือถือ ต้องเปิดดูภาพทั้งสองฝั่งก่อนรายงานเสมอ**
ดูฝั่งเดียวแล้วบอกว่าเสร็จ = รายงานเท็จ (รอบนั้นดูแต่ภาพฝั่งคอม)

## 🔴 ปุ่มทุกปุ่มต้องมีข้อความกำกับ ห้ามย่อเหลือแต่ไอคอน

**เขียนใหม่ 5 ก.ย. 2569** — กฎนี้ไม่เคยอยู่ในสกิลไหนเลย ทั้งที่พี่กันสั่งชัด

> *"ไม่ย่อ เอากลับเหมือนเดิม"*

แคลร์เคยย่อปุ่มแก้ไขกับปุ่มดูรายการเหลือแต่ไอคอน เพื่อประหยัดที่ในตาราง พี่กันสั่งเอากลับทันที

**ไอคอนเปล่า ๆ ต้องเดาความหมาย** และคนที่ไม่ได้ใช้ทุกวันจะไม่กล้ากด
ยอมให้คอลัมน์กว้างขึ้นดีกว่าให้คนกดผิดหรือไม่กล้ากด

⚠️ **ต่างจากปุ่มไอคอนล้วนที่ยอมได้** — ปุ่มปิด (✕) · ปุ่มแก้ (✎) ที่อยู่คู่กับข้อความในแถวเดียวกัน
ยังใช้ไอคอนล้วนได้ แต่ **ต้องมี `aria-label` เสมอ** · เส้นแบ่งคือ
**ปุ่มที่สั่งให้เกิดการกระทำที่คนต้องคิดก่อนกด ต้องมีข้อความ**

## 🔴🔴 ในจอเกม ของที่วางไม่ได้ต้องบอกเหตุผลติดตัวของนั้น ป้ายมุมจอไม่นับว่าบอก (8 ต.ค. 2569 · บันทึกคำด่า 8 ต.ค. (4))

> *"กูจะรู้มั้ยนยยยย"* · *"กดดูเเล้ว ไหนบอกว่าฝั่งไหนถนน"* · *"บ้านก็เหมือนกัน กดเเล้วจะรู้มั้ยว่าฝั่งไหนถนน"*

กฎเดียวกับปุ่มที่กดไม่ได้ข้างล่าง แต่ใช้กับจอเกม
- โครงอาคารสีแดง ต้องมีเหตุผลติดโครง และช่องที่ขวางต้องเห็นว่าเป็นช่องไหน
- ด้านหน้าอาคาร ประตู และด้านที่ต่อถนน ต้องดูออกด้วยตา ทั้งตอนวางและตอนกดเลือก
- ของบนพื้นที่กติกาต่างกัน (ถนน ทางดินจากรอยเท้า ช่องที่ระบายไว้ยังไม่สร้าง) ต้องหน้าตาต่างกันพอให้แยกได้
- 🔴 ถูกถามว่าทำไมทำไม่ได้ ให้ตอบก่อนว่าจอบอกผู้ใช้ตรงจุดนั้นหรือเปล่า ไม่ใช่ตอบกติกาในโค้ด

## 🔴 ปุ่มที่กดแล้วโดนตีกลับ + ข้อความเตือนหายเร็ว = ผู้ใช้เห็นเป็นปุ่มเสีย

**เกิดจริงกับพี่กัน** — กดยืนยัน → โดนตีกลับ → ข้อความเตือนหายใน 2 วินาที
**พี่กันเห็นว่าปุ่มเสีย** ไม่ได้เห็นว่าตัวเองกรอกไม่ครบ

🚨 **เหตุผลที่กดไม่ได้ ต้องอยู่บนตัวปุ่มเองหรือติดกับปุ่ม** ไม่ใช่ข้อความลอยที่หายไปเอง
🚨 **ข้อความที่บอกว่าทำไมทำไม่ได้ ห้ามตั้งเวลาให้หายเอง** ต้องอยู่จนกว่าเงื่อนไขจะเปลี่ยน

## 🔴 ห้ามโชว์ตัวเลขที่คำนวณจากค่าที่เกินเพดาน

**ตัวเลขหลักพันล้านสะดุดตากว่าบรรทัดเตือนสีแดงเสียอีก**
คนเห็นแวบแรกจะตกใจกับตัวเลข ไม่ได้อ่านคำเตือน

🚨 **ค่าที่เกินเพดานแล้ว ให้หยุดคำนวณและไม่ต้องวาดตัวเลขนั้นเลย**

## 🔴 ไอคอนต้องบอก "สถานะตอนนี้" ไม่ใช่ "สิ่งที่จะเกิดถ้ากด"

```
กำลังโชว์รหัสผ่านอยู่  →  ไอคอนตาเปิด (บอกสถานะ)     ✅
กำลังโชว์รหัสผ่านอยู่  →  ไอคอนตาขีดทับ (บอกผลถ้ากด)  ❌
```
