## 6.11 🔴 ปฏิทิน พ.ศ. บนเครื่องผู้ใช้ ทำให้ช่องวันที่มาตรฐานส่งปีผิด

**เจอจริงที่เว็บ listless — ได้ปี 3112 และมีข้อมูลเสีย 34 จาก 174 แถว**

### กลไก

ช่องเลือกวันที่มาตรฐานของเบราว์เซอร์ (`<input type="date">`) **ส่งปีตามปฏิทินที่เครื่องตั้งไว้**

| เครื่องตั้งปฏิทินแบบไหน | ช่องส่งอะไรออกมา |
|---|---|
| คริสต์ศักราช (ปกติ) | `2026-08-08` ✅ |
| **พุทธศักราช** | **`2569-08-08`** ← ส่ง พ.ศ. ออกมาเลย |

เว็บที่เก็บเป็น ค.ศ. แล้วบวก 543 ตอนแสดงผล จะได้ **2569 + 543 = 3112**

**และมันผิดทุกที่พร้อมกัน** — บนหน้าจอ · ในการเรียงลำดับ · ในเอกสารที่พิมพ์ · ในไฟล์ส่งออก

### 🚨 กฎ

- **เว็บที่มีคนใช้หลายเครื่อง อย่าใช้ช่องวันที่มาตรฐานกับข้อมูลที่ต้องแม่นยำ**
  ทำช่องกรอกเองหรือใช้ตัวเลือกวันที่ที่คุมค่าเองได้
- **ต้องมีตัวดักไว้เสมอ** — ปีที่เกิน 2400 = ได้ พ.ศ. มา ต้องลบ 543 ก่อนเก็บ
- 🔴 **เทสในเครื่องเราไม่มีวันเจอ** เพราะขึ้นกับการตั้งค่าเครื่องของคนใช้
  **ต้องคิดเผื่อตั้งแต่ออกแบบ**

⚠️ **ข้อมูลที่เสียไปแล้วต้องตามแก้ย้อนหลัง** listless ยังมี 34 แถวที่เก็บผิดค้างอยู่

## 6.12 🔽 ช่องเลือกกับช่องกรอก — กับดัก 8 ข้อที่เจอมาแล้วทุกตัว

### ①🔴 เขียนคุณสมบัติ CSS แบบรวบ = ล้างค่าที่กฎกลางตั้งไว้ทิ้ง

กฎกลางวาดลูกศร ▾ ของช่องเลือกด้วยรูปพื้นหลัง คู่กับการปิดลูกศรของระบบ
**เขียนสีพื้นแบบรวบเมื่อไหร่ รูปลูกศรถูกล้างทิ้งทันที**

```css
/* ❌ ล้างรูปลูกศรทิ้ง — ช่องกลายเป็นกล่องเปล่า ดูไม่ออกว่ากดได้ */
background: #fff;

/* ✅ เขียนแยกเสมอ */
background-color: #fff;
```

พี่กันทักทันทีที่เห็น: *"ไหนตัว v"*

🚨 **ตระกูลเดียวกับบั๊กเขียน `border` แบบรวบแล้วล้างสีขอบที่ตั้งไว้**
**คุณสมบัติที่มีหลายส่วนย่อย ต้องเขียนแบบแยกเสมอเมื่อของเดิมตั้งค่าไว้แล้ว**

### ② `<option>` ไม่สืบทอดสไตล์จาก `<select>`

**วินโดวส์วาดรายการที่กางออกด้วยระบบของตัวเอง ไม่สนใจสไตล์ของช่องแม่**

ตั้งฟอนต์ที่ `<select>` อย่างเดียว = รายการที่กางออกยังเป็นฟอนต์ระบบตัวบางสีจาง
**พี่กันจับได้ทันที** · ต้องใส่สไตล์ที่ `<option>` แต่ละอันด้วย

### ③ ลูกศร ▾ ต้องลอยทับขอบขวา ไม่กินที่ในแถว

ถ้าปล่อยให้ลูกศรกินที่จริง **ข้อความที่จัดกึ่งกลางจะเบี้ยวไปทางซ้าย**
เพราะพื้นที่ที่เหลือให้ข้อความไม่สมมาตร

ใช้ `position:absolute` วางทับขอบขวา แล้วเว้นระยะขอบขวาของช่องให้พอ

### ④ ช่องกรอกกับกล่องธรรมดาคิดความสูงคนละแบบ

**ช่องกรอกกับ `<div>` คิดความสูงจากระยะขอบในคนละสูตร**
วางข้างกันแล้วตั้งระยะขอบในเท่ากัน **ความสูงจะไม่เท่ากัน**

🚨 **ต้องกำหนดความสูงตายตัวให้ทั้งคู่ ไม่ใช่อาศัยระยะขอบใน**

### ⑤🔴🔴 ดรอปดาวที่ทำเอง ต้องหน้าตาเหมือน `<select>` ในฟอร์มเดียวกัน

**พี่กันเทียบภาพสองช่องให้ดู 5 ก.ย. 2569**

> *"มันไม่เหมือนกันอ่ะ เราอยากได้สีเข้ม และ v ชัดเจน แต่ผู้รายงานมันไม่ใช่แบบที่ต้องการ"*

บางช่องเลือกต้องทำเองแทน `<select>` (เช่นรายชื่อยาว ๆ ที่ iOS ตัดเหลือ 2 บรรทัด)
**แต่พอทำเอง มันเลยไม่ได้อะไรจากกฎกลางที่ `<select>` ได้ฟรี ๆ** — ต้องไปหยิบมาใส่เองให้ครบ

| จุด | `<select>` ได้จากกฎกลาง | ดรอปดาวที่ทำเองมักพลาด |
|---|---|---|
| **สีข้อความ** | `#0F172A` เข้มเสมอ | ตั้งจาง `#94A3B8` ตอนยังไม่เลือก |
| **ลูกศร** | SVG 16×16 · เส้นหนา 2.5 · `#94A3B8` | ใช้ตัวอักษร `▾` 12px |

#### 🔑 สีข้อความต้องเข้มเสมอ แม้ยังไม่ได้เลือก

`<select>` **ไม่มี placeholder จริง** — มันแสดงตัวเลือกแรกด้วยสีปกติเสมอ
พอทำดรอปดาวเอง มักเผลอทำข้อความ "— เลือก… —" ให้จางเหมือน placeholder ของช่องกรอก
ผลคือ **ช่องนั้นช่องเดียวดูซีดกว่าเพื่อนทั้งฟอร์ม** ทั้งที่เป็นช่องบังคับกรอกเหมือนกัน

```jsx
/* ❌ */ color: value ? "#0F172A" : "#94A3B8"
/* ✅ */ color: "#0F172A"
```

#### 🔑 ลูกศรต้องเป็น SVG ชุดเดียวกับที่กฎกลางวาดให้ `<select>`

```jsx
<svg width="16" height="16" viewBox="0 0 24 24" fill="none"
     stroke="#94A3B8" strokeWidth="2.5" aria-hidden="true">
  <path d="M6 9l6 6 6-6" />
</svg>
```

🚨 **ห้ามใช้ตัวอักษรพิเศษเป็นไอคอน** (`▾` `▼` `⌄`) — บางเครื่องขึ้นเป็นสี่เหลี่ยมว่าง
และขนาดกับน้ำหนักเส้นคุมไม่ได้ ตัวอักษร `▾` ที่ 12px **บางกว่า SVG เส้น 2.5 อย่างเห็นได้ชัด**
(กฎเดียวกับที่สกิลกลางเขียนไว้เรื่องไอคอนสลับสถานะ)

🚨 **หมุนลูกศรตอนกางด้วย** `transform: rotate(180deg)` + `transition` — บอกว่ารายการเปิดอยู่

#### ✅ วิธีตรวจ

```js
// วางในคอนโซล — เทียบดรอปดาวที่ทำเองกับ <select> ในหน้าเดียวกัน
const sel = getComputedStyle(document.querySelector('select'));
const dd  = getComputedStyle(document.querySelector('[aria-haspopup], button[aria-expanded]'));
console.log({ selectสี: sel.color, ดรอปดาวสี: dd.color, ตรงกัน: sel.color === dd.color });
```

🚨 **ต้องเทียบกับ `<select>` จริงในหน้าเดียวกัน ไม่ใช่จำค่าเอา** — ธีมของแต่ละเว็บไม่เท่ากัน

### ⑥🔴🔴🔴 ของที่อยู่แถวเดียวกัน ต้องสูงเท่ากันทุกตัว — ทั้งหน้า

**พี่กันย้ำเอง 5 ก.ย. 2569** หลังจับได้ในกริดตัวกรองหน้ารายงาน

> *"เห็นมั้ย **เราให้ความสำคัญกับขนาดของกรอบ ที่ถ้าแถวเดียวกัน มันควรเท่ากันทั้งหน้า**
>  และ**เราซีเรียสเรื่องวรรณยุกต์**"*

> *"กรอบค้นหา ทำไมสูงกว่ากรอบดรอปดาวอื่น"*

#### 🔑 ต้นเหตุที่เกิดซ้ำได้ง่ายที่สุด — เอาค่ากลางของทั้งเว็บมาใส่ในกริดที่มีค่าของตัวเอง

ตอนยกช่องค้นหาไปใช้ตัวกลาง มักใส่ความสูงมาตรฐานของทั้งเว็บ (เช่น 43/45px)
**แต่กริดตัวกรองมีความสูงของตัวเองที่เตี้ยกว่า** (38px) ช่องเดียวเลยสูงกว่าเพื่อน 5px

```
❌ h={สูงช่องค้นหา(isMobile)}   ← ค่ากลางของทั้งเว็บ
✅ h={สูงช่องกรอง}              ← ค่าของกริดนี้ ที่ช่องอื่นในแถวใช้อยู่
```

🚨 **ก่อนใส่ความสูงให้ช่องไหน ต้องวัดช่องที่อยู่ข้าง ๆ ก่อนเสมอ** ไม่ใช่หยิบค่ากลางมาใส่

#### ✅ ตั้งเป็นตัวแปรตัวเดียวต่อหนึ่งกลุ่ม แล้วให้ทุกช่องอ้างตัวนั้น

```tsx
const สูงช่องกรอง = 43;   // ทุกช่องในกริดนี้อ้างตัวนี้ ห้ามใครตั้งเอง
```

ห้ามให้แต่ละช่องเขียน `padding` ของตัวเองแล้วหวังว่าจะออกมาเท่ากัน
**`<select>` · `<input>` · `<div>` คิดความสูงจากขอบในคนละสูตร** (ดูข้อ ④)
ต้องกำหนด `height` ตายตัวให้ทุกตัว

#### 🚨 วิธีตรวจ — วัดทุกตัวในกลุ่มแล้วนับว่าได้กี่ค่า

```js
const กลุ่ม = [...document.querySelectorAll('select, input')];
const สูง = [...new Set(กลุ่ม.map(el => Math.round(el.getBoundingClientRect().height)))];
console.log({ สูง, เท่ากันหมด: สูง.length === 1 });   // ต้องได้ค่าเดียว
```

**ผลที่ควรได้คือ "ค่าเดียว" เท่านั้น** — ได้ 2 ค่าเมื่อไหร่แปลว่ามีช่องที่หลุดจากระบบ

### ⑦🔴🔴🔴 ความสูงกรอบไม่พอ = วรรณยุกต์โดนตัด — สองเรื่องนี้เป็นเรื่องเดียวกัน

**พี่กันเจอพร้อมกันในหน้าเดียว 5 ก.ย. 2569** — *"คำว่า ทั้งหมด ไม้โทหาย"*

**ตัวเลขจริงที่วัดได้** — `<select>` ในกริดตัวกรอง

```
กรอบสูง 38px − ขอบใน 9px × 2  =  18px   ← ที่มีให้ตัวอักษร
คำว่า "ทั้งหมด" ต้องใช้           19px
                                 ─────
                          ขาดไป   1px   ← ไม้โทโดนตัดพอดี
```

🔑 **ขาดแค่ 1px ก็เห็น** — พี่กันจับได้จากภาพหน้าจอที่ย่อแล้วด้วยซ้ำ

#### วิธีวัดว่าตัวอักษรต้องใช้ที่เท่าไหร่จริง ๆ

```js
// วัดความสูงจริงของข้อความไทยที่มีวรรณยุกต์ ด้วยฟอนต์ของช่องนั้นเอง
const el = document.querySelector('select');
const cs = getComputedStyle(el);
const c = document.createElement('canvas').getContext('2d');
c.font = `${cs.fontStyle} ${cs.fontWeight} ${cs.fontSize} ${cs.fontFamily}`;
const m = c.measureText('ทั้งหมด');           // คำที่มีทั้งไม้โทและสระ
const ต้องใช้ = Math.ceil(m.actualBoundingBoxAscent + m.actualBoundingBoxDescent);
const มีให้ = el.clientHeight - parseFloat(cs.paddingTop) - parseFloat(cs.paddingBottom);
console.log({ ต้องใช้, มีให้, พอไหม: มีให้ >= ต้องใช้ });
```

🚨 **ต้องวัดด้วยฟอนต์ของช่องนั้นจริง ๆ** — Sarabun กับฟอนต์ระบบสูงไม่เท่ากัน
🚨 **คำที่ใช้ทดสอบต้องมีทั้งวรรณยุกต์บนและสระล่าง** เช่น `ทั้งหมด` · `ผู้ป่วย` · `ระบุ`

#### 🔑 แก้ความสูงให้เท่ากัน = แก้วรรณยุกต์ไปด้วยในตัว

ทั้งสองปัญหาในกริดนี้แก้ด้วยค่าเดียว — ดันทุกช่องจาก 38 เป็น **43px**
ความสูงเท่ากันทั้งแถว **และ** ที่ให้ตัวอักษรเพิ่มจาก 18 เป็น 41px

### ⑧🔴🔴🔴 ช่องเลือกเฉือนหัว ไ ใ โ ทิ้ง — พังทุกเว็บ · วิธีทำยกจาก HCV 100%

**เจ้าของงานทักสามรอบ 23 ก.ย. 2569** (warfarin หน้าต่างสร้างวิธีบริหารใหม่ คำว่า "ไม่กิน")

> *"ไม้มลาย ไ มันโดนตัด อีกเเล้ว ไปอ่านสกิลมาว่าเราแก้จุดนี้ยังไง"* · *"hcv ทำมาเเล้ว"*
> *"**ยกมา 100% เเละจุดนี้พังทุกเว็บ ดังนั้น เขียนวิธีทำในสกิลด้วย**"*

#### ต้นเหตุ — หัว ไ ใ โ ยื่นออกทางซ้าย ไม่ใช่ขึ้นบน

ตัวอักษรไทยของ Sarabun ยื่นเกินกล่องของตัวเองได้ทั้งสี่ทิศ วัดในโครมที่ 15px ด้วย canvas `measureText`

| ยื่นไปทาง | ตัวไหน | กี่จุด |
|---|---|:--:|
| ซ้าย | ไ · ใ | 2 |
| ซ้าย | โ · ฐ | 1 |
| ขวา | ั (ไม้หันอากาศ) | 2 |
| ขวา | ้ · ๊ · ์ | 1 |
| บน | ็ (ไม้ไต่คู้) | สูง 16 จากขนาด 15 |
| ล่าง | ฎ · ฏ · ฐ · ุ · ู | ลงใต้เส้นฐาน 5 |

ช่องเลือกแทบทุกเว็บเขียนตัวหนังสือในปุ่มแบบนี้ เพื่อให้ข้อความยาวขึ้นจุดไข่ปลา

```jsx
/* ❌ ตัวต้นเหตุ */
<span style={{ whiteSpace: "nowrap", overflow: "hidden", textOverflow: "ellipsis", lineHeight: 1.75 }}>{ค่า}</span>
```

กล่องตัวหนังสือเริ่มตรงจุดเริ่มตัวอักษรพอดี **หัว ไ ที่ยื่นซ้าย 2 จุดโดนเฉือนที่ขอบซ้าย**
- ตั้งระยะบรรทัดเท่าไหร่ก็ไม่หาย เพราะไม่ใช่เรื่องความสูง (สูตร 1.75 ในสกิล search-system เดิมผิดข้อนี้)
- เปลี่ยน `hidden` เป็น `clip` แนวนอนอย่างเดียวก็ยังเฉือน
- `<select>` ของเบราว์เซอร์ก็เฉือนเหมือนกัน และแก้ด้วยการตั้งค่าไม่ได้เลย
  HCV ลองมาหมดแล้ว 28 ส.ค. 2569 ทั้งความหนาตัวอักษร ระยะบรรทัด ระยะขอบ กองฟอนต์ ปิด appearance

🔑 **ยกเว้นธีมของเว็บ** เจ้าของงานบอกเอง *"ไม่รวมธ๊มเว็บนะ"*
   ยกโครงกับกติกาข้างล่างมาครบทุกข้อ แต่สีขอบ สีพื้น ฟอนต์ ความสูงช่อง ใช้ของเว็บที่กำลังทำ
   (HCV ขอบสีเขียวน้ำทะเล · warfarin ใช้สีโรสของตัวเอง)

**① ช่องเลือกที่แสดงข้อความไทย ห้ามใช้ `<select>` ของเบราว์เซอร์** ทำเป็นปุ่มกับรายการเอง
**② ตัดที่ขอบปุ่มที่เดียว ตัวหนังสือห้ามมีอะไรตัด**

```jsx
<button type="button" aria-haspopup="listbox" aria-expanded={open}
  style={{
    height: "var(--h)",            // เท่าช่องกรอกในแถวเดียวกัน (ข้อ ⑥)
    padding: "0 12px",             // 🔴 ต้องมีขอบซ้ายขวา หัว ไ ยื่นเข้าไปอยู่ในนี้
    display: "flex", alignItems: "center", justifyContent: "space-between", gap: 8,
    overflow: "hidden",            // 🔴 ตัดที่นี่ที่เดียว
  }}>
  <span style={{ whiteSpace: "nowrap", minWidth: 0 }}>{ค่า}</span>  {/* 🔴 มีได้แค่สองตัวนี้ */}
  <svg style={{ flex: "none" }} width="16" height="16" viewBox="0 0 24 24"
       fill="none" stroke="currentColor" strokeWidth="2.5" aria-hidden="true">
    <path d="M6 9l6 6 6-6" />      {/* ลูกศร ข้อ ⑤ */}
  </svg>
</button>
```

🚨 **ตัวหนังสือห้ามมี** `overflow` · `text-overflow` · `line-height` · `padding` บนล่าง
   Tailwind คือห้าม `truncate` · `overflow-hidden` · `text-ellipsis` · `leading-*` · `py-*` ที่ตัวหนังสือ
🚨 **`min-width: 0` ต้องมี** ไม่งั้นข้อความยาวดันลูกศรหลุดออกนอกปุ่ม
🔑 **จุดไข่ปลาหายไป** ข้อความยาวเกินปุ่มจะโดนขอบปุ่มตัดแทน HCV ใช้แบบนี้มาตั้งแต่ 28 ส.ค. 2569
🔑 **ช่องที่ไม่ได้ยืดเต็มแถว** (เช่นตัวกรองที่ลอยอิสระ) วางทุกตัวเลือกซ้อนกันแบบมองไม่เห็นในกริดช่องเดียว
   ปุ่มจะกว้างเท่าตัวเลือกที่ยาวที่สุดเอง ไม่หดกระตุกตอนเปลี่ยนค่า · ช่องที่ยืดเต็มแถวไม่ต้องใส่

```jsx
<span style={{ display: "grid", minWidth: 0 }}>
  {ตัวเลือก.map((o) => (
    <span key={o} aria-hidden="true" style={{ gridArea: "1 / 1", visibility: "hidden", whiteSpace: "nowrap" }}>{o}</span>
  ))}
  <span style={{ gridArea: "1 / 1", whiteSpace: "nowrap", minWidth: 0 }}>{ค่า}</span>
</span>
```

# 📝 หน้ากรอกกับหน้าแก้ไข — ต้องเป็นของชุดเดียวกัน

**ตั้งหัวข้อ 5 กันยายน 2569** · บั๊กกลุ่มนี้ทำข้อมูลหายเงียบ ๆ ทุกตัว

## ①🔴 หน้าแก้ไขใช้ตัวควบคุมคนละชนิดกับหน้ากรอก = ข้อมูลหาย

**เจอจริง** — หน้ากรอกเป็นปุ่มเลือกได้หลายอัน แต่หน้าแก้ไขเป็นช่องเลือกอันเดียว
เปิดแก้ไขทีเดียว **ค่าที่เคยเลือกไว้หลายอันหดเหลืออันเดียว** ไม่มีคำเตือนอะไรเลย

🚨 **ช่องเดียวกันต้องใช้ตัวควบคุมชนิดเดียวกันทั้งสองหน้า** ถ้าหน้ากรอกเลือกได้หลายอัน หน้าแก้ไขก็ต้องเลือกได้หลายอัน

## ②🔴 ช่องบังคับที่ไม่มีช่องให้กรอกในหน้าแก้ไข = กดบันทึกไม่ได้ตลอดกาล

ตัวตรวจสั่งให้ระบุ **แต่หน้านั้นไม่มีช่องให้กรอก** ผู้ใช้ติดตายอยู่ตรงนั้น กดยังไงก็ไม่ผ่าน

🚨 **ตัวตรวจกับหน้าจอต้องมาจากรายการช่องชุดเดียวกัน** ไม่ใช่ต่างคนต่างเขียน

## ③🔴 สลับประเภทฟอร์ม — ช่องที่ปลายทางไม่มี ต้องล้างทิ้งจริง ห้ามแค่ซ่อน

**ซ่อนไว้แล้วค่าจะยังถูกบันทึกลงฐานไปด้วย** เพราะช่องนั้นยังอยู่ในรายการคอลัมน์ที่ส่ง

```
ผู้ใช้เลือก ก → กรอกช่องของ ก → เปลี่ยนใจเป็น ข
ช่องของ ก ถูกซ่อน แต่ค่ายังอยู่ → บันทึกแล้วได้เคสที่มีข้อมูลของทั้ง ก และ ข
```

🚨 **เปลี่ยนค่าแม่เมื่อไหร่ ล้างค่าลูกที่ไม่ใช้แล้วทันที**

## ④🔴 กรอกไม่ครบต้องบันทึกได้ — เหตุผลของพี่กันเอง

> *"ถ้าบังคับกรอกทุกช่องแล้วหน้างานทำไม่ได้ **จะเลิกใช้ระบบ**"*

**ระบบที่เก็บข้อมูลไม่ครบ ยังดีกว่าระบบที่ไม่มีใครใช้** โดยเฉพาะงานที่ทีมยังไม่ได้ตกลงวิธีทำงานกัน
บังคับได้เฉพาะช่องที่ขาดแล้วข้อมูลไม่มีความหมายจริง ๆ

## ⑤🔴 ค่าที่ระบบเติมให้อัตโนมัติ ต้องแยกจากค่าที่ผู้ใช้ตั้งเอง

**ต้องมีธงจำไว้ว่าค่านี้ใครเป็นคนตั้ง**

| ใครตั้ง | เกิดอะไรตอนเงื่อนไขหายไป |
|---|---|
| ระบบเติมให้ | **ปลดออกได้** เมื่อเงื่อนไขหมดไป |
| ผู้ใช้ติ๊กเอง | **ห้ามปลดเด็ดขาด** แม้เงื่อนไขจะหมดไปแล้ว |

ไม่มีธงนี้ = ระบบไปลบสิ่งที่คนตั้งใจติ๊กเอง หรือปล่อยธงที่ควรหายไปให้ค้าง

## ⑥🔴 เลื่อนไปหาช่องที่กรอกไม่ครบ — ชุดกฎครบชุด

**หน้ายาว ๆ ที่บอกแค่ "กรุณากรอกให้ครบ" ลอย ๆ = ผู้ใช้ต้องไล่หาเองทั้งหน้า**

| ต้องทำ | รายละเอียด |
|---|---|
| ลำดับช่อง | **เรียงตามที่ตาเห็นบนฟอร์มจริง** ไม่ใช่ลำดับในตัวตรวจ |
| ขอบแดง + ข้อความใต้ช่อง | **ต้องมีทั้งหน้ากรอกและหน้าแก้ไข** — เคยขาดในหน้าแก้ไขทั้งหน้า |
| เรืองซ้ำได้ | ถอดคลาสก่อนแล้วบังคับคำนวณใหม่ ไม่งั้นกดซ้ำแล้วไม่เรือง |
| โฟกัส | โฟกัสเฉพาะช่องพิมพ์ · ปุ่มกับชิปห้ามโฟกัส กันกรอบค้าง |
