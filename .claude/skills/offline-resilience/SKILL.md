## 30. ชุดรับมือเน็ตหลุด — ต้องครบทั้ง 5 อย่าง 🔴

**พี่กันสั่ง 31 ส.ค. 2569** หลังถามว่า "ถ้าเน็ตหลุด จะเกิดอะไรขึ้น เราวางแผนเรื่องนี้ยัง"
แล้วต่อด้วย "มันจะขึ้นเตือนไหม แบบเป็นแบนเนอร์ไว้เลย ว่าเน็ตหลุด เหมือนเว็บยาคืน"

เน็ตโรงพยาบาลไม่ได้หลุดแบบขาดสะบั้นอย่างเดียว แบบที่อันตรายกว่าคือ
**"ต่ออยู่แต่ไม่ไปไหน"** — `fetch` จะไม่ throw และไม่ resolve ปุ่มหมุนค้างตลอดกาล

### ต้องมีครบทั้ง 5 อย่าง ขาดข้อใดข้อหนึ่งก็ยังเสียของ

| # | อย่าง | ทำไมต้องมี |
|---|---|---|
| 1 | **แถบเตือนค้างบนสุด** | บอกตลอดเวลาที่เน็ตหลุด ไม่ใช่รอให้กดแล้วค่อยรู้ |
| 2 | **ตัวจับเวลาตัดทุกคำขอ** | เน็ตค้างแบบไม่ตอบ ต้องตัดเองแล้วบอกผู้ใช้ |
| 3 | **ร่างเก็บในเครื่อง** | เผลอปิดแท็บระหว่างเน็ตหลุด ของที่กรอกต้องไม่หาย |
| 4 | **กันบันทึกซ้ำที่ฐาน** (ข้อ 20) | กดส่งใหม่ได้โดยไม่กลัวได้ข้อมูลสองชุด |
| 5 | **เตือนก่อนปิดแท็บ** | มีของค้างยังไม่บันทึก ต้องถามก่อน |

### แถบเตือน — เขียนยังไง

```
เน็ตหลุด — ยังกรอกต่อได้ตามปกติ สิ่งที่กรอกไว้ถูกเก็บในเครื่องนี้แล้ว
                                                    กดบันทึกได้เมื่อเน็ตกลับมา
```

🚨 **ต้องบอกว่า "ของไม่หาย" ก่อน แล้วค่อยบอกว่าให้ทำอะไรต่อ**
ถ้าบอกแค่ "เน็ตหลุด" เภสัชกรจะรีบจดใส่กระดาษเผื่อไว้ ซึ่งเสียเวลาโดยไม่จำเป็น

- สีแดงอิฐ `#c2543c` ตัดกับธีมเว็บชัด เห็นทันทีแม้กวาดตาผ่าน
- **วางเหนือพื้นที่เลื่อน** จะได้ค้างบนสุดเสมอ ไม่เลื่อนหนีไปกับเนื้อหา
- `role="status" aria-live="polite"` ให้โปรแกรมอ่านหน้าจออ่านให้เมื่อสถานะเปลี่ยน
- 🚨 **เช็คสถานะตอนเปิดเว็บด้วย** (`navigator.onLine === false`) ไม่ใช่ฟังแต่เหตุการณ์
  เผลอเปิดตอนเน็ตหลุดอยู่แล้วต้องเห็นป้ายทันที

### ตัวจับเวลาตัด

```ts
export const NET_TIMEOUT = 20000;
export async function fetchT(url, opts = {}, ms = NET_TIMEOUT) {
  if (navigator.onLine === false) throw new Error(NET_OFFLINE_MSG);
  const ac = new AbortController();
  const timer = setTimeout(() => ac.abort(), ms);
  try { return await fetch(url, { ...opts, signal: ac.signal }); }
  catch (e) {
    if (e instanceof DOMException && e.name === 'AbortError') throw new Error(NET_TIMEOUT_MSG);
    throw e;
  } finally { clearTimeout(timer); }
}
```

🚨 **ต้องใช้ทุกจุดที่คุยกับหลังบ้าน** เหลือ `fetch` ดิบไว้จุดเดียวก็ค้างได้ที่จุดนั้น

ข้อความตอนตัด **ต้องบอกว่ายังไม่รู้ผล และกดใหม่ได้**
`ยังไม่รู้ผลว่าบันทึกเข้าหรือยัง — กดส่งใหม่ได้เลย ระบบกันข้อมูลซ้ำไว้แล้ว`

### ร่างเก็บในเครื่อง

- เก็บหลังหยุดพิมพ์ ~800ms ไม่เก็บทุกตัวอักษร
- 🚨 **ล้างทันทีที่ 1) บันทึกสำเร็จ 2) กดออกโดยไม่บันทึก 3) ออกจากระบบ**
  เพราะร่างมี HN กับข้อมูลผู้ป่วยอยู่ข้างใน
- เปิดฟอร์มมาเจอร่างค้าง → **ถามก่อนว่าจะเอากลับมาไหม** ไม่ใช่ยัดกลับเอง
- 🚨 บันทึกล้มเหลว **ห้ามล้างร่าง** (วาง `clearDraft()` ไว้หลังจุดที่ throw แล้วเท่านั้น)

### ที่ยาคืนมีแต่เว็บอื่นยังไม่มี — ส่งซ้ำเองจนกว่าจะสำเร็จ

**`retryFailedSave` ใน `MedReturnApp.jsx`**

### 🚨🔴🔴 รอสัญญาณ "เน็ตกลับมา" อย่างเดียว **ไม่พอ** — เน็ตโรงพยาบาลไม่เคยส่งสัญญาณนั้น

⚠️ **ข้อนี้เคยเขียนผิดไว้ในสกิลว่า "ผูกกับเหตุการณ์ `online` พอแล้ว"** ซึ่งพิสูจน์แล้วว่าไม่พอ
แก้ให้ตรงเมื่อ 5 ก.ย. 2569 · **HCV Tracker กำลังจะทำตามข้อที่ผิดนี้ ต้องบอกก่อนลงมือ**

**เบราว์เซอร์ยิงสัญญาณ `online` เมื่อเครื่องหลุดจากเครือข่ายแล้วต่อกลับ**
แต่**อาการจริงในโรงพยาบาลคือไวไฟขึ้นครบทุกขีดแต่ออกเน็ตไม่ได้**
เครื่องยังต่อกับเราเตอร์อยู่ตลอด **จึงไม่มีสัญญาณไหนยิงเลยสักตัว**
ของที่ค้างจะนอนอยู่เฉย ๆ จนกว่าจะมีคนมากดเอง — ซึ่งอาจไม่มีใครกด

### ต้องมีครบ 3 ทาง ขาดข้อใดข้อหนึ่งไม่ได้

| ทาง | ทำอะไร |
|---|---|
| **① ตัวจับเวลาถอยห่าง** | ลองส่งเองเรื่อย ๆ **โดยไม่ต้องรอสัญญาณอะไรทั้งนั้น** |
| ② สัญญาณ `online` | เน็ตหลุดจริงแล้วกลับมา — ยิงทันทีไม่ต้องรอรอบถัดไป |
| ③ กลับเข้าแท็บ (`visibilitychange`) | คนสลับไปทำอย่างอื่นแล้วกลับมา |

**ทางที่ ① คือทางหลัก** อีกสองทางเป็นตัวเร่งให้เร็วขึ้นเท่านั้น

```js
const RETRY_WAITS = [20, 40, 80, 160, 300];   // วินาที
```

🚨 **ค้างที่ 5 นาทีไปเรื่อย ๆ ห้ามหยุดเอง** — หยุดเมื่อไหร่แปลว่าต้องมีคนมากด
ซึ่งคือสิ่งที่ระบบนี้มีไว้เพื่อเลี่ยง

🚨 **หน้าจอต้องนับถอยหลังจริงทุกวินาที** ว่าอีกกี่วินาทีจะลองใหม่ และลองไปแล้วกี่ครั้ง
ข้อความลอย ๆ ว่า "ระบบจะลองใหม่ให้" **ไม่มีอะไรพิสูจน์ว่าระบบยังทำงานอยู่**
คนจะไม่เชื่อแล้วกดเองรัว ๆ

🚨 **หน่วง 1.2 วินาทีก่อนยิงหลังได้สัญญาณ `online`** สัญญาณมาถึงก่อนที่เน็ตจะใช้ได้จริง

🚨 **ธงว่า "ยังส่งไม่สำเร็จ" ต้องเก็บลงเครื่องด้วย** ปิดแท็บแล้วเปิดใหม่ ของยังอยู่ครบ
แต่เว็บนึกว่าเป็นร่างธรรมดา **ไม่ลองส่งเองอีกเลย** และคนเวรถัดไปอาจกดล้างทิ้ง

# 💻 โค้ดจริงที่ยกไปใช้ได้เลย

**ตั้งหัวข้อ 5 กันยายน 2569 ตามที่พี่กันสั่ง** — *"ถ้ามีโค้ดก็เอามาเลย
เพราะสิ่งที่ทำดีแล้ว แล้วควรใช้ทุกเว็บ ก็ยกมาเลย เหมือนระบบ pdf ระบบปุ่ม ระบบค้นหา"*

## ① ตัวยิงคำขอกลาง — ทุกเว็บต้องมี ห้ามเรียก `fetch` ตรง

**ต้นแบบ `ME-DRP/lib/net.ts`** (สมบูรณ์ที่สุดในกอง)

```ts
export const NET_TIMEOUT = 20000;

// ข้อความที่คนกรอกอ่านแล้วรู้ว่าต้องทำอะไรต่อ ไม่ใช่ศัพท์เทคนิค
export const NET_TIMEOUT_MSG =
  "เน็ตค้างหรือช้าเกินไป ยังไม่รู้ผลว่าบันทึกเข้าหรือยัง กดส่งใหม่ได้เลย ระบบกันข้อมูลซ้ำไว้แล้ว";
export const NET_OFFLINE_MSG =
  "ตอนนี้เครื่องไม่ได้ต่อเน็ต ต่อเน็ตแล้วค่อยกดใหม่ สิ่งที่กรอกไว้ยังอยู่ครบ";

export async function fetchT(url, opts = {}, ms = NET_TIMEOUT) {
  // เครื่องไม่ได้ต่อเน็ตเลย บอกได้ทันทีไม่ต้องรอครบเวลา
  if (typeof navigator !== "undefined" && navigator.onLine === false) {
    throw new Error(NET_OFFLINE_MSG);
  }
  const ac = new AbortController();
  const timer = setTimeout(() => ac.abort(), ms);
  try {
    return await fetch(url, { ...opts, signal: ac.signal });
  } catch (e) {
    // แยกให้ออกว่าโดนตัดเพราะครบเวลา หรือเน็ตหลุดกลางทาง
    if (e?.name === "AbortError") throw new Error(NET_TIMEOUT_MSG);
    if (typeof navigator !== "undefined" && navigator.onLine === false) throw new Error(NET_OFFLINE_MSG);
    throw e;
  } finally {
    clearTimeout(timer);
  }
}
```

🚨🔴 **ห้ามเอาการลองส่งซ้ำมาไว้ในตัวนี้** — ตัวนี้ไม่รู้ว่าคำขอไหนส่งซ้ำได้อย่างปลอดภัย
การลองซ้ำต้องอยู่ชั้นที่รู้ความหมายของงาน (ดูข้อ ③)

### ตัวแกะคำตอบ — ล้มเหลวต้องโยนออกมาเสมอ

```ts
export async function เรียกหลังบ้าน(path, opts = {}, ms = NET_TIMEOUT) {
  const res = await fetchT(path, {
    ...opts,
    cache: "no-store",   // 🚨 กันเบราว์เซอร์หยิบผลเก่าของตัวเองมาใช้ซ้ำ
  }, ms);

  const data = await res.json().catch(() => null);
  if (!data) {
    // เซิร์ฟเวอร์ล่มแล้วตัวกลางตอบเป็นหน้า HTML — ถ้าโยนเข้า .json() ตรง ๆ
    // ผู้ใช้จะเห็น "Unexpected token '<'" แทนคำเตือนภาษาคน
    throw new Error("เซิร์ฟเวอร์ตอบกลับมาผิดรูปแบบ (รหัส " + res.status + ") ลองใหม่อีกครั้ง");
  }
  if (!res.ok || data.isOk === false) {
    throw new Error(data.error || "ทำรายการไม่สำเร็จ (รหัส " + res.status + ")");
  }
  return data;
}
```

🚨🔴🔴 **ห้ามคืนค่าว่างเมื่อคำขอไม่สำเร็จเด็ดขาด**
ตัวที่เรียกจะเอา "ค่าว่าง" นั้นไปทับสำเนาในเครื่อง **แล้วข้อมูลหายหมดจอ**
เกิดจริงมาแล้วที่ ME-DRP v0.9.21.0 — เปิดเว็บครั้งแรกไม่เห็นรายงานเลยสักใบ

## ② รหัสประจำแถวต้องมีตัวสำรอง

```js
export function newUuid() {
  if (typeof crypto !== 'undefined' && crypto.randomUUID) return crypto.randomUUID();
  return 'xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx'.replace(/[xy]/g, (c) => {
    const r = (Math.random() * 16) | 0;
    return (c === 'x' ? r : (r & 0x3) | 0x8).toString(16);
  });
}
```

**ตัวสร้างรหัสของเบราว์เซอร์มีเฉพาะเว็บที่เข้ารหัสแล้วกับเครื่องตัวเอง**
เปิดผ่านเลขเครื่องในวงแลน (เทสจากมือถือ) จะไม่มีตัวนี้ → ฐานตีกลับเพราะรหัสผิดรูปแบบ
🔴 **ถ้าดักข้อผิดพลาดเงียบ จะขึ้นว่า "บันทึกแล้ว" หลอก ทั้งที่ข้อมูลไม่เข้า** (ME-DRP เคยเจอจริง รายงานหายหลายใบ)

## ③ ลองส่งซ้ำในการกดครั้งเดียว — 3 รอบ ถอยห่างขึ้นเรื่อย ๆ

**ต้นแบบ `ME-DRP/lib/data.ts`**

```ts
export async function ส่งขึ้นระบบ(rec, opts = {}) {
  const attempts = opts.attempts ?? 3;
  const timeoutMs = opts.timeoutMs ?? 9000;
  for (let a = 0; a < attempts; a++) {
    try {
      await ส่งหลังบ้าน("/api/incidents", "POST", rec, timeoutMs);
      return true;                       // สำเร็จ หรือรหัสซ้ำ — หลังบ้านตอบสำเร็จทั้งคู่
    } catch (e) {
      logWarn("ส่งขึ้นระบบ (รอบที่ " + (a + 1) + " ไม่สำเร็จ)", e);
    }
    if (a < attempts - 1) await new Promise((r) => setTimeout(r, 500 * (a + 1)));  // 0.5s แล้ว 1s
  }
  logFail("ส่งขึ้นระบบ", "ไม่สำเร็จครบ " + attempts + " รอบ");
  return false;                          // ตกไปเข้าคิวส่งทีหลัง ผู้ใช้เห็นหน้า "ส่งไม่สำเร็จ"
}
```

| 1 | **ลองซ้ำ 3 รอบในการกดครั้งเดียว** | บางเบราว์เซอร์คำขอแรกสะดุดที่ฝั่งเครื่องผู้ใช้ — บันทึกฝั่งเซิร์ฟเวอร์เห็นแต่คำขอสำเร็จ ไม่มีข้อผิดพลาด **กดครั้งเดียวไม่ไป กดซ้ำแล้วไป** |
| 2 | **ตัวจับเวลาตัดต่อรอบ** | เน็ตแบบต่ออยู่แต่ไม่ไปไหน ต้องตัดเองทุกรอบ |
| 3 | **รหัสซ้ำ = สำเร็จ** | ส่งรอบสองเจอแถวเดิมอยู่แล้วคือเรื่องปกติ **ไม่ใช่ความผิดพลาด** |

🚨 **คืนค่าจริงว่าสำเร็จหรือไม่ ห้ามดักข้อผิดพลาดเงียบแล้วขึ้นว่าบันทึกแล้ว**
ME-DRP เคยมีตัวบันทึกการแก้ไขที่ดักเงียบ → ขึ้น "บันทึกการแก้ไขแล้ว" หลอก การแก้ไขหายทุกครั้ง

## ④ กันบันทึกซ้ำที่ฐาน — ที่เดียวที่กันได้จริง

**ต้นแบบ `ยาคืน/app/api/returns/route.js`**

```js
// ทุกแถวมี batch_id (ก้อนการบันทึก) + client_rid (แถวที่เท่าไหร่ในก้อน)
await db.from('mr_return')
  .upsert(rows, { onConflict: 'batch_id,client_rid', ignoreDuplicates: true });
```

```sql
create unique index on mr_return (batch_id, client_rid) where batch_id is not null;
```

🚨 **กด "ลองส่งใหม่" ต้องใช้รหัสก้อนเดิม** ไม่งั้นกันซ้ำไม่ได้เลยสักนิด
🚨🔴 **ห้ามเปลี่ยนเป็นเขียนทับ (`ignoreDuplicates: false`)** จะกลายเป็นทับของเดิม —
ราคาที่แช่ไว้ในแถวจะโดนทับด้วยราคาปัจจุบัน **ตัวเลขย้อนหลังเปลี่ยนทั้งระบบ**

## ⑤ ส่งซ้ำเองเป็นระยะ — ห้ามรอสัญญาณ "เน็ตกลับมา" อย่างเดียว

**สัญญาณนั้นเชื่อไม่ได้** — เครื่องต่อไวไฟติดแต่ออกอินเทอร์เน็ตไม่ได้ ก็รายงานว่าออนไลน์

```js
// ถอยห่างขึ้นเรื่อย ๆ แต่ไม่เกินเพดาน · ห้ามหยุดเอง
const delays = [5000, 10000, 20000, 30000, 60000];
```

🚨 **ห้ามหยุดลองเองเมื่อครบจำนวนรอบ** ของที่ค้างต้องพยายามส่งจนสำเร็จหรือจนผู้ใช้สั่งทิ้ง
🚨 **หน้าจอ "ส่งไม่สำเร็จ" ต้องตอบ 3 คำถาม** — ของอยู่ไหน · ตอนนี้ระบบกำลังทำอะไร · ผู้ใช้ต้องทำอะไร
พร้อม**นับถอยหลังจริงทุกวินาที** ไม่ใช่ตัวเลขนิ่ง ๆ ที่ดูเหมือนค้าง

## ⑥ คิวของที่ยังส่งไม่ขึ้นระบบ

```
แหล่งความจริงของหน้าจอ = ข้อมูลจากเซิร์ฟเวอร์ + คิวที่ค้างในเครื่อง (รวมกันแล้วตัดตัวซ้ำด้วยรหัส)
```

🚨 **แก้คิวทีละรายการ ห้ามเขียนทับทั้งชุด** — เขียนทับทั้งก้อนจะลบรายการที่เพิ่งเพิ่มเข้ามาระหว่างนั้น
🚨 **ล้างข้อมูลในเครื่องเฉพาะตอนผู้ใช้กดออกจากระบบเอง** ห้ามล้างตอนบัตรผ่านหมดอายุ
เพราะบัตรหมดอายุ = คนเดิมเครื่องเดิม **ถ้าล้าง ร่างที่กรอกค้างกับคิวที่ยังไม่ขึ้นระบบหายถาวร**

## ⑦🔴 ร่างที่กรอกค้าง ต้องแยกรายหน้าต่าง ไม่ใช่รายเครื่อง

**พี่กันสั่งเอง** — *"ที่กรอก 100 เครื่องก็ต้องแยกกัน และกรอกโครมเดียวกัน แต่คนละคนต้องแยกกัน"*

เก็บร่างไว้ก้อนเดียวต่อเครื่อง = **เปิดสองแท็บกรอกคนละเคส ร่างทับกันทันที**
ห้องยามีคอมเครื่องเดียวที่คนหลายคนสลับกันใช้ และเปิดหลายแท็บพร้อมกันเป็นเรื่องปกติ

**วิธี** — ให้แต่ละหน้าต่างถือรหัสของตัวเอง เก็บใน `sessionStorage` (แยกตามแท็บอยู่แล้ว)
แล้วมีทะเบียนกลางใน `localStorage` บอกว่ารหัสไหนยังมีคนถืออยู่

## ⑧🔴🔴 รีเฟรชหน้ากับก๊อปแท็บใหม่ แยกไม่ออกจากมุมโค้ด

**ทั้งคู่หน้าตาเหมือนกันเป๊ะ** — มีรหัสเดิมอยู่ และทะเบียนบอกว่ารหัสนั้นยังมีคนถือ

| เกิดอะไร | ควรได้ร่างไหน |
|---|---|
| รีเฟรชหน้าเดิม | **ได้ร่างเดิมกลับมา** |
| ก๊อปแท็บ (เปิดแท็บใหม่จากแท็บเดิม) | **ต้องได้ร่างเปล่า** ไม่ใช่ร่างของแท็บแม่ |

🔑 **ตัวแยกคือการปล่อยรหัสคืนตอนหน้ากำลังจะปิด** (`pagehide`)
รีเฟรชจะปล่อยคืนก่อนแล้วมาขอใหม่ → ทะเบียนว่าง → ได้ของเดิม
ก๊อปแท็บไม่ได้ปล่อยอะไรคืน → รหัสนั้นยังถูกถืออยู่ → ต้องแจกรหัสใหม่

## ⑨🚨 ระบบที่ทำงานเอง ห้ามเด้งหน้าเต็มจอ

**ทั้งตอนสำเร็จและตอนล้มเหลว** — ผู้ใช้อาจกำลังกรอกรายการถัดไปอยู่
และถ้าล้มซ้ำทุก 5 นาที หน้าจอจะเด้งขวางทั้งวัน

```js
// ตัวรับปุ่มที่ถูกเรียกทั้งจากคนกดและจากระบบ ต้องแยกให้ออก
function ส่งใหม่(opts = {}) {
  const อัตโนมัติ = opts.auto === true;
  if (!อัตโนมัติ) เปิดหน้าผล();      // คนกดเองเท่านั้นถึงเด้งหน้าเต็มจอ
}
```

🚨 **ระบบที่ทำงานเองบอกผลด้วยแถบเล็ก ๆ หรือตัวเลขบนไอคอน** ไม่ใช่หน้าเต็มจอ
