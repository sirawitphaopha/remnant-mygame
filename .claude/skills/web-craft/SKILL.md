## 6. 🏆 ทักษะ web dev ระดับเทพ (best practices จากที่ทำมาจริง)
- **Offline-first sync** — localStorage + debounce push + **merge เทียบเวลา (`_t` timestamp) ไม่ใช่ last-write-wins ทื่อๆ** + **tombstone `_del:true` แทน delete จริง** (กันติ๊กออกแล้วเด้งกลับข้ามเครื่อง) + flush ตอนปิดแอป · ทุกปุ่ม **immutable update** (สร้าง object ใหม่ ไม่ mutate)
- **Optimistic UI** — อัปเดต state ทันที → ยิง API เบื้องหลัง `.catch()` → revert ถ้าล้มเหลว · มี confirmUndo ก่อนทุกการยกเลิก/ลด/ลบ
- 🚨 **โหลดครั้งเดียว (load-once)** — หน้าที่โหลด list/data ห้าม fetch ใหม่ทุกครั้งที่เข้า · pattern: `loadCache(key)` seed state ตอน mount (ไม่ skeleton ซ้ำ) → `load(force)`: ถ้ามี cache สด (`Date.now()-c.ts < CACHE_TTL`) และไม่ force = **return ไม่ยิง server** · `saveCache` หลัง fetch สำเร็จ · invalidate cache ตอน mutation · helper กลางใช้ข้าม domain
- **Realtime** — **1 channel ต่อ 1 ตาราง** (หลาย channel ซ้อนตารางเดียว = ส่ง event ไม่ครบ ติดๆดับๆ) · **refetch ผ่าน API เมื่อได้ event ดีกว่า patch จาก payload** · subscription deps นิ่ง (ไม่ churn)
- 🚨 **Sticky header ห้ามมีช่องว่าง** — sticky ใน scroll container ที่มี `padding` (เช่น `p-6`=24px) ถ้าใช้ `top:0` จะ**ติดต่ำลง 24px** (=padding-top) · **สูตรถูก: `top:'-24px'` + `margin:'0 -24px Xpx'` + `padding:'12px 24px Ypx'`** · bg = สีพื้นหน้า · พิสูจน์: `getBoundingClientRect().top` ของ sticky = ของ scroll container (gap=0)
- 🚨🚨 **`margin:0 auto` + พ่อเป็น flex = หน้าเว็บหดเงียบ ๆ** — ใน flex ตัว `margin:auto` บนแกนขวางจะ**ยกเลิกการ stretch** แล้วย่อกล่องลงเท่า fit-content ไม่มี error ไม่มีคำเตือน (เจอจริง มูลค่ายาคืน 2026-08-05: หน้าเว็บหด 1360 → **1013px**) · **แก้: ใส่ `width:100%` ให้กล่องที่ใช้ `max-width + margin:0 auto` ทุกตัวที่พ่อเป็น flex** · ข้อยกเว้น: พ่อเป็นบล็อกธรรมดาไม่ต้องใส่
- 🚨 **จะให้กล่องลูกเลื่อนในตัวเอง (`overflow-y:auto`) พ่อทุกชั้นต้องมีความสูงที่แน่นอน** — ชั้นไหนเป็น `flex:1 0 auto` (ห้ามหด) จะทำให้ลูกไม่รู้ความสูงตัวเอง แล้วยืดตามเนื้อหาไปเรื่อย ๆ จนทั้งหน้าเลื่อนแทน · **สูตร: ทุกชั้นตั้งแต่ scroll container ลงมาต้องเป็น `flex:1;min-height:0`** แล้วชั้นสุดท้ายค่อยใส่ `overflow-y:auto` · ใส่ `min-height:XXXpx` ที่ตัวหน้าไว้เป็นทางหนีตอนจอเตี้ยมาก (ให้กลับไปเลื่อนทั้งหน้าแทนการบีบจนอ่านไม่ได้)
- **ระยะ sticky ที่ต้องอิงความสูงของอีกก้อน = วัดสดด้วย `ResizeObserver` เขียนลง CSS variable** อย่าตั้งเลขตายตัว (แถบที่มี `flex-wrap` จะขึ้นบรรทัดใหม่เองเมื่อจอแคบ ความสูงเปลี่ยน) · ผูก observer ผ่าน **ref แบบฟังก์ชัน** จะได้ต่อ/ถอดถูกจังหวะตอนของโผล่/หายจากจอ
- **ตรวจ "มีเมาส์จริงไหม" ใช้ `matchMedia('(pointer: fine)')`** ไม่ใช่เดาจากความกว้างจอ (แท็บเล็ตแนวนอน 1024px จะหลุด) · **ต้องฟัง event `change` ด้วย** ไม่ใช่วัดครั้งเดียวจบ เพราะเสียบเมาส์/ถอดจากแท่นวางค่าเปลี่ยนกลางคันได้ · โน้ตบุ๊กจอสัมผัสที่ต่อเมาส์ยังนับเป็น fine (ดูตัวชี้หลัก)
- **ไอคอนในปุ่มใช้ SVG inline ไม่ใช่ตัวอักษรพิเศษ** (`⤓` `⌫` ฯลฯ ขึ้นกับฟอนต์ของเครื่อง บางเครื่องกลายเป็นสี่เหลี่ยมว่าง)
- 🚨 **เช็ค Chrome จริง แต่ไม่ต้องเทสทุกครั้ง** — เทสเองเฉพาะ (1) พี่กันสั่งให้เทส (2) จุดที่เป็นระบบ/ฟีเจอร์ใหม่ · นอกนั้นถามพี่กัน/ให้พี่กันเทสเอง · 🔴 **หน้าที่เป็นส่วนของแอปจริง (มี auth/ข้อมูลจริง) = ต้องเทส "หน้าจริง" ในเบราว์เซอร์จริง ห้ามสร้าง mock HTML มาเทสแทน** (mock ผ่านหมดแต่เว็บจริงมีบั๊ก) · เทสที่**สัดส่วนจริง** (เดสก์ท็อป landscape มี sidebar ~1360px ถ้าเป็นเว็บเดสก์ท็อป / portrait ถ้าเป็น mobile app)
- **Security** — RLS ทุกตาราง (ลบ policy "allow all" ก่อน prod) · ไม่มี secret ใน client · privileged op ผ่าน API route (admin client) · escape XSS · CSP headers (ไม่มี unsafe-eval) · storage private + signed URL · rate limit brute force login
- **Performance** — lazy render (30 + ดูเพิ่ม) · debounce search 200-500ms · useMemo คำนวณหนัก · **CSS class แทน inline** เมื่อมี element เยอะ · materialized view + pg_cron สำหรับ query ช้า · virtual scroll · **Cache-Control no-store** แก้ error 500 chunk หาย
- **Mobile/PWA** — mobile-first · touch target ใหญ่ · `dvh` units · manifest+icon · **เทสเครื่องจริง** (headless จับ GPU freeze/paint ไม่ได้)
- **ไทยเฉพาะ** — วันที่ **timezone +7** (อย่าลืมบวก) · ฝังฟอนต์ไทยเอง (woff2 @font-face กันเครื่องไม่มีฟอนต์) · print-color-adjust บังคับพิมพ์สี
- **Deploy** — **Cloudflare Pages = HTML/static · Workers = Next.js มี server** · ตั้ง env vars บน host ให้ตรง .env.local · **Next.js 16 ห้าม rename middleware.ts→proxy.ts บน Cloudflare** · changelog generator อัตโนมัติ (ห้ามแก้ไฟล์ changelog มือ)
- **Email** — Resend · **fire-and-forget** (เมลล้มไม่ทำให้ flow พัง try/catch) · โลโก้ **PNG hosted (ไม่ใช่ inline SVG)** สำหรับ Gmail · Gmail บังคับรูปเต็มกล่อง → ใช้รูปจัตุรัส · เมลอ่านรูปจาก localhost ไม่ได้ (เห็นหลัง deploy)
- **File org** — แยกไฟล์ใหญ่ได้ (verify concat กลับ byte-identical) · classic scripts แชร์ global env · ⚠️ **content-visibility ทำ popup ค้าง** (diff หาเจอ ไม่ใช่การแยกไฟล์)
- 🚨 **Next.js dev/build** — **ห้ามรัน `npm run build` ขณะ `npm run dev` เปิดอยู่** → .next ชนกัน (Cannot find module './xxx.js') · ต้องหยุด dev + ลบ .next ก่อน build (เจอ 2026-07-17)
- 🚨🚨 **เซิร์ฟเวอร์ทดสอบ (localhost) เปิดได้ทีละตัวเดียวเท่านั้น · วันไหนเริ่มพอร์ตไหน ใช้พอร์ตนั้นทั้งวัน** (พี่กันสั่ง 10 ส.ค. 2569 *"เอาแค่อันเดียว อย่าเปิดสองโลคอลสิวะ"* · *"เธอรันโลคอลเลขไหนมาแล้วในวันนั้นๆ ให้ใช้อันเดิม"*)
  - **ก่อนเปิดทุกครั้ง เช็คก่อนว่ามีตัวไหนรันอยู่แล้ว** (`netstat -ano | grep LISTENING | grep :30`) · **มีอยู่แล้ว = ใช้ตัวนั้นเทส ห้ามเปิดเพิ่ม ห้ามปิดของพี่กันแล้วเปิดใหม่**
  - **ห้ามเปิด ๆ ปิด ๆ สลับพอร์ตไปมาเด็ดขาด** — พี่กันเปิดเว็บค้างไว้อยู่ พอแคลร์ปิด พี่กันเจอ ERR_CONNECTION_REFUSED แล้วต้องมาถามใหม่ เสียเวลาหลายรอบ (เคยพลาด: เปิด 3100 คู่กับ 3000 แล้วปิดทิ้งโดยไม่บอก)
  - จดพอร์ตของวันไว้ในไฟล์ session/CLAUDE.md ของโปรเจกต์ ครั้งหน้ามาต่อจะได้ใช้ตัวเดิม
- **Debug** — Supabase MCP execute_sql แยก backend/frontend · SWC strict จับ bug ที่ Babel ซ่อน (TDZ/ซ้ำ) · เทสหลายเบราว์เซอร์จับ GPU-specific freeze

## 6.6 🩺 คิดแบบนักออกแบบเว็บทางการแพทย์ — มาตรฐานงานทุกชิ้น

> พี่กันสั่งไว้ 19 ส.ค. 2569 · **อ่านข้อนี้ก่อนออกแบบหรือแก้หน้าจอทุกครั้ง**
> *"เราอยากให้เธอคิดว่าเธอเป็นนักออกแบบเว็บทางการแพทย์ ที่ข้อมูลจะต้องครบ สวย
> ผู้ใช้ใช้แล้วไม่งง ไม่ด่า และทุกอย่างมันต้อง perfectionist"*

### เกณฑ์ 4 ข้อที่ทุกหน้าต้องผ่าน

| | เกณฑ์ | แปลว่าอะไร |
|---|---|---|
| **ครบ** | ข้อมูลที่เก็บมาต้องไปโผล่ที่หน้าจอ | เก็บแล้วไม่แสดง = เสียเวลาคนกรอกฟรี |
| **สวย** | จัดวางเป็นระเบียบ สีมีความหมาย ไม่ใช่ตกแต่ง | ตารางดิบๆ ไม่ใช่งานออกแบบ |
| **ไม่งง** | คนเปิดมาครั้งแรกต้องรู้ว่ากำลังดูอะไร | ต้องเดา ต้องถาม = ออกแบบพลาด |
| **เนี้ยบ** | ไม่มีจุดค้าง ไม่มีของครึ่งๆ กลางๆ | ทำครึ่งเดียวแล้วบอกว่าเสร็จ ไม่นับ |

### 🔴 กฎที่ตกผลึกจากงานจริง

**1. ข้อมูลแต่ละชิ้นต้องไปอยู่บ้านของมัน ห้ามกองรวมเป็นตารางยาว**

พลาดจริง 19 ส.ค. 2569 — พี่กันสั่งว่า "ข้อมูลแรกรับต้องแสดงในแฟ้มทั้งหมด"
แคลร์เอาทุกช่องมากางเป็นตารางยาวก้อนเดียว พี่กันทักว่า
> *"หมายถึง ถ้า eGFR ก็ไปกราฟของมัน ชื่อ สิทธิรักษาก็ไปที่ส่วนข้อมูลส่วนตัว หรือยาก็ไปส่วนยา"*

· ค่าที่มีประวัติตามเวลา → **ไปอยู่กับกราฟของมัน**
· ข้อมูลตัวบุคคล → ไปอยู่ส่วนข้อมูลส่วนตัว
· ยา → ไปอยู่ส่วนยา · การแพ้ → ไปอยู่ส่วนความปลอดภัย
· **อยากดูทั้งหมดพร้อมกัน = ทำปุ่มกดแล้วเด้งหน้าต่างขึ้นมา** ไม่ใช่กางไว้บนหน้า

**2. ค่าอะไรที่วัดซ้ำได้ตามเวลา ต้องมีกราฟ**

ตัวเลขล่าสุดตัวเดียวบอกไม่ได้ว่าดีขึ้นหรือแย่ลง ซึ่งเป็นสิ่งที่คนดูแลอยากรู้ที่สุด
เก็บค่าไว้ทุกครั้งแล้วไม่วาดให้ดู = เก็บไปทำไม

**3. ทุกตัวเลขต้องบอกความหมาย ไม่ใช่โยนเลขเปล่า**

· ทาสีตามเกณฑ์จริง ไล่โทนต่อเนื่องไม่ข้ามขั้น
· มีหน่วยกำกับเสมอ · บอกว่าเทียบกับอะไร (ครั้งก่อน / แรกรับ / เป้าหมาย)
· 🔴 **ทุกเกณฑ์ต้องบอกที่มา** ว่ามาจากแนวทางฉบับไหนหน้าไหน หรือพี่กันกำหนดเอง
  สองอย่างนี้น้ำหนักไม่เท่ากัน คนอ่านต้องแยกออก

**4. ช่องที่ยังไม่มีข้อมูล ต้องเขียนว่ายังไม่ได้บันทึก**

ปล่อยว่างไว้เฉยๆ คนอ่านแยกไม่ออกว่า "ไม่มีข้อมูล" กับ "ระบบพัง"

**5. หน้าที่ไม่มีข้อมูลต้องเหลือโครง** การ์ดเป็น 0 หัวตารางยังอยู่ ไม่ใช่หายทั้งหน้า

**6. เก็บข้อมูลเกินดีกว่าขาด**

พี่กันสั่ง 19 ส.ค. 2569 — *"เราว่ามีตารางเก็บข้อมูลที่เกิน ดีกว่าขาด"*
เพราะข้อมูลที่ไม่ได้เก็บตั้งแต่แรก **ย้อนกลับไปเก็บไม่ได้** ตอนงานใกล้เสร็จค่อยทบทวนว่าจะตัดช่องไหน

**7. สีต้องพาสเทล นุ่มตา** พี่กันย้ำหลายรอบ
สีจัดจ้านใช้เฉพาะตอนเตือนจริงๆ · ที่เหลือให้อ่านสบายตาเพราะทีมต้องจ้องทั้งวัน

**8. ทำหน้าจอ = ทำมอคอัปให้ดูก่อนเสมอ ห้ามลงเว็บเลย**

🔴 พลาดจริง 19 ส.ค. 2569 พี่กันขอมอคอัป แคลร์ลงโค้ดในเว็บไปเลย
> *"แต่จริงๆที่ให้เธอทำคือมอคอัปนะ 55555 เธอทำลงเว็บซะงั้น"*

· ทำเป็นไฟล์ HTML เดี่ยวใน `mockups/` แล้วส่งให้ดู
· **เสนอหลายแบบให้เลือก** อย่างน้อย 2 ถึง 3 แบบ พร้อมบอกข้อดีข้อเสียของแต่ละแบบ
· ห้ามใช้ฟอนต์จาก CDN แม้แต่ในมอคอัป (เน็ตโรงพยาบาลไม่นิ่ง)

## 6.1 📊 ตารางต้องเป็น "ตารางจริง" เท่านั้น

**พี่กันสั่ง 1 ก.ย. 2569: "ตั้งเป็นกฎ ต้องสร้างตารางจริงเท่านั้น"**
หลังจากเพิ่งรู้ว่าปัญหาตารางที่ด่ามาทั้งหมดมาจากการไม่ได้ใช้ตารางจริง

- 🔴🔴🔴 **ข้อมูลที่เป็นแถวเป็นคอลัมน์ ต้องใช้ `<table>` `<thead>` `<tbody>` `<tr>` `<td>` เท่านั้น**
  ห้ามเอากล่อง (`<div>` + flex) มาวางเรียงให้ดูเหมือนตาราง

**ทำไม** — ที่เคยเสียเวลาแก้ซ้ำ ๆ เพราะเรื่องพวกนี้ ตารางจริงได้มาฟรีหมด

| เรื่อง | ตารางจริง | กล่องเรียงกัน |
|---|---|---|
| ความกว้างคอลัมน์ | เบราว์เซอร์จัดเอง ทุกแถวตรงแนวเสมอ | ต้องกำหนดเองทุกช่อง เหลื่อมกันบ่อย |
| เส้นแบ่งคอลัมน์เต็มความสูง | `border` ธรรมดา | ต้อง `align-self:stretch !important` แล้วยังพลาดได้ |
| ไฮไลต์แถวตอนชี้ | `tr:hover` | ต้องไล่ทำเองทุกชิ้นในแถว |
| ตรึงหัวตาราง | `thead` + `position:sticky` | ต้องวัดความสูงหัวด้วย ResizeObserver |
| หัวตารางซ้ำทุกหน้าตอนพิมพ์ | `display:table-header-group` | ทำไม่ได้เลย |
| โปรแกรมอ่านจอ | บอกได้ว่าช่องนี้อยู่คอลัมน์ไหน แถวไหน | อ่านเป็นข้อความกองเดียว |

🚨 **ข้อยกเว้นเดียว — การ์ดบนมือถือ** จอแคบเกินกว่าจะแสดงหลายคอลัมน์
   ให้สลับเป็นการ์ดได้ แต่ฝั่งคอมต้องเป็นตารางจริงเสมอ

⚠️ **ถ้าเจอโค้ดเก่าที่ทำเป็นกล่องเรียงกันไว้แล้ว** ให้บอกพี่กันว่าควรรื้อ
   อย่าเขียนกฎเพิ่มซ้อนไปเรื่อย ๆ เพราะจะต้องดูแลสองชุดตลอดไป

## 6.2 📊 CSS กลางของตาราง — ชุดเดียวใช้ทั้งเว็บ

**ต้นแบบ:** เว็บยาคืน `app/globals.css` คลาส `.tbl` (พี่กันย้ำว่าเอาต้นแบบจากหน้ารายการ Lot)

| คลาส | ใช้กับ |
|---|---|
| `.tbl` | โครงเต็ม — หัวตรึง · เส้นแบ่ง · มุมมน · ลูกศรเรียง |
| `.tbl-grid` | เฉพาะเส้นแบ่ง + ไฮไลต์แถว (ตารางที่หัวมีสีของตัวเอง) |
| `.tbl-zebra` | แถวสลับสีจาง |
| `.wrap` | คอลัมน์ที่ยอมให้ขึ้นบรรทัดใหม่ |
| `.ta-r` · `.ta-c` | ชิดขวา · กึ่งกลาง รายคอลัมน์ |

```css
.tbl { width:100%; border-collapse:collapse; table-layout:fixed; --tbl-pad:15px }
.tbl th, .tbl td { box-sizing:border-box; padding:0 12px; vertical-align:middle;
                   text-align:left; white-space:nowrap }
.tbl th:first-child, .tbl td:first-child { padding-left:var(--tbl-pad) }
.tbl th:last-child,  .tbl td:last-child  { padding-right:var(--tbl-pad) }
.tbl th:not(:last-child), .tbl td:not(:last-child) { border-right:1px solid rgba(30,36,32,.06) }
.tbl thead th { position:sticky; top:var(--tbl-top,0px); z-index:3; background:#e3f0e8 }
.tbl thead th.tbl-sort { cursor:pointer; user-select:none }
.tbl thead th.tbl-sort:hover { background:#d5e8dd }
```

🚨 **ค่าเริ่มต้นของทุกช่องคือ `white-space:nowrap`** เคยใส่ `overflow-wrap:anywhere` ให้ทุกช่อง
ผลคือปุ่มกลายเป็น **"แ ก้"** และมูลค่าตกสองบรรทัด · คอลัมน์ที่ต้องตัดบรรทัดใส่คลาส `wrap` เอง

🚨 **ตารางที่ไม่มี `table-layout:fixed` ต้องใช้ `box-shadow:inset` แทน `border-right`**
เส้นขอบจะไปเพิ่มความกว้างอีก 1px ต่อคอลัมน์ ตารางที่ล้นอยู่แล้วยิ่งล้น

🚨🔴 **ห้ามมี `overflow-x` หรือ `max-height` ครอบ `<table>`**
`overflow-x` ทำให้ `overflow-y` กลายเป็น `auto` โดยปริยาย → `position:sticky` ของ `<th>`
ไปผูกกับกรอบนั้นแทนพื้นที่เลื่อนของเว็บ **หัวตารางลอยไปโผล่กลางตาราง**
(เจอทั้งเว็บยาคืนและ ME-DRP)

🚨 **กรอบขาวที่ครอบตารางต้องมี `min-width: fit-content`**
ตารางล็อกความกว้างคอลัมน์ไว้ตายตัว จอที่แคบกว่านั้นถ้ากรอบไม่ยอมกว้างตาม
**ตารางจะทะลุออกนอกกรอบ เห็นเป็นปุ่มกับหัวตารางลอยทับกัน**

### แถบตรึงในกรอบที่มีระยะขอบใน — ต้องทำครบ 3 อย่าง

ขาดข้อใดข้อหนึ่งจะเห็นเป็นบั๊กคนละแบบ

| ต้องทำ | ถ้าไม่ทำ |
|---|---|
| `top` ติดลบเท่าระยะขอบใน (`-16px`) | ติดต่ำลง 16 จุด เกิดร่องให้แถวลอดผ่าน |
| ระยะขอบติดลบ + ระยะในชดเชย | เห็นแถวลอดตรงร่องซ้ายขวา |
| มุมมนตรงกับกรอบ (`14px 14px 0 0`) | มุมเหลี่ยมทับมุมมนของกรอบ |

🚨 **หัวตารางต้องติดที่ `calc(ความสูงแถบหัว - ระยะขอบใน)`**
ตัววัดความสูง (ResizeObserver) วัดความสูงเต็มซึ่งรวมระยะขอบในไว้ด้วย
เอามาใช้ตรง ๆ หัวตารางจะติดต่ำกว่าที่ควร

## 6.2.1 🔴🔴 หัวตารางที่ตรึงไว้ — เส้นขอบหายตอนเลื่อน (เจอจริง 21 ก.ย. 2569)

**อาการที่เจ้าของงานเห็น** — เลื่อนหน้าลง หัวตารางตรึงอยู่ตามปกติ แต่ **เส้นขอบรอบหัวตารางหายไป**
เหลือเป็นแถบสีลอย ๆ ไม่มีกรอบ ต่างจากตอนยังไม่เลื่อนที่มีกรอบครบ

### ① ต้นเหตุ — ตารางแบบ collapse วาดเส้นขอบที่ "ตัวตาราง" ไม่ใช่ที่ "ช่อง"

```css
table { border-collapse: collapse }     /* ตารางเกือบทุกตัวใช้แบบนี้ */
thead th { border-bottom: 1px solid ... }
```

ในโหมดนี้เส้นขอบเป็นสมบัติของตาราง ไม่ใช่ของช่อง
พอ `thead th` ถูกตรึงแล้วลอยขึ้นไปจากที่เดิม **เส้นไม่ลอยตามไปด้วย** จึงหายทั้งเส้นบนและเส้นล่าง

🔑 **ทางแก้ — หัวตารางต้องวาดเส้นของตัวเองด้วย `box-shadow: inset`**
ห้ามใช้ `border` เพราะเส้นขอบกินที่จริงแล้วดันความกว้างคอลัมน์ ตารางที่ล็อกความกว้างจะล้นทันที

### ②🔴🔴 `box-shadow` ไม่บวกกันระหว่างกฎ — กฎที่ชนะจะทับทั้งชุด

นี่คือจุดที่พลาดแล้วหาสาเหตุไม่เจอ

```css
.tbl-grid th:not(:last-child) { box-shadow: inset -1px 0 0 ... }   /* เส้นแบ่งคอลัมน์ ของเดิม */
.tbl thead th { box-shadow: inset 0 1px 0 ... }                    /* เส้นบน ที่เพิ่งเขียน */
```

กฎแรกมีน้ำหนักมากกว่า (class + pseudo-class + element) จึง **ทับเส้นบนหายทั้งแถว**
เหลือเห็นเส้นเฉพาะคอลัมน์แรกกับคอลัมน์สุดท้าย เพราะสองอันนั้นมีกฎของตัวเองที่น้ำหนักสูงกว่า

> เจ้าของงานเป็นคนจับได้ — *"คอลัมน์จัดการมีเส้นขอบ แปลว่าคอลัมน์ที่ไม่มีเส้นขอบคือคอลัมน์ที่เอาเมาส์ชี้แล้วเปลี่ยนสี"*

🚨 **ต้องเขียนเส้นทุกด้านรวมไว้ในกฎเดียวกัน และคุมน้ำหนักให้ชนะกฎเดิม**

```css
.tbl thead th:not(:last-child) { box-shadow: inset 0 1px 0 var(--กรอบ), inset 0 -1px 0 var(--เส้นล่าง), inset -1px 0 0 var(--เส้นแบ่ง) }
.tbl thead th:first-child { box-shadow: inset 0 1px 0 var(--กรอบ), inset 0 -1px 0 var(--เส้นล่าง), inset 1px 0 0 var(--กรอบ), inset -1px 0 0 var(--เส้นแบ่ง) }
.tbl thead th:last-child  { box-shadow: inset 0 1px 0 var(--กรอบ), inset 0 -1px 0 var(--เส้นล่าง), inset -1px 0 0 var(--กรอบ) }
```

### ③ กรอบที่ครอบตารางต้องถอดเส้นบนออก ไม่งั้นซ้อนกันเป็นเส้นหนาสองจุด

ตอนยังไม่เลื่อน กรอบยังอยู่ที่เดิม เส้นของกรอบกับเส้นที่หัวตารางวาดเองจะซ้อนทับกันพอดี

> *"พอเป็นแบบนี้ขอบเรามันหนาขึ้นไงตอนยังไม่เลื่อนเพจ"*

```jsx
<div style={{ border: "1px solid var(--กรอบ)", borderTop: "none", borderRadius: 10 }}>
```

🔑 ให้เหลือตัววาดเส้นบนตัวเดียวคือหัวตาราง แล้วหน้าตาจะเหมือนกันทั้งสองสภาพ

### ④🚨 ห้ามแก้ด้วยการเว้นช่องว่างใต้แถบที่ตรึงไว้

ถ้าเส้นบนของหัวตารางมุดหายใต้แถบค้นหา **ห้ามขยับหัวตารางลงหนึ่งจุดเพื่อให้เส้นโผล่**
ช่องว่างหนึ่งจุดนั้นกลายเป็นร่องให้แถวข้อมูลลอดผ่านให้เห็นทันที

> *"มันมีคำโผล่ฉากหลัง"*

ของสองชิ้นที่ตรึงต่อกันต้องชิดกันสนิทเสมอ ระยะต้องเป็น **0 พอดี**

### ⑤ สีเส้นต้องเท่ากับสีกรอบเป๊ะ

- จางกว่ากรอบ → มองไม่เห็นเลยบนพื้นหัวตารางที่มีสี (เคยใส่แล้วเจ้าของงานบอกว่า *"โกหก"*)
- เข้มกว่ากรอบ → ตอนยังไม่เลื่อนเห็นเป็นเส้นเข้มเกินมาหนึ่งเส้น

ใช้ตัวแปรสีเดียวกับกรอบที่ครอบตาราง ไม่ต้องคิดสีใหม่

### ⑥ วิธีตรวจ — สามสภาพ และต้องดูทุกคอลัมน์

| สภาพ | ต้องเห็นอะไร |
|---|---|
| ยังไม่เลื่อน | กรอบครบสี่ด้าน เส้นหนาหนึ่งจุด ไม่ใช่สองจุด |
| เลื่อนลง | เส้นบน เส้นล่าง และเส้นข้างยังอยู่ครบเหมือนเดิม |
| เลื่อนไปขวาสุด (ตารางกว้างเกินจอ) | เส้นขวาของคอลัมน์สุดท้ายยังอยู่ |

🚨🔴 **ห้ามตรวจแค่คอลัมน์แรก** — กับดักข้อ ② ทำให้คอลัมน์แรกกับคอลัมน์สุดท้ายมีเส้น
แต่คอลัมน์กลางทั้งหมดไม่มี ถ้าดูแค่ด้านซ้ายจะผ่านทุกครั้งทั้งที่ยังพัง

🚨🔴 **ห้ามรายงานว่าเสร็จจากการอ่านค่า `getComputedStyle`** ค่ามีอยู่ไม่ได้แปลว่าตาเห็น
ต้องเปิดภาพซูมดูจริงทั้งสามสภาพก่อนพูดว่าแก้แล้ว (พลาดมาแล้วในรอบเดียวกันนี้)


## 6.3 ⬆️ ลูกศรเรียงลำดับ — เรื่องที่โดนด่า 3 รอบ

**พี่กันสั่งเรื่องนี้ครั้งแรก 27 ส.ค. 2569 แล้วยังต้องทวงอีกที่ ME-DRP 4 ก.ย. 2569**

### ค่ามาตรฐาน — ทุกตารางในทุกเว็บต้องเหมือนกัน

```js
arrow:      on ? (dir === 'asc' ? '↑' : '↓') : '↑↓',
arrowColor: on ? '#2f7d5d' : 'rgba(30,36,32,.34)',
arrowSize:  on ? '19px' : '16px',
```

```
↑↓  ยังไม่ได้เรียงด้วยคอลัมน์นี้   16px  สีจาง
↑   น้อยไปมาก                    19px  เขียวเทล
↓   มากไปน้อย                    19px  เขียวเทล
```

⚠️ **ข้อยกเว้น** — ตารางที่มีคอลัมน์เยอะมาก (คลังยา 15 คอลัมน์) ใช้ **12px**
ลูกศรใหญ่เท่าหน้าอื่นจะดันหัวคอลัมน์จนตารางล้นขอบ

### 🔴🔴🔴 ลูกศรต้องเป็นฟอนต์ Roboto Mono ห้ามปล่อยให้ตกไปที่ Sarabun

พี่กันชี้ให้ดูภาพเทียบสองเว็บแล้วบอกว่า
> *"แหกตาดู ลูกศร / เราไม่ได้บอกให้อ่าน code / ดุรูป"*

**Sarabun วาด ↑↓ ผอมกว่า Roboto Mono ราว 30%** ตั้ง `font-size` เท่ากันเป๊ะก็ยังดูเล็กกว่าอยู่ดี

| ฟอนต์ | ↑↓ ที่ 16px กว้างเท่าไหร่ |
|---|---|
| Roboto Mono (`var(--font-mono)`) | **19.6px** |
| Sarabun | **14.1px** |

```jsx
<span aria-hidden="true" className="tbl-arrow"
      style={{ fontFamily:'var(--font-mono)', fontSize: c.arrowSize, color: c.arrowColor }}>
  {c.arrow}
</span>
```

🚨🔴 **เรื่องนี้อ่านโค้ดหรือวัด `font-size` ไม่มีทางเจอ** เพราะเลขเท่ากันทุกตัว
**ต้องเปิดสองเว็บเทียบด้วยตา** — พี่กันด่าเพราะแคลร์ตอบจากการอ่านโค้ดว่า "ตั้งเท่ากันแล้ว"
ทั้งที่ภาพที่พี่กันส่งมาเห็นชัดว่าไม่เท่า

### 🔴 ลูกศรต้องบอกความจริง — "ลูกศรโกหก" เจอมาแล้ว 2 เว็บ

**อาการ** หน้าจอเรียงวันที่ใหม่→เก่าอยู่แล้วตั้งแต่เปิดหน้า (ฐานส่งมาแบบนั้น)
แต่ตัวแปรที่จำว่า "เรียงด้วยคอลัมน์ไหน" ยังว่าง **ลูกศรจึงแสดง `↑↓` ทั้งที่เรียงอยู่จริง**

```js
// ✅ ยังไม่กดเรียง = ถือว่าเรียงด้วยคอลัมน์ตั้งต้น
const on  = sortKey ? sortKey === c.key : c.key === 'date';
const dir = sortKey ? sortDir : 'desc';
```

🚨 **กดคอลัมน์ตั้งต้นครั้งแรกต้องสลับทิศทันที** ไม่ใช่ตั้งค่าเดิมซ้ำ
ไม่งั้นกดแล้วหน้าจอไม่เปลี่ยนอะไรเลย **ดูเหมือนปุ่มเสีย**

🚨 **ตอนยังไม่ได้กดเรียง ต้องเรียงตั้งต้นเองเสมอ** ไม่ใช่ปล่อยตามลำดับที่ตัวโหลดคืนมา
(ตัวโหลดอาจเอารายการค้างมาต่อท้าย) ไม่งั้น **ลูกศรชี้ ↓ แต่ข้อมูลเรียงมั่ว**

🚨 **ถ้าใช้ `useMemo` ต้องใส่ตัวแปรการเรียงในรายการที่เฝ้าดู** ลืมแล้วกดเรียงข้อมูลไม่ขยับ
(กับดักที่ ME-DRP เขียนเตือนตัวเองไว้แล้ว แล้วก็ยังพลาดซ้ำ)

### ปุ่มล้างการเรียง

โผล่**เฉพาะตอนกดเรียงเองแล้วจริง ๆ** · โทนแดงอิฐ (`#c2543c` บนพื้น `#fdf1ed`)
🚨 **คนละปุ่มกับ "ล้างตัวกรอง"** — การเรียงกับการกรองคนละเรื่องกัน

### 🔑 บทเรียนที่แพงที่สุดของเรื่องนี้

**พี่กันบอกว่าให้ดูรูป = ให้ดูรูป ไม่ใช่ให้ไปอ่านโค้ดแล้วตอบว่าตั้งค่าถูกแล้ว**
ความต่างที่ตาเห็นแต่ตัวเลขบอกไม่ได้ มีจริงและเจอบ่อย — ฟอนต์ · น้ำหนักเส้น · ระยะที่ตาชั่ง
🔴 **พี่กันบอกว่ายังไม่เหมือน = ยังไม่เหมือน** ห้ามเถียงด้วยตัวเลขในโค้ด

## 6.4 🪟 ชั้นหน้าต่างซ้อน — ตารางกลางตัวเดียว ห้ามตั้งเลขเอง

**พี่กันเจอเอง 1 ก.ย. 2569:** กดดูรายการล็อต แล้วกดลบ
> *"เจ้า popup ลบมันดันอยู่ด้านหลัง popup ก่อนหน้า มันควรอยู่บนสุดสิ"*

**ต้นเหตุ** — แต่ละหน้าต่างตั้งเลขชั้นเองตามใจ (20 · 25 · 35 · 40 · 45 · 50 · 60 · 80 · 82)
ป๊อปยืนยันอยู่ 40 ส่วนหน้าต่างรายการล็อตอยู่ 60 **ป๊อปยืนยันจึงถูกทับ**

```js
export const Z = {
  bar:      6,   // แถบเมนู · แถบล่าง · หัวเว็บที่ตรึงไว้
  float:   15,   // ปุ่มลอย เช่น ปุ่มขึ้นบนสุด
  sheet:   20,   // แผ่นเลื่อนขึ้นจากขอบล่าง (มือถือ)
  menu:    29,   // เมนูเล็กที่กางจากช่องในหน้า (ไม่ใช่หน้าต่างซ้อน)
  panel:   32,   // หน้าต่างซ้อนทั่วไป
  over:    52,   // หน้าต่างที่เปิดทับหน้าต่างอื่นได้
  pick:    70,   // ตัวเลือกที่เปิดจากในหน้าต่างซ้อน
  confirm: 85,   // 🚨 ป๊อปยืนยัน — บนสุดของหน้าต่างทั้งหมดเสมอ
  toast:   95,   // ข้อความเด้ง — เหนือทุกอย่าง
};
```

🚨 **ทุกหน้าต่างต้องใช้เลขจากตารางนี้ ห้ามเขียนเลขเองอีก**
🚨 **ฉากหลังใช้เลขตรง ๆ · ตัวกล่องใช้ +1 · ของที่ซ้อนในกล่องใช้ +2**
🚨 **ป๊อปยืนยันต้องสูงกว่าหน้าต่างทุกตัว** มันคือด่านสุดท้ายก่อนข้อมูลหาย
🚨 **ปุ่มลอยต้องต่ำกว่าหน้าต่างซ้อนที่ต่ำที่สุดเสมอ** ไม่งั้นลอยทับแล้วกดโดน

### ฉากหลังห้ามเลื่อนเมื่อมีหน้าต่างซ้อน

| ชั้น | ที่ | ทำอะไร |
|:--:|---|---|
| 1 | ตัวดักเหตุการณ์ | ห้าม `touchmove` / `wheel` ที่ไม่ได้อยู่ในตัวหน้าต่างเอง (**ต้อง `passive: false`** ไม่งั้นห้ามไม่ได้) |
| 2 | `body` | ตรึงเป็น `position: fixed` แล้ว**จำตำแหน่งเลื่อนไว้คืนตอนปิด** |
| 3 | พื้นที่เลื่อนของเว็บ | `overflow-y: hidden` |

**ชั้นที่ 2 เขียนยังไง**

```js
// ตอนเปิด
const y = window.scrollY;
document.body.style.cssText = `position:fixed;top:${-y}px;left:0;right:0;overflow:hidden`;
// ตอนปิด — ต้องคืนตำแหน่งเดิม ไม่งั้นเด้งไปบนสุดทุกครั้งที่ปิดหน้าต่าง
document.body.style.cssText = "";
window.scrollTo(0, y);
```

🚨 **ชั้นที่ 2 คือตัวที่ขาดไม่ได้บน iOS** — ปิด `overflow` เฉย ๆ ไอโฟนยังเลื่อนได้
🚨 **ต้องคืนตำแหน่งเลื่อนตอนปิดเสมอ** ลืมแล้วผู้ใช้เด้งกลับบนสุดทุกครั้งที่ปิดหน้าต่าง
   ซึ่งเจ็บมากตอนกำลังดูรายการยาว ๆ อยู่กลางหน้า

🚨 **ปิด `overflow` อย่างเดียวพอสำหรับคอม แต่มือถือไม่พอ** เบราว์เซอร์ส่งการเลื่อนต่อ
ให้ตัวที่อยู่ข้างนอก ต้องห้ามที่เหตุการณ์ด้วย
🚨 **ต้องปล่อยให้เลื่อนได้ถ้านิ้วอยู่ในหน้าต่างซ้อนเอง** ตรวจด้วย `closest('[role="dialog"]')`
ไม่งั้นหน้าต่างที่มีเนื้อหายาวเลื่อนดูข้างในไม่ได้เลย
🚨 **เพิ่มหน้าต่างใหม่ต้องเติมชื่อในตัวนับหน้าต่างที่เปิดอยู่ด้วย** ไม่งั้นกฎนี้ไม่ทำงานกับตัวใหม่

## 6.5 ⌨️ ปุ่มทุกปุ่มต้องกดด้วยคีย์บอร์ดได้ + มีชื่อให้โปรแกรมอ่านจอ

มอคอัปมักทำปุ่มเป็น `<div onClick>` ซึ่ง **Tab ไม่ถึงและ Enter ไม่ทำงาน**
เว็บยาคืนเคยมีแบบนี้ **107 จุด** — หน้าบันทึกกด Tab ได้แค่ 4 ชิ้น ทั้งที่กดด้วยเมาส์ได้ 15 ชิ้น

```js
// ตัวช่วยกลาง — คืน onClick + role + tabIndex + onKeyDown ครบในตัวเดียว
export function kb(fn) {
  return { onClick: fn, role: 'button', tabIndex: 0,
           onKeyDown: (e) => { if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); fn(e); } } };
}
```

```jsx
// ❌ เดิม                          // ✅ ตอนนี้
<div onClick={V.save}>              <div {...kb(V.save)}>
```

🚨 **Space ต้อง `preventDefault`** ไม่งั้นหน้าเลื่อนลงตอนกด
🚨 **ปุ่มใหม่ทุกปุ่มต้องใช้ตัวช่วยนี้ ห้ามเขียน `onClick` เปล่า ๆ อีก**

### โปรแกรมอ่านจอต้องรู้ว่าปุ่มนี้ทำอะไร

| ทำอะไร | ใส่ที่ไหน |
|---|---|
| `aria-label` | **ปุ่มที่มีแต่ไอคอน** (✕ ✎ ⚙ ℹ ✓ ←) ไม่งั้นอ่านว่า "กากบาท" เฉย ๆ |
| `aria-hidden="true"` | ไอคอนที่เป็นแค่เครื่องหมายประกอบข้อความ (ไม่ใช่ปุ่ม) · ชั้นวาดตัวอักษร |
| `role="dialog" aria-modal="true"` | หน้าต่างซ้อนทุกตัว |
| `role="status" aria-live="polite"` | ข้อความเด้ง |
| `role="main"` · `role="navigation"` | กล่องเนื้อหาหลัก · แถบเมนู |
| `role="heading" aria-level="1"` | หัวเรื่องของหน้า |

🚨🔴 **เติม `role=` บนแท็กเดิม ห้ามเปลี่ยนแท็ก**
`<h1>` กับ `<main>` มีสไตล์ตั้งต้นของเบราว์เซอร์ติดมาด้วย (ระยะขอบ ขนาดตัวอักษร)
เปลี่ยนแท็กแล้วหน้าตาขยับทันที ซึ่งผิดกติกาว่างานเก็บกวาดต้องไม่แตะหน้าตาสักพิกเซล

## 6.7 🚨 คอมเมนต์ในโค้ดวางผิดที่ = เว็บพังทั้งเว็บ

**ย้ายมาจากสกิล `button-feedback` เมื่อ 5 ก.ย. 2569** — เดิมอยู่ผิดที่เพราะวันที่เจอบั๊กนี้
กำลังแก้ปุ่มอยู่พอดี แต่กฎนี้ **เกิดได้ทุกที่ที่เขียน JSX** คนที่กำลังทำตารางหรือหน้าสรุป
ไม่มีทางเปิดสกิลปุ่มมาอ่าน

**คอมเมนต์แบบ `{/* */}` วางได้เฉพาะตำแหน่งที่รับ element เท่านั้น**

```jsx
// ❌ พังทันที — วางในแอตทริบิวต์ของแท็ก
<div {/* คำอธิบาย */} style={...}>

// ❌ พังทันที — วางเป็นลูกตัวแรกของ {เงื่อนไข && (
{V.showBar && (
  {/* แถบนี้โผล่เฉพาะตอนมีของค้าง */}
  <div>...</div>
)}

// ❌ พังทันที — วางหลัง ) : ( ของเงื่อนไขสามทาง
// ❌ พังทันที — วางในบล็อก .map() ที่คืนค่าเดียว

// ✅ ถูก — ใช้คอมเมนต์จาวาสคริปต์เหนือบรรทัดแทน
// แถบนี้โผล่เฉพาะตอนมีของค้าง
{V.showBar && (<div>...</div>)}
```

**เหตุผล** — JSX รับ element ได้ชิ้นเดียวในตำแหน่งพวกนั้น **คอมเมนต์นับเป็นอีกชิ้น**

🚨 **อาการคือหน้าเว็บขึ้น error ทั้งใบ ไม่ใช่แค่จุดนั้นเสีย** เจอมาแล้ว 2 รอบในเว็บยาคืน
รอบที่สองเกิดหลังจากเขียนกฎเตือนตัวเองไว้แล้วด้วย

## 6.8 ✍️ ฟอนต์ — Sarabun สำหรับไทย · Roboto Mono สำหรับอังกฤษและตัวเลข

**พี่กันตั้งเป็นมาตรฐานกลาง 5 กันยายน 2569**

> *"ตั้งสารบรรณเป็นฟอนต์ไทย แล้ว roboto mono เป็นฟอนต์อังกฤษ **เป็นตัวหลักเลย**
>  ยกเว้นเว็บบางเว็บจะมีฟอนต์ไทยเป็นหัวเรื่องของตัวเอง อันนี้แยก"*

### กลไก — ทำไมไม่ต้องเขียนเงื่อนไขแยกภาษา

```css
font-family: var(--font-en), var(--font-sarabun), sans-serif;
/*              ↑ Roboto Mono      ↑ ตัวไทยตกมาใช้ตัวนี้เอง */
```

เบราว์เซอร์ไล่ตามลำดับ — ตัวอักษรไหนมีในฟอนต์แรกก็ใช้ตัวนั้น ไม่มีก็ตกมาตัวถัดไป
**Roboto Mono ไม่มีตัวอักษรไทยเลย ภาษาไทยจึงได้ Sarabun เองโดยอัตโนมัติ**
ไม่ต้องเขียนเงื่อนไขแยกภาษาสักบรรทัด

### 🥇 ต้นแบบที่สะอาดที่สุด — HCV Tracker

**HCV เป็นเว็บแรกที่ใช้ระบบนี้** และวางโครงไว้ดีที่สุด ตั้งที่เดียวจบ

```jsx
// app/layout.tsx
const sarabun    = Sarabun({     variable: '--font-sarabun-src', ... });
const robotoMono = Roboto_Mono({ variable: '--font-mono-src',    ... });

<html lang="th" className={`${sarabun.variable} ${robotoMono.variable}`}>
```

```css
/* app/globals.css */
:root { --font-en: var(--font-mono-src); }
html  { font-family: var(--font-en), var(--font-sarabun-src), sans-serif; }
```

🔑 **ตั้งที่ `<html>` ครั้งเดียวแล้วสืบทอดลงมาทั้งเว็บ ไม่ต้องไปแตะที่อื่นเลย**

⚠️ **เว็บยาคืนทำแบบเดียวกันแต่ยากกว่า** เพราะทั้งเว็บวาดด้วยสไตล์ฝังในแท็กราว 600 จุด
จึงต้องใช้ตัวแปลงกลาง (`fontify()` ใน `helpers.js`) แทรก `var(--font-en)` ให้ทุกจุด
**เว็บใหม่ไม่ต้องทำแบบนี้ ใช้ท่าของ HCV ได้เลย**

### 🚨 ตั้งชื่อตัวแปรให้เหมือนกันทุกเว็บ

ตอนนี้ 3 เว็บใช้ชื่อคนละชุด ทำให้ยกโค้ดข้ามเว็บไม่ได้

| ตัวแปร | ใช้ทำอะไร |
|---|---|
| `--font-sarabun` | Sarabun ตัวจริงจากตัวโหลดฟอนต์ |
| `--font-mono` | Roboto Mono ตัวจริง |
| **`--font-en`** | **ตัวกลางที่ทุกจุดในเว็บอ้างถึง** — ชี้ไป `--font-mono` ตอนเปิดโหมดนี้ |

🔑 **ต้องมี `--font-en` เป็นตัวกลางเสมอ** เพื่อให้สลับกลับไปใช้ Sarabun ล้วนได้ในที่เดียว
🚨 **โหมด "แบบปกติ" ต้องชี้ `--font-en` กลับไปที่ Sarabun ห้ามตั้งเป็นค่าว่าง**
ค่าว่างทำให้ประโยค `font-family` พังทั้งบรรทัด ตัวอักษรกลายเป็นฟอนต์ของระบบ

### ฟอนต์หัวเรื่องเฉพาะเว็บ — แยกต่างหาก ไม่บังคับ

แต่ละเว็บมีฟอนต์ของตัวเองสำหรับ **ชื่อเว็บ** ได้ ไม่ต้องเหมือนกัน

| เว็บ | ฟอนต์ชื่อเว็บ |
|---|---|
| มูลค่ายาคืน | **Krub** (พี่กันไล่ลองเอง 4 ตัว — Charm → Thasadith → Charmonman → Krub) |
| คลังคำ | Charmonman |

🚨 **ใช้กับชื่อเว็บเท่านั้น ห้ามลามไปที่อื่น** ฟอนต์ตกแต่งอ่านตัวเลขกับชื่อยายาก
ซึ่งเป็นข้อมูลความปลอดภัยที่ต้องอ่านง่ายที่สุด
⚠️ **ขนาดต้องใหญ่กว่าตัวพิมพ์ทั่วไป** เพราะเส้นบางกว่า

### 🔴🔴 เว็บที่มีอยู่แล้ว ห้ามแตะฟอนต์เอง ต้องรอพี่กันสั่ง

> พี่กันสั่ง 5 ก.ย. 2569: *"เว็บที่มีก่อนหน้าค่อย ๆ ปรับฟอนต์ **ไม่งั้นพังทั้งเว็บ**
>  ส่วนเว็บในอนาคตที่จะสร้าง ให้ใช้สองฟอนต์นี้เป็นฐานตั้งแต่เริ่มเลย"*

**เพราะ Roboto Mono กว้างกว่า Sarabun ราว 15%** เปลี่ยนทีเดียวทั้งเว็บแล้วของที่เคยพอดีจะล้นทุกจุด

เว็บยาคืนเคยเจอตอนเปลี่ยน — คอลัมน์วันที่ตกบรรทัดเป็นสองแถว · ตัวเลขใหญ่หน้าสรุปล้นออกนอกกรอบ ·
ชื่อผู้บันทึกถูกตัดท้ายด้วยจุดไข่ปลา · ต้องไล่แก้ทีละจุดทั้งเว็บ

| เมื่อไหร่ | ทำยังไง |
|---|---|
| **เว็บใหม่ที่กำลังจะสร้าง** | ✅ ใส่ทั้งสองฟอนต์ตั้งแต่วันแรก ใช้ท่าของ HCV |
| **เว็บที่มีอยู่แล้ว** | 🛑 **ห้ามแตะเอง** รอพี่กันสั่งแล้วค่อย ๆ ปรับทีละส่วน |

### ⚠️ กับดักที่เคยเจอจริง

**① ใบพิมพ์เอกสารราชการห้ามเปลี่ยนตาม**

## 6.9 🔴🔴🔴 ค่าที่ถูกใช้ข้ามหน้า ห้ามอยู่ในไฟล์ที่ถูกข้ามการคำนวณได้

## 6.13 📐 กับดักการจัดวางกล่องแบบยืดหยุ่น — ครบชุด 5 ข้อ

### ① `margin:0 auto` + พ่อเป็นกล่องยืดหยุ่น = หน้าเว็บหดเงียบ ๆ

**เจอจริง เว็บยาคืนหดจาก 1360 เหลือ 1013 จุด** ไม่มีข้อความผิดพลาด ไม่มีคำเตือน
**แก้:** ใส่ `width:100%` ให้กล่องที่ใช้ `max-width` คู่กับ `margin:0 auto` ทุกตัวที่พ่อเป็นกล่องยืดหยุ่น

### ② กล่องลูกจะเลื่อนในตัวเองได้ พ่อทุกชั้นต้องมีความสูงที่แน่นอน

ชั้นไหนเป็น "ห้ามหด" จะทำให้ลูกไม่รู้ความสูงตัวเอง แล้วยืดตามเนื้อหาไปเรื่อย ๆ
**สูตร:** ทุกชั้นตั้งแต่พื้นที่เลื่อนลงมาต้องเป็น `flex:1;min-height:0`

### ③🚨 `flex:1` ย่อมาจาก `1 1 0%` — ฐานเป็นศูนย์ กล่องจึงไม่ยอมหด

**นี่คือกับดักที่ต่างจากข้อ ② และเจอแยกกัน**

```css
flex: 1;          /* = 1 1 0%  ฐานความสูงเป็นศูนย์ */
flex: 1 1 auto;   /* ✅ ฐานเป็นความสูงจริงของเนื้อหา */
```

**ฐานเป็นศูนย์ทำให้การคำนวณการหดได้ศูนย์ตาม กล่องไม่ยอมหดแม้ใส่ `min-height:0` แล้ว**
เว็บยาคืนเจอตอนกล่องในแผงขวาไม่ยอมหด **แล้วไปดันปุ่มบันทึกตกขอบแผง**

### ④ ของที่ "ยุบได้ตอนที่ว่างไม่พอ" ต้องเช็คว่ายุบแล้วยังอ่านได้

ใส่ให้กล่องเลื่อนในตัวเองได้ + ความสูงต่ำสุดน้อยเกินไป **= พอที่ว่างหด กล่องจะยุบจนเนื้อหาหายเข้าไปข้างใน**

🚨 **ซ่อนเนื้อหาในกล่องจิ๋ว แย่กว่าปล่อยให้ทั้งแผงเลื่อน**
ตั้งความสูงต่ำสุดที่อ่านได้จริง แล้วถ้าที่ไม่พอ ให้กลับไปเลื่อนทั้งหน้าแทน

**🔑 วิธีหาบั๊กนี้** — วัดพื้นที่เลื่อนทุกอันในหน้า แล้วหาตัวแปลกปลอม
กล่องที่ไม่ควรเลื่อนได้แต่เลื่อนได้ = ตัวที่ยุบ

### ⑤🔴 พื้นที่เลื่อนก้อนเดียวใช้ร่วมทุกหน้า = ตำแหน่งเลื่อนค้างข้ามหน้า

🦴 **ย้ายไปเป็นข้อ 6.26 ของตัวเองแล้ว (17 ก.ย. 2569)** — ต้นเหตุ วิธีทำ และวิธีเทสครบอยู่ที่นั่น

**เจอจริง** — ตัวคำนวณหน้าสรุปเคยอ่านค่าตัวเลขที่กำลังวิ่งนับขึ้น
**ตัวเลขวิ่ง 112 รอบ = คำนวณข้อมูลใหม่ทั้งก้อน 112 รอบ**

🚨 **รายการที่ตัวคำนวณเฝ้าดู ต้องใส่เฉพาะค่าที่ใช้จริง ห้ามใส่สถานะทั้งก้อน**
ใส่ทั้งก้อน = ขยับอะไรก็ตามในหน้า ตัวคำนวณหนักทำงานใหม่หมด

## ③ ตัวช่วยที่เก็บผลไว้ใช้ซ้ำ ห้ามแก้ของที่ได้คืนมา

ตัวช่วยสไตล์ที่ถูกเรียกหลายร้อยจุดจะคืน**ของชิ้นเดิม** ทุกครั้ง
แก้ของที่ได้มา = **ไปเปลี่ยนหน้าตาของทุกจุดที่เรียกตัวเดียวกัน**

## ④ โหมดเข้มงวดสร้างส่วนประกอบสองรอบ

ตัวดักที่ผูกไว้ตอนสร้าง จะถูกผูกซ้ำสองครั้ง **ต้องมีธงกันผูกซ้ำ**
ไม่งั้นเหตุการณ์เดียวถูกจัดการสองรอบ (เช่น บันทึกซ้ำ · เสียงเตือนดังสองที)

# 6.18 🚀 ปล่อยขึ้นเว็บจริง — 4 กับดักที่ทำให้เว็บพังทั้งใบ

## ①🔴🔴 แตะกติกาความปลอดภัยของหน้าเว็บเมื่อไหร่ ต้องเทสแบบเว็บจริงเสมอ

**เทสตอนพัฒนาผ่านหมด แต่พอสร้างเป็นเว็บจริง สคริปต์ถูกบล็อกทั้งหมด จอขาวทั้งใบ**

หน้าที่ถูกสร้างไว้ล่วงหน้าจะได้ไฟล์ที่**ไม่มีใบอนุญาตแนบไปด้วย** ต่างจากตอนพัฒนา
🚨 **ต้องสร้างแบบเว็บจริงแล้วเปิดดูทุกครั้งที่แตะเรื่องนี้** ไม่มีข้อยกเว้น

## ②🔴 ตัวแปรที่เบราว์เซอร์ต้องเห็น ต้องมีอยู่ตอนสร้าง ไม่ใช่ตอนรัน

**ต้นเหตุจริงที่ทำให้เว็บเปิดมาแล้วต่อฐานไม่ติด** — ตัวแปรถูกตั้งไว้แล้ว
**แต่ตั้งหลังจากสร้างเสร็จ** ค่าจึงไม่ถูกฝังลงไฟล์ที่ส่งให้เบราว์เซอร์ เหลือเป็นค่าว่าง

🚨 **เพิ่มหรือแก้ตัวแปรพวกนี้ = ต้องสั่งสร้างใหม่เสมอ**

## ③ คำสั่งสร้างกับชื่อโปรเจกต์บนบริการ ต้องตรงกับของจริง

| พลาดตรงไหน | ผลที่ได้ |
|---|---|
| คำสั่งสร้างไม่ใช่ตัวแปลงสำหรับบริการนั้น | ได้ไฟล์ผิดชุด ปล่อยขึ้นไปแล้วหาไฟล์ไม่เจอ |
| **ชื่อในไฟล์ตั้งค่าไม่ตรงกับชื่อโปรเจกต์จริง** | **ปล่อยขึ้นไปแล้วไปสร้างเว็บใหม่อีกอัน แทนที่จะทับของเดิม** |

## ④ ตัวอักษรพิเศษในไฟล์ไอคอน ต้องแปลงเป็นเส้นวาด

**ไฟล์ไอคอนถูกวาดนอกหน้าเว็บ ฟอนต์ที่เว็บโหลดมาใช้ไม่ได้**
ปล่อยเป็นตัวอักษร = เครื่องที่ไม่มีฟอนต์นั้นเห็นเป็นกล่องเปล่า

# 6.19 🪟 หน้าต่างซ้อนกับปุ่ม — 4 ข้อที่พี่กันเจอเองทั้งหมด

## ①🔴 ของที่กระจายเข้าแท็ก ต้องวางก่อนของที่ตั้งค่าตายตัวเสมอ

**พี่กันเจอเอง** — *"ทำไมเราสโครลเมาส์ลงไม่ได้วะ"*

```jsx
<div {...kb(onClose)} role="dialog">   {/* ✅ ของที่กระจายอยู่ก่อน ค่าตายตัวชนะ */}
<div role="dialog" {...kb(onClose)}>   {/* ❌ ตัวช่วยคืน role="button" มาทับ dialog */}
```

พอบทบาทถูกทับ ระบบกันเลื่อนที่ผูกกับบทบาทหน้าต่างซ้อนก็หยุดทำงานทั้งชุด

## ② ฉากหลังห้ามเลื่อนบนมือถือ — ดักเหตุการณ์แตะอย่างเดียวไม่พอ

**พี่กันเจอเอง** — *"ทำไมเราเปิดหน้าต่างซ้อนแล้วเลื่อนหน้าลงล่างได้"*

🚨 **ต้องตรึงตัวหน้าเว็บด้วย `position:fixed` และจำตำแหน่งเลื่อนไว้คืนตอนปิด**
ไม่งั้นปิดหน้าต่างแล้วเด้งกลับไปบนสุด ซึ่งน่ารำคาญกว่าเดิม

## ③ เปลี่ยนหน้าต่างซ้อนเป็นหน้าเต็มจอ ต้องเป็น "แทนที่" ไม่ใช่ "วาดเพิ่ม"

วาดคู่กับหน้าเดิม = ของสองหน้าอยู่ในจอพร้อมกัน **ปุ่มชื่อเดียวกันมีสองตัว**
ตัวตรวจกับโปรแกรมอ่านจอจะเจอของซ้ำ และการกดคีย์ลัดจะไปโดนตัวที่ซ่อนอยู่

## ④🚨 แถวที่มีปุ่มสลับสถานะ ต้องมีจำนวนช่องปุ่มคงที่เสมอ

```
ปกติ:  [ตัวเลข 150px][✎ 26px][ที่ว่าง 26px]
แก้ไข: [ช่องกรอก 150px][✓ 26px][✕ 26px]
```

**จำนวนช่องไม่เท่ากัน = กดแล้วทั้งกรอบขยับ** ตาหลุดจากแถวที่กำลังแก้

# 6.20 🔢 ตัวเลขและกราฟที่ข้อมูลอาจไม่ครบ

## 🔴 กราฟที่ข้อมูลอาจไม่ครบ อันตรายกว่าไม่มีกราฟ — เหตุผลของพี่กันเอง

> พี่กันปฏิเสธมอคอัปด้วยเหตุผล *"ไม่รู้ว่าคนใช้จะกรอกเรื่องทำลายครบไหม"*

**กราฟที่วาดจากข้อมูลที่กรอกไม่ครบ จะดูเหมือนข้อมูลจริงทุกอย่าง**
คนอ่านไม่มีทางรู้ว่าตัวเลขนั้นขาดไปเท่าไหร่ **แล้วเอาไปตัดสินใจต่อ**

🚨 **ช่องที่ไม่ได้บังคับกรอก ห้ามเอามาทำกราฟที่ใช้ตัดสินใจ**
ถ้าจำเป็นต้องมี ต้องเขียนกำกับว่าอิงจากกี่รายการจากทั้งหมดเท่าไหร่

```js
await โหลดข้อมูล();
if (โหมดเปลี่ยนไปแล้ว) return;   // 🚨 เช็คซ้ำ "หลังรอ" ก่อนเขียนลงจอ
setState(...)
```

**เจอจริง** — คำขอที่ยิงไปก่อนสลับโหมด เดินทางกลับมาทีหลังแล้วเขียนทับข้อมูลของโหมดใหม่

# 6.21 ⬆⬇ ปุ่มขึ้นบนสุด / ลงล่างสุด — กฎกลาง ใช้ทุกเว็บ ทุกฝั่งจอ

> **พี่กันสั่งตั้งเป็นกฎกลาง 10 ก.ย. 2569** — *"ตั้งเป็นสกิลหลักหน่อย ที่จะใช้ทุกเว็บ
> ทุกโมบาย และเดส"* · ก่อนหน้านั้นเลือกแบบนี้จากมอคอัป 3 แบบ
> *"ไม่เอา ก เพราะมันจะมองปุ่มนั้นเป็นปุ่มเรียง"* · *"ควรเอาแบบ ค"*

หน้าที่มีรายการยาว (รายงาน · ประวัติ · แดชบอร์ด · รายการชุด) เลื่อนลงไปลึกแล้วกลับขึ้นมาไกลมาก
แต่ปุ่มลอยแบบธรรมดา **ตกไปทับปุ่มในแถวข้อมูลพอดี** ซึ่งมักเป็นปุ่ม "ลบ"

---

## ① ปุ่มไหนโผล่ — ตามตำแหน่งที่เลื่อนอยู่

| อยู่ตรงไหน | ↑ ขึ้นบนสุด | ↓ ลงล่างสุด |
|---|:---:|:---:|
| **บนสุด** | ซ่อน | **โผล่** |
| **ระหว่างทาง** | **โผล่** | **โผล่** |
| **ล่างสุด** | **โผล่** | ซ่อน |
| **เนื้อหาสั้นกว่าจอ** | ซ่อน | ซ่อน |

🚨 **ปุ่มที่ชี้ไปยังที่ที่ยืนอยู่แล้ว = ปุ่มหลอก** กดแล้วไม่มีอะไรเกิดขึ้น
คนจะเลิกเชื่อปุ่มนั้นไปเลย ทั้งที่อีกปุ่มยังทำงานปกติ

🚨 **แถวสุดท้ายสำคัญที่สุด** — หน้าที่เนื้อหาสั้นกว่าจอ **ห้ามมีปุ่มลอยมาบังอะไรเลย**
ลืมข้อนี้แล้วหน้าที่ว่างเปล่าจะมีปุ่มลอยสองอันชี้ไปไหนก็ไม่รู้

---

## ② ชัดแค่ไหน — ตามว่าเพิ่งเลื่อนไหม

```
เพิ่งเลื่อนภายใน 1.5 วินาที    ชัดเต็มตา   (ทึบ 100%)
หยุดอ่านเกิน 1.5 วินาที         จางลง       (ทึบ 30% — อ่านตัวหนังสือใต้ปุ่มทะลุได้)
เอาเมาส์ชี้ (เฉพาะจอที่มีเมาส์) กลับมาชัด + พื้นเข้มขึ้น
```

**นี่คือส่วนที่ทำให้ปุ่มไม่บังเนื้อหาจริง ๆ** — ชั้นที่ ① อย่างเดียวไม่พอ
เพราะปุ่มที่เหลืออยู่ปุ่มเดียวก็ยังทับของข้างใต้อยู่ดี

---

## ③ 🚨 กฎที่ห้ามละเมิด — ทุกข้อมาจากของที่พังจริง

### ①🔴 กล่องครอบต้องไม่รับการกด ปุ่มข้างในถึงรับ

```css
กล่องครอบ  pointer-events: none
ปุ่มข้างใน  pointer-events: auto
```

ไม่งั้น **ช่องว่างระหว่างปุ่มสองอันจะกลืนการกดของสิ่งที่อยู่ข้างใต้**
กล่องสูงราว 96 จุด แต่ปุ่มจริงกินแค่ 88 จุด ที่เหลือคือกล่องเปล่าที่มองไม่เห็น
คนกดตรงนั้นแล้วไม่มีอะไรเกิดขึ้น หาสาเหตุไม่เจอเพราะไม่มีอะไรให้เห็น

### ②🔴 ปุ่มที่ถูกซ่อนต้องกดไม่ได้ด้วย ไม่ใช่แค่จางจนมองไม่เห็น

ปุ่มใสที่ยังกดได้คือกับดักที่ไม่มีทางหาสาเหตุเจอ — ต้องตั้ง `pointer-events: none` คู่กันเสมอ

### ③🔴 ปุ่มที่ "จาง" ต้องยังกดได้ (ตั้งใจ ไม่ใช่ลืม)

ฟังดูขัดกับข้อ ② แต่คนละเรื่องกัน — **ซ่อน** กับ **จาง** ต่างกัน

ถ้าปล่อยให้กดทะลุปุ่มที่จางไปโดนของข้างใต้ คนที่เล็งกดปุ่ม ↑ จะไปโดนปุ่ม **ลบ**
ที่อยู่ใต้ปุ่มพอดี = **ลบข้อมูลโดยไม่ตั้งใจ** ซึ่งอันตรายกว่าปุ่มที่บังปุ่มลบไว้มาก

### ④ ตำแหน่งปุ่มตายตัวเสมอ — ขึ้นอยู่บน ลงอยู่ล่าง

ปุ่มวางด้วยตำแหน่งสัมบูรณ์ในกล่องความสูงคงที่
**ห้ามให้ปุ่มเลื่อนขึ้นมาแทนที่กันเมื่ออีกปุ่มหายไป**
ปุ่มที่ขยับตำแหน่งตามสถานการณ์ทำให้ตาต้องไล่หาใหม่ทุกครั้ง

### ⑤ ห้ามเขียนสถานะทุกครั้งที่เลื่อน

ปัดนิ้วครั้งเดียวยิงเหตุการณ์เป็นร้อยครั้ง — รวบด้วย `requestAnimationFrame`
แล้วเขียนเฉพาะตอนค่าเปลี่ยนจริง ไม่งั้นวาดจอใหม่เป็นร้อยรอบต่อการปัดหนึ่งครั้ง

### ⑥ ต้องทวนตำแหน่งใหม่ทุกครั้งที่หน้าจอวาดใหม่ด้วย

ความสูงเนื้อหาเปลี่ยนได้ตลอดโดยไม่มีใครเลื่อนเลย
(ข้อมูลมาถึง · เปลี่ยนตัวกรอง · สลับหน้า · กดดูเพิ่ม)
🚨 **แต่ต้องไม่ปลุกปุ่มให้ชัดขึ้นมาเอง** ตื่นได้เฉพาะตอนคนเลื่อนจริงเท่านั้น

### ⑦ หน้ากรอกข้อมูลห้ามใส่

> พี่กันสั่ง 1 ก.ย. 2569 — *"ใส่เฉพาะหน้าแดชบอร์ด และหน้ารายงาน แต่หน้ากรอกข้อมูลไม่ใส่"*

หน้ากรอกมักมีแถบบันทึกตรึงอยู่ล่างจอแล้ว ปุ่มลอยเพิ่มอีกคู่จะบังรายการที่กำลังกรอกอยู่

**นอกนั้นใส่ให้ครบทุกหน้าที่เป็นรายการยาว** — พี่กันต้องมาสั่งเพิ่มทีละหน้าถึงสองรอบ
เพราะรอบแรกใส่ไม่ครบ (*"หน้า lot ทำด้วยสิ"* · 10 ก.ย. 2569)

### ⑧ ต้องหายไปเมื่อมีหน้าต่างซ้อนเปิดอยู่

ไม่งั้นปุ่มลอยค้างอยู่เหนือฉากหลังที่ถูกล็อกไว้ กดแล้วเลื่อนฉากหลังที่ห้ามเลื่อน

### ⑨ เดสก์ท็อปต้องมีด้วย ไม่ใช่ของมือถืออย่างเดียว

> พี่กันสั่ง — *"เอาระบบนี้ไปใช้กับเว็บเดสก์ท็อปด้วย แต่ถ้าเอาเมาส์ไปชี้ มันจะเปลี่ยนเป็นสีเข้ม"*

ตรรกะชุดเดียวกันเป๊ะทั้งสองฝั่ง ต่างกันแค่เดสก์ท็อปมีการตอบสนองตอนเอาเมาส์ชี้เพิ่มมา
(กฎเรื่องสีตอนชี้อยู่ในสกิล `button-feedback`)

### ⑩🔴 กดแล้วต้อง "เลื่อน" ไม่ใช่ "วาร์บ"

> พี่กันสั่งเอง 16 ก.ย. 2569 — *"ตอนกดขึ้นสุดลงสุด มันควรเลื่อนเพจ ไม่วาร์บ"*
> และท้วงต่อว่า *"ทุกเว็บของเราไม่มีเว็บไหนวาร์บเลยตอนกด"*

กระโดดถึงทันทีทำให้ **ไม่รู้ว่าตัวเองอยู่ตรงไหนของหน้า** ต้องกวาดตาหาใหม่ทั้งหน้า
ทั้งที่ปุ่มนี้มีไว้เพื่อให้เดินทางง่ายขึ้น ไม่ใช่ให้หลงทาง

🚨 **แต่ห้ามใช้ `behavior: "smooth"` เป็นคำตอบ**

`smooth` **ไม่ทำงานเมื่อแท็บไม่ได้แสดงผลอยู่** (`document.hidden`)
ซึ่งเป็นสภาพปกติของแท็บที่ใช้ตรวจงาน สั่งแล้วตำแหน่งไม่ขยับเลยสักจุด
เบราว์เซอร์หยุดยิงจังหวะวาดจอให้แท็บที่ซ่อนอยู่ ทุกอย่างที่พึ่งจังหวะนั้นจึงหยุดหมด
รวมทั้ง `requestAnimationFrame` ที่เขียนเองด้วย — จึงต้องเพิ่มทางออกให้มัน

```js
if (document.hidden) { window.scrollTo(0, end); return; }   // ไม่มีใครดูอยู่ ไปถึงทันทีเลย
```

🔴 **เคยสรุปผิดมาแล้ว** — 16 ก.ย. 2569 วัดในแท็บที่ซ่อนอยู่แล้วเห็นว่า `smooth` ไม่ขยับ
จึงเขียนความจำถาวรว่า *"เครื่องพี่กันใช้ smooth ไม่ได้ ทุกเว็บต้องใช้ auto"*
แล้วไล่เปลี่ยนทั้งเว็บให้กระโดด **ทั้งที่เครื่องพี่กันไม่เคยมีปัญหานี้**
พี่กันเป็นคนจับได้เอง เพราะเว็บ ME-DRP กับ HCV ใช้ `smooth` อยู่และเลื่อนปกติมาตลอด

> **บทเรียน** — เบราว์เซอร์ที่เราสั่งงานเพื่อตรวจ **ไม่ใช่** เบราว์เซอร์ของคนใช้
> เจออะไรไม่ทำงานในนั้น ห้ามสรุปเป็นกฎของเครื่องคนใช้ ต้องหาหลักฐานจากเว็บที่ใช้งานจริงก่อน

**วิธีที่ถูก — เขียนการเลื่อนเองทีละเฟรม** ได้ทั้งความนุ่มบนเครื่องคนใช้ และตรวจได้จริงตอนเทส

```js
const dist = end - start;
const dur  = Math.min(620, Math.max(280, Math.abs(dist) * 0.42));  // ไกลขึ้นช้าลงนิดหน่อย
const e    = k < 0.5 ? 2*k*k : 1 - Math.pow(-2*k+2, 2)/2;          // ออกช้า เร่งกลาง หยุดนุ่ม
window.scrollTo(0, start + dist * e);
```

· **ต้องยกเลิกทันทีเมื่อคนใช้หมุนล้อ แตะจอ หรือกดคีย์** ไม่ใช่ลากเขาไปจนสุดทางแล้วค่อยปล่อย
· **อยู่ในไฟล์กลางไฟล์เดียวทั้งเว็บ** ทุกที่ที่เลื่อนหน้าตามคำสั่งคนใช้เรียกตัวเดียวกัน
  ไม่งั้นจังหวะจะไม่เหมือนกันคนละหน้า
· **การตั้งตำแหน่งเริ่มต้นของของที่เพิ่งกางออก (วงล้อ · ปฏิทิน) ไม่ใช้ตัวนี้**
  ตรงนั้นคือการ "วาง" ไม่ใช่ "เลื่อน" ต้องถึงที่ตั้งแต่เฟรมแรก
· 🔴🔴 **กล่องที่เลื่อนในตัวเองบนหน้า ก็อยู่ใต้กฎนี้ทุกข้อ** — ไม่ใช่แค่ปุ่มขึ้นบนสุดลงล่างสุดของทั้งหน้า
  ปุ่มในการ์ดที่สั่งให้กล่องเลื่อน (ปฏิทินที่เลื่อนดูทีละสัปดาห์ · รายการยาวในกล่อง) ต้องค่อย ๆ เลื่อนด้วย
  ใช้ตัวเลื่อนกล่องจากไฟล์กลางเดียวกัน (warfarin คือ `glideBox` ใน `lib/glideScroll.ts`) จังหวะจะเหมือนทั้งหน้า
  🚨 **กล่องที่ตั้งให้หยุดตรงแถว (`scroll-snap`) ต้องปิดตัวหยุดระหว่างเลื่อนแล้วคืนตอนจบ**
  ไม่งั้นเบราว์เซอร์ดึงกลับเข้าแถวทุกเฟรม กล่องสั่นอยู่กับที่ไม่ไปไหน
  🔴 **เคยพลาด 17 ก.ย. 2569** — ปุ่ม "กลับสัปดาห์นี้" ของปฏิทินนัดเจาะ warfarin กระโดดทันที
  พี่กันสั่งเอง *"อยากให้กดแล้วมันสไลด์มาถึงเอง ไม่เอาวาร์บ"*
  ต้นเหตุคือบรรทัดสารบัญความจำยังเขียนข้อสรุปผิดว่าเครื่องพี่กันเลื่อนนุ่มไม่ได้ (เรื่องเต็มใน `SCOLDING-LOG.md`)

### ⑪🔴 สีของปุ่มต้องอยู่ในไฟล์ CSS เท่านั้น ห้ามเขียนเป็นสไตล์ฝังในแท็ก

> พี่กันทักเอง 16 ก.ย. 2569 — *"ทำไมเอาเมาส์ไปชี้สีมันขึ้นนะ แต่มันยังจาง"*
> และก่อนหน้านั้น *"ตอนเอาเมาส์ไปชี้ มันควรเปลี่ยนสีเป็นตามธีมเว็บ"*

**สไตล์ฝังในแท็กชนะ `:hover` เสมอ** เขียนกฎ hover ไว้สวยแค่ไหนก็ไม่มีทางติด
ปุ่มจะดูเหมือนไม่ตอบสนอง ทั้งที่โค้ด CSS ถูกทุกบรรทัด — ไล่หาสาเหตุไม่เจอเพราะไม่มีอะไรผิด

🚨 **ความจางก็ต้องอยู่ใน CSS ด้วย** ไม่ใช่แค่สี
เขียนความทึบไว้ในแท็กแล้ว `:hover` จะปลุกให้ชัดไม่ได้ ปุ่มก็เปลี่ยนสีแต่ยังจางอยู่
ส่งสถานะออกมาเป็น `data-` แล้วให้ CSS ตัดสินทั้งหมด

```jsx
<button className="jumpbtn" data-show={show} data-awake={awake} />
```
```css
.jumpbtn                                   { opacity: 0 }
.jumpbtn[data-show="true"]                 { opacity: .32 }
.jumpbtn[data-show="true"][data-awake="true"] { opacity: 1 }
.jumpbtn[data-show="true"]:hover           { opacity: 1; background-color: ... }
```

🚨 **ใช้ `background-color` ไม่ใช่ `background`** — ในเว็บที่ใช้ Tailwind v4
กฎ `:hover` ที่เขียนด้วยตัวย่อ `background` ไม่ติด แต่ตัวเต็มติด
(เจอจริงในเว็บ warfarin 16 ก.ย. 2569 — ตรวจแล้วว่ากฎ match แต่สีไม่เปลี่ยน)

### ⑫🔴 เขียนกฎในหัวไฟล์แล้ว ไม่ได้แปลว่าทำแล้ว

ข้อ ⑧ (ต้องหายเมื่อมีหน้าต่างซ้อน) เคยถูกเขียนไว้ครบในคอมเมนต์หัวไฟล์ของเว็บ warfarin
**แต่ไม่มีโค้ดที่ทำจริงสักบรรทัด** อยู่แบบนั้นหลายวันโดยไม่มีใครรู้
เพราะคนอ่านโค้ดเห็นคอมเมนต์แล้วเชื่อว่าทำแล้ว

🔑 **วิธีทำข้อ ⑧ ที่ใช้ได้จริง** — ตั้งธงกลางไว้ที่ตัวล็อกการเลื่อน
ซึ่งของที่กางออกทุกชนิดเรียกอยู่แล้ว แล้วให้ปุ่มลอยจ้องธงนั้น
ของกางใหม่ที่เพิ่มทีหลังจะได้รับการดูแลเองโดยไม่ต้องจำ
· **ต้องนับจำนวน ไม่ใช่ตั้ง/ลบเป็นค่าเดียว** เพราะของกางซ้อนกันสองชั้นได้

# 6.22 📐 แถบเมนูซ้าย — กฎกลาง ใช้ทุกเว็บที่มีเมนูข้าง

> 🔴🔴 **ทั้งหมดนี้มาจากงานจริงวันที่ 16 ก.ย. 2569** — พี่กันทักเองสี่รอบในชั่วโมงเดียว
> *"มันมีขอบซ้ายขวาโคตรหนาทั้งเว็บเลย"* · *"แถบซ้ายต้องเปิดปิดได้ด้วยสิ"* ·
> *"ปกติ การย่อแถบซ้าย มันย่อหายหมดเลยไหมนะ"* · *"มันไม่เท่ากัน ที่มุม"*
> และสรุปด้วยประโยคที่ต้องจำ — **"ไม่ใช่ตาดี เธอทำผิดทุกรอบต่างหาก เรื่องมุมนี้"**

## ①🔴🔴🔴 มุมบนซ้าย — เส้นใต้แถบบนกับเส้นใต้หัวแถบเมนู ต้องอยู่ระดับเดียวกันเป๊ะ

**นี่คือข้อที่พลาดทุกรอบ ไม่ใช่รอบเดียว**

เส้นสองเส้นนี้มาชนกันที่มุมบนซ้ายของจอ ต่างกันแค่ 8 จุดก็เห็นเป็น**รอยหัก**ทันที
และมันอยู่ตรงมุมที่ตาคนกวาดผ่านเป็นจุดแรกของทุกหน้า

```
❌ ผิด — สองที่พิมพ์ตัวเลขของตัวเอง

   Sidebar.tsx  height: 64        ← ต่าง 8 จุด = รอยหักที่มุม

✅ ถูก — ประกาศที่เดียว ทั้งสองฝั่งอ่านจากตัวเดียวกัน
   AppShell.tsx  export const TOPBAR_H = 64;
   TopBar.tsx    height: TOPBAR_H
   Sidebar.tsx   height: TOPBAR_H   (หัวแถบ)
```

🚨 **กฎบังคับ: ห้ามพิมพ์ความสูงแถบบนเป็นตัวเลขเกินหนึ่งที่ในโปรเจกต์**
ประกาศเป็นค่ากลางตัวเดียว แล้วทุกที่อ้างตัวนั้น รวมถึงจุดที่เลื่อนหน้าหลบแถบบนด้วย

**วิธีตรวจ ทำทุกครั้งที่แตะโครงเว็บ**

```bash
grep -rn "height: 56\|height: 64\|h-14\|h-16" components/ app/ --include=*.tsx
```

เจอตัวเลขความสูงแถบมากกว่าหนึ่งที่ = ผิดทันที ไม่ต้องรอให้พี่กันเห็น

และ**ต้องซูมดูมุมบนซ้ายด้วยตาจริงก่อนส่งงานทุกครั้ง** — วัดด้วยโค้ดอย่างเดียวไม่พอ

```js
const h = document.querySelector('header').getBoundingClientRect().bottom;
const n = document.querySelector('nav > div:first-child').getBoundingClientRect().bottom;
console.log({ header: h, navHead: n, ตรงกัน: Math.abs(h - n) < 1 });
```

## ②🔴 เนื้อหาต้องเต็มความกว้างที่เหลือ ห้ามล็อกกลางจอ

เว็บของพี่กันทุกตัว (ME-DRP · ยาคืน · HCV · TB) **ไม่ล็อกความกว้าง** ใช้เต็มจอหมด

```
❌ maxWidth: 1500 + padding 0 40px   → จอ 1920 เหลือขอบว่างข้างละเกือบสองนิ้ว
✅ ไม่มี maxWidth + padding 0 20px    → ตารางกว้าง ๆ มีที่พอ ไม่ต้องเลื่อนซ้ายขวา
```

🔑 **ขอบซ้ายขวาที่หนาเกิน ไม่ได้แค่ดูโล่ง — มันไปบีบตารางจนล้นกรอบ**
ขอบข้างละ 40 = เสียที่ 80 จุด ซึ่งมากกว่าที่ตารางล้น (57 จุด) เสียอีก
ลดขอบอย่างเดียวก็หายล้นแล้ว โดยไม่ต้องแตะตารางเลย

🚨 **แต่ละหน้าห้ามล็อกความกว้างซ้อนอีกชั้น** — ตรวจด้วย

```bash
grep -rn "maxWidth: [0-9]" app/ --include=*.tsx
```

## ③🔴 ย่อแถบเมนู = ย่อเหลือแถบไอคอน ไม่ใช่ซ่อนหายทั้งแถบ

พี่กันถามเองว่า *"ปกติ การย่อแถบซ้าย มันย่อหายหมดเลยไหมนะ"* — **คำตอบคือไม่**

| แบบ | เกิดอะไร | ใช้เมื่อไหร่ |
|---|---|---|
| **ย่อเหลือไอคอน** (ถูก) | ยังกดสลับหน้าได้ทันทีโดยไม่ต้องกางคืน | เดสก์ท็อป — **ใช้แบบนี้เสมอ** |
| ซ่อนหายทั้งแถบ | ต้องกางคืนก่อนถึงจะไปหน้าอื่นได้ | มือถือเท่านั้น |

**ต้นแบบของเรา = เว็บ TB Dashboard** (`app/legacy/tb-monolith.jsx` บรรทัด ~727)
เว็บ HCV ก็ทำแบบเดียวกัน (`components/Sidebar.tsx`)

## ④ วิธีทำ — ยกไปวางได้เลย

**ค่าที่ใช้จริง**

| ของ | ค่า | ทำไม |
|---|---|---|
| กว้างตอนกาง | 240–260 | ชื่อเว็บกับป้ายนับต้องอยู่บรรทัดเดียวได้ |
| กว้างตอนย่อ | 56 | เท่ากับกล่องไอคอนหัวแถบพอดี |
| กล่องไอคอนแต่ละแถว | 36–44 (ตายตัว) | **หัวใจที่ทำให้ไอคอนไม่ขยับสักจุดตอนย่อ/กาง** |
| ปุ่มสลับ | วงกลม 23–24 ลอยที่ `right: -11, top: 20` | อยู่ที่เดิมทั้งสองสถานะ |
| จังหวะเปลี่ยน | `width .2s ease` | |

**🔑 เคล็ดที่สำคัญที่สุด — ตัวอักษรย่อด้วยการบีบความกว้าง ไม่ใช่ถอดออกจากหน้า**

```jsx
// ✅ ถูก — ไหลลื่นทั้งขาไปขากลับ
function fade(open, wide) {
  return {
    overflow: "hidden", whiteSpace: "nowrap",
    maxWidth: open ? wide : 0,
    opacity: open ? 1 : 0,
    transition: "max-width .2s ease, opacity .15s ease",
  };
}
<span style={fade(open, 130)}>{label}</span>

// ❌ ผิด — ของกระโดดเป็นจังหวะ ๆ ตอนย่อและตอนกาง
{open && <span>{label}</span>}
```

**โครงที่ถูก**

```jsx
<div style={{ position:"fixed", insetInlineStart:0, top:0, bottom:0,
              width: open ? 240 : 56, transition:"width .2s ease" }}>
  <nav style={{ width:"100%", height:"100%", overflow:"hidden",
                display:"flex", flexDirection:"column" }}>
    {/* หัวแถบ — สูงเท่า TOPBAR_H เป๊ะ (ข้อ ①) */}
    {/* รายการ — flex:1 + minHeight:0 + overflowY:auto  ← ห้ามลืม minHeight:0 */}
    {/* การ์ดล่าง — flex:"none" */}
  </nav>
  {/* ปุ่มสลับ อยู่นอก <nav> เพราะถ้าอยู่ข้างในแล้วย่อ ปุ่มจะหายไปด้วย */}
  <button style={{ position:"absolute", insetInlineEnd:-11, top:20 }} />
</div>
```

🚨🔴 **`minHeight: 0` ต้องคู่กับ `flex: 1` เสมอ**
ของที่ยืดตามพื้นที่ว่างจะไม่ยอมเล็กกว่าเนื้อหาข้างในโดยปริยาย
พอเมนูยาวกว่าจอ มันจึงไม่หดและ**ไม่เลื่อน** แต่ไปดันการ์ดล่างให้ทับเมนูแทน
เจอจริงบนจอสูง 633 จุด — เมนูตัวสุดท้ายโดนการ์ดบังหายไปทั้งรายการ
และ `overflowY` ที่ตั้งไว้ก็ไม่เคยได้ทำงานเลยสักครั้ง

**สิ่งที่ต้องมีครบ**

- ย่ออยู่ ทุกแถวต้องมี `title={label}` ไม่งั้นเหลือไอคอนเปล่าแล้วเดาไม่ออกว่าหน้าอะไร
- ป้ายนับ — กางเป็นตัวเลข · ย่อเป็นจุดที่มุมไอคอน (ยังบอกได้ว่ามีของรออยู่)
- จำสถานะไว้ใน `localStorage` แต่ **เริ่มที่กางเสมอ** แล้วค่อยอ่านค่าทีหลังใน effect
  (ฝั่งเซิร์ฟเวอร์ไม่มีที่เก็บของเบราว์เซอร์ เดาไปก่อนแล้วสองฝั่งจะวาดไม่ตรงกัน)
- เนื้อหาฝั่งขวาเลื่อนตามด้วย `marginInlineStart` + `transition` จังหวะเดียวกัน

# 6.23 🎚 แถบเลื่อน (scrollbar) — วาดเองทั้งเว็บ กฎกลาง ใช้ทุกเว็บ

> 🔑 **ต้นแบบคือเว็บ TB Dashboard** — พี่กันชมเองว่า *"ระบบสโควเราทำมาดีมาก"*
> และสั่งให้ยกไปใช้ทุกเว็บ (16 ก.ย. 2569)
> โค้ดพร้อมใช้ที่ `warfarin-dash/components/ui/OverlayScrollbar.tsx`

## ① ทำไมต้องวาดเอง ไม่ใช้ของเบราว์เซอร์แล้วแต่งสีเอา

| เหตุผล | ของเบราว์เซอร์ | ที่วาดเอง |
|---|---|---|
| ค่อย ๆ จาง | **ทำไม่ได้** WebKit ไม่ยอม transition สี `::-webkit-scrollbar-thumb` โผล่ปุ๊บหายปั๊บ | จางเข้าจางออกเนียน |
| กินที่ | **กินจริง** โผล่มาทีเนื้อหาข้าง ๆ ขยับทั้งแถบ | ลอยทับ ไม่เบียดใคร |
| ครอบคลุม | ต้องเขียน CSS ให้ทุกกล่องที่เลื่อนได้ | ตัวเดียวจับทุกกล่องอัตโนมัติ |

🚨 **หน้าใหม่ที่มีของให้เลื่อน ไม่ต้องทำอะไรเพิ่มเลย** ตัววาดจับให้เอง

## ② วิธีทำ — 3 ชิ้น

**ชิ้นที่ 1 — ซ่อนของเบราว์เซอร์ทั้งเว็บ (globals.css)**

```css
::-webkit-scrollbar { width: 0; height: 0; }
* { scrollbar-width: none; }

.ovthumb {
  position: fixed;
  border-radius: 4px;
  background: var(--สีอ่อนของธีม);
  opacity: 0;
  pointer-events: none;
  z-index: 99999;
  will-change: top, left, width, height, opacity;
}
.ovthumb:hover { background: var(--สีเข้มขึ้นหนึ่งขั้น); }
```

🔴 **ต้องถอด `scrollbar-gutter: stable` ที่ `html` ออกด้วย** ถ้าเคยใส่ไว้
มันจองที่ให้แถบที่ไม่มีอยู่แล้ว กลายเป็นขอบขาวเปล่า ๆ ข้างขวาตลอดเวลา

**ชิ้นที่ 2 — ตัววาด** (คัดลอก `OverlayScrollbar.tsx` ไปทั้งไฟล์)

**ชิ้นที่ 3 — วางไว้ในโครงของเว็บครั้งเดียว**

```jsx
<OverlayScrollbar />
```

## ③ ค่าที่ใช้จริง

| ของ | ค่า | ทำไม |
|---|---|---|
| หนา | 7px | บางพอไม่เกะกะ หนาพอจับได้ |
| สั้นสุด | 24px | สั้นกว่านี้เล็งลากยาก |
| ห่างจากขอบ | 2px | |
| โผล่ | `opacity .6s` | |
| หยุดเลื่อนแล้วรอ | 400ms | เร็วกว่านี้จะกะพริบตอนเลื่อนเป็นจังหวะ |
| จางหาย | `opacity 1.3s` | |
| ระยะ "เมาส์เข้าใกล้ขอบ" | 16px | |

## ④ 🚨 กับดักที่ต้องระวัง — ทุกข้อเจอมาแล้วจริง

**① 🔴🔴 เลื่อนทั้งหน้า ห้ามใช้กรอบของเอกสาร ต้องใช้กรอบของจอ**

**ของต้นแบบก็มีจุดนี้ ลอกมาทั้งดุ้นไม่ได้**

```js
// ❌ ผิด — ตัวเอกสารมีขอบบนติดลบทันทีที่เลื่อนลง (เลื่อน 9 จุด ขอบบนเป็น -9)
const r = el.getBoundingClientRect();
thumb.style.top = (r.top + at) + 'px';    // วัดได้จริง -8.8 = หลุดออกนอกจอ มองไม่เห็นเลย

// ✅ ถูก — แยกกรณีออกมา
const boxOf = (el) => {
  const root = el === document.documentElement || el === document.body;
  return root
    ? { top: 0, bottom: innerHeight, left: 0, right: innerWidth }
    : el.getBoundingClientRect();
};
```

**①ข 🔴 และต้องบีบตำแหน่งสุดท้ายให้อยู่ในจอเสมอ — คนละเรื่องกับข้อ ①**

กล่องที่ **ยาวหรือสูงเกินจอ** มีขอบอยู่นอกจอ แม้จะไม่ใช่การเลื่อนทั้งหน้าก็ตาม

```js
const clamp = (v, lo, hi) => Math.max(lo, Math.min(hi, v));

// แนวตั้ง
thumb.style.top = clamp(r.top + at, 0, innerHeight - len) + 'px';
// แนวนอน — ก้นกล่องอยู่นอกจอ แถบจะไปลอยทับกลางตารางแทนที่จะอยู่ก้นกล่อง
thumb.style.top = clamp(r.bottom - 9, 0, innerHeight - 9) + 'px';
```

เห็นจากภาพจริง — แถบแนวนอนไปพาดกลางตารางทับแถวที่ 4 ดูเหมือนเส้นขีดฆ่าข้อมูล

**② 🔴 ต้องดักเหตุการณ์เลื่อนแบบ capture**

```js
window.addEventListener('scroll', onScroll, true);   // ← true ห้ามลืม
```

เหตุการณ์เลื่อนของกล่องข้างใน **ไม่ลอยขึ้นมาถึงหน้าต่าง**
ไม่ใส่ `true` เมื่อไหร่ แถบจะทำงานเฉพาะตอนเลื่อนทั้งหน้า ส่วนกล่องข้างในเงียบสนิท

**③ ต้องสลับ `pointer-events` ตามสถานะ**

จางอยู่ = `none` ไม่งั้นมันกินการกดของสิ่งที่อยู่ข้างใต้ทั้งที่มองไม่เห็น
โผล่อยู่ = `auto` ไม่งั้นลากไม่ได้

**④ ต้องลากได้ ไม่ใช่แค่โชว์**

ไม่มีตัวลาก แถบจะเป็นแค่ของประดับ — คนเห็นแล้วพยายามลากแล้วไม่ขยับ จะงงหนักกว่าไม่มีแถบเลย

**⑤ เก็บกวาดต้องครบ**

ถอดตัวดักทุกตัว + `clearTimeout` ตัวจับเวลาจางด้วย
ไม่ล้างตัวจับเวลา มันจะไปสั่งของที่ถูกเก็บไปแล้ว

## ⑤ วิธีตรวจว่าทำถูกจริง

```js
// เลื่อนก่อน แล้วรันทันที
const [v] = document.querySelectorAll('.ovthumb');
const r = v.getBoundingClientRect();
console.log({
  อยู่ในจอ: r.top >= 0 && r.bottom <= innerHeight && r.right <= innerWidth,
  จางเป็น: getComputedStyle(v).opacity,     // ต้องค่อย ๆ ลดลง ไม่ใช่ 1 หรือ 0 ทันที
  ลากได้: getComputedStyle(v).pointerEvents, // ตอนโผล่ต้องเป็น auto
});
```

🚨 **ต้องเทสครบ 3 ที่** — เลื่อนทั้งหน้า · เลื่อนในแถบเมนูซ้าย · เลื่อนตารางแนวนอน
ทั้งสามใช้เส้นทางคนละเส้นในโค้ด ผ่านที่หนึ่งไม่ได้แปลว่าอีกสองที่ผ่าน

## ⑦🔴🔴 สี่ข้อที่พลาดมาแล้วจริง — ตรวจทุกครั้งที่แตะแถบเลื่อน

**เจ้าของงานเจอเองทั้งสี่ข้อ 21 ก.ย. 2569 ที่เว็บวอร์ฟาริน** หลังเพิ่งทำแถบแนวนอนเสร็จ

### ① แถบเสริมห้ามมีหน้าตาของตัวเอง

> *"จะทำให้มันเหมือนแนวนอนทำไม ตัวหลักคือแนวตั้งนี่"*

**แถบแนวตั้งคือตัวหลักของทุกเว็บ** มีอยู่ทุกหน้า · แถบแนวนอนเป็นของเสริมที่โผล่เฉพาะหน้าที่กว้างเกินจอ

ตอนทำแถบแนวนอนเพิ่ม อย่าตั้งสี ความหนา มุมมน หรือใส่เงาให้มันเอง
**ยกชุดของแถบแนวตั้งมาทั้งชุด** ของเสริมจะได้ไม่เด่นกว่าของหลัก

```css
/* ✅ ถูก — คลาสของแถบแนวนอนมีไว้ให้โค้ดแยกตัวเท่านั้น ไม่ต้องมีสไตล์ */
.ovthumb-h { }
```

⚠️ ข้อเดียวที่ต่างได้คือ **พฤติกรรม** ไม่ใช่หน้าตา — แนวนอนไม่จางหาย เพราะไม่มีใครเดาออกว่า
มีของซ่อนอยู่ทางขวา และล้อเมาส์เลื่อนแนวนอนไม่ได้ ต้องลากแถบอย่างเดียว

### ② แถบที่กำลังจาง ต้องยังเอาเมาส์ไปโดนได้

> *"ตอนที่มันกำลังจางลง ทำไมเราเอาเมาส์ไปโดนไม่ได้ มันก็ยังจางแล้วหาย
>  ซึ่งตามปกติ แถบเลื่อนนี้พอเมาส์ไปโดนมันควรกลับมาเข้มสิ"*

🚨 **ห้ามตัด `pointer-events` ตั้งแต่วินาทีที่เริ่มจาง** — ระหว่างไล่จางแถบยังมองเห็นอยู่
คนที่เห็นแล้วรีบเอาเมาส์ไปโดนจะโดนไม่ติด มันจางต่อจนหายไปต่อหน้าต่อตา

```js
t.style.opacity = "0";                       // เริ่มจาง
// ❌ t.style.pointerEvents = "none";        // ตัดตรงนี้ = โดนไม่ได้ตลอดช่วงที่ยังเห็น
t._k2 = setTimeout(() => {                   // ✅ รอจนจางหมดจริงก่อน
  if (t._drag || t._hov) return;
  t.style.pointerEvents = "none";
}, เวลาไล่จาง + 50);
```

🔑 **ตัวจับเวลาตัวที่สองต้องถูกเคลียร์ทุกครั้งที่แถบโผล่ใหม่** ไม่งั้นมันไปตัดทีหลังทั้งที่แถบเข้มอยู่

### ③ เมาส์เข้าใกล้ขอบ แถบต้องโผล่มาเอง — รวมหน้าที่เลื่อนทั้งหน้า

> *"หรือตอนนี้ที่มันล่องหนอยู่เพราะเราตั้งใจแบบนั้น พอเอาเมาส์ไปใกล้ ๆ ขอบเพจ มันควรจะแสดงขึ้นมาด้วยสิ"*

ตัวไล่หากล่องที่เลื่อนได้มักเขียนแบบ "ไล่จากตัวใต้เมาส์ขึ้นไปหาแม่ จนถึง `body` แล้วคืนค่าว่าง"
🚨 **แบบนั้นไม่เคยจับกรณีที่เลื่อนทั้งหน้าได้เลย** ซึ่งเป็นกรณีของเกือบทุกหน้าในเว็บ

```js
while (el && el !== document.body) { ...ถ้าเจอกล่องที่เลื่อนได้ก็คืนตัวนั้น... }
// ✅ ไม่เจอเลย = หน้านี้เลื่อนทั้งหน้า ตัวที่เลื่อนคือเอกสาร
const root = document.scrollingElement || document.documentElement;
if (root && root.scrollHeight > root.clientHeight + 1) return root;
return null;
```

🚨🔴 **และต้องวัดขอบจาก "กรอบจอ" ไม่ใช่กรอบของเอกสาร** เมื่อเป็นการเลื่อนทั้งหน้า
หน้าที่กว้างเกินจอ กรอบเอกสารจะกว้างกว่าจอ เทียบกับตำแหน่งเมาส์แล้วไม่มีวันเข้าเงื่อนไข

### ④ ตารางที่วาดทีละชุด ต้องจองความสูงของแถวที่ยังไม่วาด

**อาการ** — เลื่อนลงแล้วแถบ **หดลงเรื่อย ๆ** และบางจังหวะ **เลื่อนลงแต่แถบถอยขึ้น**

**ต้นเหตุ** — ตารางวาดแถวเพิ่มเมื่อเลื่อนถึง ความสูงของหน้าจึงงอกขึ้นระหว่างที่คนกำลังเลื่อน
แถบคิดสัดส่วนจากความสูงนั้นทุกครั้ง พอตัวหารโตขึ้น แถบก็หดและตำแหน่งขยับผิด

วัดจริงที่เว็บวอร์ฟาริน (ตาราง 419 แถว วาดทีละ 80)

| เลื่อนไป | ความสูงหน้า | แถบยาว | แถบอยู่ที่ |
|---|---|---|---|
| 900 | 2,661 | 125 | 195 |
| 1,500 | 5,180 | 125 | 325 |
| 2,500 | 5,180 | **64** | **278 (ถอยขึ้น)** |
| 6,000 | 7,616 | **44** | 455 |

**วิธีแก้ — ใส่แถวจองที่ต่อท้าย สูงเท่ากับจำนวนแถวที่เหลือคูณความสูงเฉลี่ยของแถวจริง**

```jsx
<tr ref={moreRef} aria-hidden="true">      {/* แถวตรวจจับ สูง 1 */}
  <td colSpan={n} style={{ height: 1, padding: 0, border: 0 }} />
</tr>
<tr aria-hidden="true">                     {/* แถวจองที่ */}
  <td colSpan={n} style={{ height: Math.round(avgH * (ทั้งหมด - ที่วาดแล้ว)), padding: 0, border: 0 }} />
</tr>
```

🚨🔴 **แถวจองที่ต้องอยู่ "หลัง" แถวตรวจจับ ห้ามรวมเป็นแถวเดียวกัน**
รวมกันเมื่อไหร่ แถวตรวจจับจะสูงจนค้างอยู่ในสายตาตลอด แล้ววาดรวดเดียวหมดทั้งตาราง

🔑 **ความสูงเฉลี่ยต้องวัดจากของจริง** — ขอบบนแถวแรกถึงขอบล่างแถวสุดท้ายที่วาดแล้ว หารจำนวนแถว
ห้ามวัดความสูงของกล่องทั้งก้อน เพราะกล่องรวมแถวจองที่เข้าไปด้วย กลายเป็นวัดตัวเอง

ผลหลังแก้ — ความสูงหน้าคงที่ 12,589 ถึง 13,055 (ขยับ 3.7% แทนที่จะเป็น 186%)
แถบยาว **26 คงที่ทุกช่วง** ตำแหน่งขยับลงอย่างเดียว 41 → 69 → 111 → 177 → 265 → 398

# 6.24 🪟 หน้าต่างซ้อน (popup) — กฎกลาง ใช้ทุกเว็บ

> 🔴 มาจากบั๊กจริงที่เจ้าของงานเจอเอง **16 ก.ย. 2569** สามเรื่องรวด
> *"เรากดเปิดเลือกเภสัชกร แล้วเรากดปิดมัน แต่เจ้าแถบเลื่อนมันปิดไม่ทัน มันต้องทันสิ"*
> *"เรากดเลือกไปแล้วแต่ดันไปกดที่ว่าง แล้ว popup มันหายเลย อันนี้ไม่ควรหายสิ"*
> *"มันก็ยังปิดช้า ประมาณเสี้ยววิ"*
>
> **ที่อยู่โค้ดกลาง** `warfarin-dash/lib/popup.ts` — คัดลอกไปวางได้ทั้งไฟล์

## ①🔴🔴 popup มีสองชนิด ปิดคนละแบบ ห้ามสลับกัน

| | **เมนูเลือกค่า** | **แผงที่มีงานค้าง** |
|---|---|---|
| ตัวอย่าง | ดรอปดาวน์ · ปฏิทิน · วงล้อเลือกค่า | ตัวคิดคะแนน · แผงจัดการรายชื่อ · ฟอร์มในหน้าต่างซ้อน |
| ข้างในมีอะไร | ไม่มีอะไรค้าง กดพลาดก็เปิดใหม่ | ติ๊กไปหลายข้อ · พิมพ์ค้างไว้ครึ่งทาง |
| **กดข้างนอก** | ✅ ปิดได้ | 🔴 **ห้ามปิด** |
| **ปุ่ม Esc** | ✅ ต้องปิดได้ | ✅ ต้องปิดได้ |
| **ปุ่มปิดในตัว** | ไม่จำเป็น | ✅ ต้องมี |
| **ล็อกฉากหลังไม่ให้เลื่อน** | ✅ ต้องมี | ✅ ต้องมี |

🚨 **เกณฑ์ตัดสินง่าย ๆ — "ถ้าเผลอกดที่ว่างข้าง ๆ แล้วเสียงานไหม"**
เสีย = ห้ามปิด · ไม่เสีย = ปิดได้

🔑 **กรณีลูกผสม** — แผงที่ปกติไม่มีอะไรค้าง แต่บางจังหวะมี (เช่นแผงรายชื่อที่มีช่องเพิ่มชื่อ)
ให้ปิดได้ตามปกติ **แต่พอมีข้อความค้างในช่องเมื่อไหร่ ให้หยุดปิด**

```js
const onDoc = (e) => {
  if (adding.trim()) return;          // ← มีของค้าง ห้ามปิด
  if (box && !box.contains(e.target)) close();
};
```

## ② 🚨 ปุ่ม Esc ต้องปิดได้ทุกตัว ไม่มีข้อยกเว้น

คนที่ใช้แป้นพิมพ์อย่างเดียวต้องมีทางออกจากหน้าต่างที่เปิดค้าง

```js
// ดักที่หน้าต่างเบราว์เซอร์ ไม่ใช่ที่ตัวกล่อง
// เพราะตอนเปิดเมนู โฟกัสอาจอยู่ที่ปุ่มข้างนอก ไม่ได้อยู่ในกล่อง
useEffect(() => {
  if (!open) return;
  const onKey = (e) => { if (e.key === 'Escape') { e.stopPropagation(); close(); } };
  window.addEventListener('keydown', onKey);
  return () => window.removeEventListener('keydown', onKey);
}, [open, close]);
```

## ③ กดข้างนอก — ดักตอน **กดลง** ไม่ใช่ตอนปล่อย

```js
document.addEventListener('mousedown', onDown);   // ✅
document.addEventListener('click', onDown);       // ⚠️ ลากเลือกข้อความออกมาข้างนอกแล้วปิดตาม
```

## ④ 🔴 ของลอยที่เกาะกับ popup ต้องหายพร้อมกัน — ในเฟรมเดียว

แถบเลื่อนลอย (ข้อ 6.23) เกาะอยู่กับกล่องข้างใน popup
พอ popup ปิด กล่องถูกถอดออกจากหน้า **โดยไม่มีเหตุการณ์เลื่อนใด ๆ เกิดขึ้น**
ของลอยจึงค้างอยู่กลางหน้าเว็บ จนกว่าจะมีคนไปเลื่อนอะไรสักอย่าง

**วิธีที่ถูก — ฟังตอนของถูกถอดออกจากหน้า**

```js
const gone = new MutationObserver(() => {
  for (const t of thumbs) if (t._el && !t._el.isConnected) hideNow(t);
});
gone.observe(document.body, { childList: true, subtree: true });
```

| วิธี | ผลวัดจริง |
|---|---|
| ตัวจับเวลาทุก 150 ms | 🔴 เจ้าของงานเห็นว่าช้า — *"ยังปิดช้า ประมาณเสี้ยววิ"* |
| วนตรวจทุกเฟรม (rAF) | ⚠️ ทันตา แต่วนตลอดเวลาโดยไม่จำเป็น |
| **ฟังการเปลี่ยนแปลงของหน้า** | ✅ **วัดได้ 16 ms = หนึ่งเฟรมพอดี** และไม่วนเปล่า |

🚨 **ห้ามใช้ตัวจับเวลากับของที่ต้องหายพร้อมกัน** — ทุกค่าที่ตั้ง ตาคนจับได้หมด

## ⑤ 🔴 ของที่คำนวณตำแหน่งแล้วหลุดจอ = ซ่อน ห้ามบีบกลับ

```js
// ❌ ผิด — พอกล่องเลื่อนพ้นขอบบน ค่าติดลบถูกบีบเป็น 0
//         ของไปกองเป็นเส้นพาดขอบบนจอ ดูเหมือนเว็บพัง
top = clamp(raw, 0, innerHeight - len);

// ✅ ถูก — อยู่นอกจอก็หายไปเลย
if (top + len < 0 || top > innerHeight) { hide(); return; }
```

# 6.25 📅 ของที่กางออกมา ต้องกดถึงทุกปุ่ม

> พี่กันเคาะ **16 กันยายน 2569** หลังแคลร์เสนอ — *"ถ้ามันทำให้ทุกเว็บดีได้ ก็เอา"*
> 🔑 ข้อนี้เป็น **concept** ไม่ใช่หน้าตา · หน้าตาแต่ละเว็บต่างกันได้ตามใจ
> แต่ทุกเว็บต้องได้ผลลัพธ์เดียวกันคือ **กางแล้วกดได้ทุกปุ่ม**

## ①🔴 ไม่มีที่ข้างล่าง ต้องพลิกขึ้นข้างบน

**นี่ไม่ใช่เรื่องสวยไม่สวย — มันคือกดไม่ได้**
เพราะกฎ 6.24 สั่งว่าตอนเมนูกางอยู่ **ฉากหลังห้ามเลื่อน**
พอเลื่อนไม่ได้ ส่วนที่ล้นออกนอกจอคือส่วนที่ **กดไม่ถึงตลอดกาล**

วัดจริงตอนเทสหน้าลงทะเบียนผู้ป่วย warfarin — ช่องวันเกิดอยู่กลางหน้า ปฏิทินกางลงล่าง

| | ค่าที่วัดได้ |
|---|---|
| ขอบล่างปฏิทิน | 691 |
| ความสูงจอ | 633 |
| วันที่ 28 · 29 · 30 | อยู่ที่ 678 — **คนเกิดวันพวกนั้นลงทะเบียนวันเกิดไม่ได้เลย** |

**สิ่งที่ต้องทำ** — วัดที่ว่างรอบช่องก่อนวาด แล้วเลือกข้างเอง
ข้างล่างไม่พอและข้างบนกว้างกว่า = พลิกขึ้น · สองข้างไม่พอทั้งคู่ = ให้กล่องเลื่อนในตัวมันเอง

```tsx
// วัดหลังวาดแต่ก่อนจอติด — ใช้ layout effect ไม่ใช่ effect ธรรมดา ไม่งั้นเห็นมันกระพริบย้ายที่
const r = wrapRef.current.getBoundingClientRect();
const below = window.innerHeight - r.bottom - 12;
const above = r.top - 12;
const up = panelRef.current.scrollHeight > below && above > below;
// วัดใหม่ทุกครั้งที่เนื้อในเปลี่ยนความสูง
```

🚨 **ต่างจากกฎ 6.24 ⑤ ตรงไหน** — ข้อนั้นคือของลอยที่เกาะกับ popup (แถบเลื่อน) หลุดจอแล้ว **ให้ซ่อน**
ข้อนี้คือตัว popup เอง **ซ่อนไม่ได้ ต้องพลิก** เพราะซ่อนแปลว่าเปิดไม่ขึ้น

## ②🔴 ช่องที่ค่าอยู่ไกล ห้ามมีแต่ปุ่มเดินทีละก้าว

ปฏิทินเดิมมีแต่ `‹ ›` เดินทีละเดือน ปีกับเดือนเป็นข้อความกดไม่ได้
**คนไข้อายุ 70 ปี = กดปุ่มเดือนก่อนหน้า 840 ครั้ง** ถึงจะถึงปีเกิด — ใช้งานจริงไม่ได้เลย

**สิ่งที่ต้องทำ** — ค่าที่อยู่ห่างจากค่าเริ่มต้นมาก ต้องมีทางกระโดดถึงตรง ๆ
ปฏิทิน = กดที่ปีแล้วเลือกปีได้เลย · รายการยาว = ช่องค้นหา · ตัวเลขช่วงกว้าง = พิมพ์ได้

🔑 **ท่าตรวจ** — ถามว่า *"ค่าที่อยู่ไกลที่สุดที่คนใช้จริงต้องเลือก ต้องกดกี่ครั้ง"*
เกิน 5-6 ครั้ง = ต้องมีทางลัด

## ③ วิธีตรวจว่าทำถูกจริง

```js
// ของที่กางแล้วต้องอยู่ในจอครบ และทุกปุ่มต้องกดถึง
const d = document.querySelector('[role="dialog"]');
const r = d.getBoundingClientRect();
console.log('ล้นล่าง', Math.round(r.bottom - innerHeight), 'ล้นบน', Math.round(-r.top)); // ต้อง ≤ 0

  const q = b.getBoundingClientRect();
  return q.bottom > innerHeight || q.top < 0;

```

# 6.26 🦴 เปลี่ยนหน้าแล้วต้องอยู่บนสุดเสมอ — กระดูกของ UX/UI ใช้ทุกเว็บ ทุกฝั่งจอ

> **พี่กันสั่งเขียนลงสกิล 17 ก.ย. 2569** — *"เขียนลงสกิลเลย มันสำคัญมากๆ เเละนี่คือกระดูกของ UXUI"*
>
> ต้นเรื่องรอบล่าสุด (warfarin) — *"เจอ bug อีกเเล้ววว เจอตลอด เรากดเลือกที่ผู้ป่วยตรงนี้ พอกดเข้าไป หน้าเพจมันไม่บนสุด"*
> ครั้งแรกที่เจอ (ย้ายมาจาก 6.13 ⑤) — *"เราเลื่อนขึ้นลงในหน้าบันทึก ประวัติ แล้วพอเปิดหน้าอื่นมันค้างที่เดิม"*

🔴🔴🔴 **กดเข้าหน้าไหนก็ตาม หน้านั้นต้องเริ่มที่บนสุด** — ไม่มีข้อยกเว้น ไม่ว่าหน้าเดิมจะเลื่อนลงไปแค่ไหน

## ②🔴 วิธีทำ — ใส่ที่โครงเว็บจุดเดียว ห้ามไปใส่ทีละหน้า

ใส่ทีละหน้า = หน้าที่ทำทีหลังลืมแน่นอน · ใส่ที่ตัวที่ครอบทุกหน้า = หน้าใหม่ได้เองโดยไม่ต้องจำ

| ชนิดเว็บ | ใส่ที่ไหน |
|---|---|
| หลายหน้า (Next.js App Router) | ส่วนประกอบโครงเว็บที่ครอบทุกหน้า ฟังการเปลี่ยน `pathname` |
| หน้าเดียวสลับด้วย state (แบบ HCV) | ตัวเก็บสถานะกลาง ตอนหน้า (view) หรือรายการที่เปิด (id) เปลี่ยน |
| เนื้อหาเลื่อนในกล่อง ไม่ใช่ทั้งหน้าต่าง | ตั้ง `scrollTop = 0` ของกล่องนั้น ไม่ใช่ของ `window` |

```tsx
// components/shell/AppShell.tsx — โครงเว็บที่ครอบทุกหน้า (ของจริงใน warfarin-dash)
const pathname = usePathname() || "/";
// useLayoutEffect = ขึ้นไปก่อนจอวาด ไม่งั้นเห็นหน้าใหม่โผล่กลางทางแวบหนึ่ง
useLayoutEffect(() => {
  placeTop();
}, [pathname]);

// lib/glideScroll.ts
export function placeTop() {
  if (typeof window === "undefined") return;
  stopGlide();            // 🔴 หยุดการเลื่อนนุ่มที่ค้างอยู่ก่อน ไม่งั้นหน้าใหม่ถูกลากลงต่อ
  window.scrollTo(0, 0);  // 🔴 "วาง" ทันที ไม่ใช่ค่อย ๆ เลื่อน
}
```

```tsx
// เว็บหน้าเดียวแบบ HCV (components/HcvProvider.tsx)
useEffect(() => {
  document.getElementById("hcv-scroll")?.scrollTo({ top: 0 });
}, [state.view, state.currentId]);
```

### กติกาประกอบ

- 🔴 **เปิดหน้าใหม่ = "วาง" ไม่ใช่ "เลื่อน"** — ต้องอยู่บนสุดตั้งแต่เฟรมแรก
  ไม่ขัดกับ 6.21 ที่ห้ามวาร์ป เพราะข้อนั้นคือ **ปุ่มที่คนกดเพื่อเลื่อน** ส่วนข้อนี้คือจุดเริ่มของหน้า
  ค่อย ๆ เลื่อนขึ้นตอนเปิดหน้า = เห็นหน้าใหม่โผล่มากลางทางแล้ววิ่งหนีขึ้นไปทุกครั้ง
- ✅ **ย้อนกลับด้วยปุ่มของเบราว์เซอร์ ไม่ต้องเขียนอะไรเพิ่ม** — วัดแล้วเบราว์เซอร์คืนแถวที่เคยเลื่อนไว้ให้เอง หลังจุดรีเซ็ตนี้
- ✅ **เปลี่ยนแค่ค่าในที่อยู่ของหน้าเดิม** (กดชิปกรอง · เปลี่ยนหน้าที่ 2 ของตาราง) ไม่ใช่การเปลี่ยนหน้า ไม่ต้องขึ้นบนสุด
  ตรงนั้นใช้กติกาของหน้านั้นเอง เช่นเลื่อนนุ่มกลับไปหัวตาราง

## ③🔴 วิธีเทส — ต้องเทสบนจอเตี้ยเท่าจอเจ้าของงาน

🚨 **ห้ามเทสแค่จอใหญ่** — จอสูงบังเอิญผ่านทุกกรณี แล้วรายงานว่าใช้ได้ทั้งที่จอพี่กันพัง
🚨 **เทสใน Chrome ของพี่กัน** ตามสกิล `testing-proof` 5.6 ไม่ใช่แผงเบราว์เซอร์ของแอป

```js
// วางในหน้ารายการที่มีแถวให้กด (ตัวอย่างนี้คือทะเบียนผู้ป่วย) — ต้องได้ after: 0 ทุกบรรทัด
const sleep = (ms) => new Promise(r => setTimeout(r, ms));
const out = [];
for (const start of [40, 100, 250, 600]) {
  if (location.pathname !== '/patients') { history.back(); await sleep(1500); }
  window.scrollTo(0, start); await sleep(300);
  document.querySelectorAll('tbody tr[aria-label]')[2].click();   // กดเหมือนคนกด
  await sleep(1500);
  out.push({ start, after: Math.round(scrollY) });
}
out;
```

- [ ] จอเตี้ย (สูงราว 600 จุด) เลื่อนลง 40 · 100 · 250 · 600 แล้วกดเข้าหน้าใหม่ → **0 ทุกครั้ง**
- [ ] กดย้อนกลับ → หน้าเดิมกลับไปแถวที่เคยเลื่อนไว้
- [ ] กดปุ่มลงล่างสุด แล้วรีบกดเปลี่ยนหน้าระหว่างที่ยังเลื่อนอยู่ → หน้าใหม่ยังอยู่บนสุด
- [ ] ทำครบทั้งฝั่งคอมและฝั่งมือถือ

## 🔴🔴🔴 เครื่องหมายที่ห้ามใช้ในข้อความบนจอ (พี่กันสั่ง 21 ก.ย. 2569)

> *"ไปตั้งกฎหลักของเว็บ ภาษาไทย ห้ามภาษาพูด ต้องทางการทั้งหมด
>  และไม่มี . - หรือเครื่องหมายแปลก ๆ ที่เว็บเขาไม่ใช้"*

| ❌ ห้ามใช้บนจอ | ✅ ใช้แทน |
|---|---|
| **·** จุดคั่นกลางบรรทัด | **แยกเป็นคนละบรรทัด** หรือใช้คำเชื่อม เช่น และ หรือ แต่ |
| **—** ขีดยาวคั่นความ | แยกบรรทัด หรือใช้คำว่า คือ |
| **?** เครื่องหมายคำถาม | ตัดทิ้ง ประโยคคำถามไทยไม่ต้องมี |
| **…** จุดไข่ปลา | ตัดทิ้ง หรือเขียนเป็นคำ เช่น กำลังบันทึก |
| **/** ขีดเฉียงคั่นคำไทย **ที่แปลว่า หรือ** เช่น ชาย/หญิง | ใช้คำว่า หรือ |

🔑 **ที่ใช้ได้ปกติ** — จุลภาค (,) วงเล็บ ( ) และเครื่องหมายในหน่วยวัดภาษาอังกฤษ เช่น mg/week
🔑 **`/` ที่แปลว่า ต่อ ใช้ได้ แม้เป็นคำไทย** เช่น หัวคอลัมน์ `ครั้ง/วัน` เป็นหน่วยนับแบบเดียวกับ mg/week ห้ามแก้
   แคลร์เคยนับ `ครั้ง/วัน` เป็นข้อผิดในรายงานตรวจหน้าวิธีบริหารยา เจ้าของงานแย้ง 24 ก.ย. 2569 *"ผิดเหรอ ไม่นะ"*

🔴 **กฎนี้คุมเฉพาะข้อความที่คนอ่านบนจอ** — หัวข้อ ปุ่ม ป้าย ช่องกรอก ข้อความเตือน หน้าต่างถามย้ำ

## 🔴🔴🔴 กล่องที่เลื่อนได้ กับการไหลของการเลื่อนไปกล่องข้างหลัง (21 ก.ย. 2569)

เจอทั้งสองด้านในวันเดียวกัน เพราะใส่ผิดที่ทั้งคู่

| อาการที่เจ้าของงานเจอ | ต้นเหตุ |
|---|---|
| *"ชื่อหมอตรงตั้งค่า พอเอาเมาส์ไปชี้แล้ว มันเลื่อนขึ้นลงไม่ได้"* | ใส่ `overscroll-behavior: contain` ในกล่องที่**ไม่มีอะไรให้เลื่อนในตัวเอง** การเลื่อนจึงถูกกลืนหายไปเฉย ๆ ทั้งหน้า |
| *"เอาเมาส์ไปไว้ที่แถบซ้าย แต่เราสกรอลแล้วมันไปเลื่อนแถบขวา"* | **ไม่ได้ใส่** ในกล่องที่มีพื้นที่เลื่อนของตัวเอง พอเลื่อนจนสุด เบราว์เซอร์ส่งต่อให้หน้าข้างหลังอัตโนมัติ |

### กฎที่ใช้ตัดสิน

> **กล่องนั้นมีพื้นที่เลื่อนของตัวเองจริงหรือเปล่า**

| กล่องแบบไหน | ทำยังไง |
|---|---|
| แถบเมนูตรึง · แผงที่กางออก · กล่องในการ์ดที่จำกัดความสูง | ✅ ใส่ `overscroll-behavior: contain` |
| กล่องในหน้าเพจปกติที่ความสูงยืดตามเนื้อหา | ❌ ห้ามใส่ ปล่อยให้ล้อเมาส์เลื่อนทั้งหน้าตามปกติ |

🔑 **ตัวชี้ขาดคือมี `overflow-y: auto` พร้อมความสูงที่จำกัดไว้จริงไหม**
มีแค่ `overflow-y` แต่ความสูงยืดได้ = ไม่มีอะไรให้เลื่อน = ห้ามใส่

🚨 **ตรวจด้วยมือทุกครั้ง** เอาเมาส์ไปชี้ในกล่องแล้วหมุนล้อ ต้องได้ผลตามนี้
เลื่อนในกล่องจนสุดแล้วหน้าหลังต้องไม่ขยับ · และถ้ากล่องไม่มีอะไรให้เลื่อน หน้าหลังต้องเลื่อนได้ตามปกติ

# 📏 ปุ่มปรับความสูงแถวของตาราง (เจ้าของงานสั่งตั้งเป็นสกิล 21 ก.ย. 2569)

> ต้นฉบับอยู่ที่เว็บมูลค่ายาคืน หน้าประวัติ · เจ้าของงานสั่งให้ยกไปทุกเว็บที่มีตารางยาว
> *"ความสูง 43 34 30 เรารู้ละ เอาปุ่มเลือกขนาดได้ใส่ไปเลย"* (10 ก.ย. 2569)
> *"ขอปุ่มปรับขนาดแถว เหมือนเว็บยาคืนด้วย"* (21 ก.ย. 2569)

## ① สามระดับ ตัวเลขนี้เจ้าของงานเคาะแล้ว ห้ามตั้งเอง

| ระดับ | คลาส | แถวสูงจริง | บอกผู้ใช้ว่า |
|---|---|---|---|
| โปร่ง (ค่าตั้งต้น) | `rh-roomy` | 43 จุด | อ่านสบายที่สุด |
| แน่น | `rh-tight` | 34 จุด | เห็นเพิ่มราว 7 แถว |
| แน่นมาก | `rh-dense` | 30 จุด | ตัวอักษรเล็กลง เห็นเพิ่มราว 9 แถว |

## ② 🔴 บีบ 3 อย่างพร้อมกัน ไม่ใช่แค่ระยะขอบ

ทำแค่ระยะขอบจะไม่มีวันถึงตัวเลขข้างบน เพราะ**ของที่สูงที่สุดในแถวเป็นตัวกำหนดความสูงจริง**

1. **ระยะบนล่างของช่อง** 6 → 4 → 2 จุด
2. **ปุ่มในแถว** ต้องเตี้ยลงตามทุกระดับ — ปุ่มคือตัวกำหนดความสูงแถว ไม่ใช่ตัวหนังสือ
3. **ตัวอักษร** เล็กลงเฉพาะระดับแน่นมาก

```css
.rh-roomy .tbl tbody td { padding-top: 6px; padding-bottom: 6px }
.rh-tight .tbl tbody td { padding-top: 4px; padding-bottom: 4px }
.rh-dense .tbl tbody td { padding-top: 2px; padding-bottom: 2px; font-size: 13px }
/* ปุ่มในแถว — ต้องมี !important เพราะปุ่มมักเขียนสไตล์ฝังในแท็ก */
.rh-tight .tbl tbody .rh-btn { padding-top: 3px !important; font-size: 11px !important }
.rh-dense .tbl tbody .rh-btn { padding-top: 1px !important; font-size: 11px !important }
```

## ③ 🚨🔴 ตารางที่เขียนสไตล์ฝังในแท็ก ต้องใส่ `!important` ทุกบรรทัด

**พลาดมาแล้ว 21 ก.ย. 2569 ที่หน้าคลังยาของเว็บยาคืน** — เขียนกฎถูกทุกตัว กดปุ่มแล้วแถวไม่ขยับเลย
เพราะช่องตารางหน้านั้นเขียน `padding:9px 10px` ฝังในแท็ก ซึ่ง**ชนะกฎ CSS เสมอ**

วัดได้จริง: ก่อนแก้ 49/45/41 จุด · หลังใส่ `!important` 43/35/27 จุด

🔑 **วิธีจับ** — ไม่ใช่ดูว่าเขียนกฎถูกไหม แต่วัดความสูงแถวจริงในเบราว์เซอร์ทั้งสามระดับ

## ④ คลาสไปเกาะที่ `<html>` ไม่ใช่ที่ตาราง

ตั้งครั้งเดียวมีผลกับตารางทุกหน้าของเว็บ หน้าใหม่ที่ทำทีหลังได้ฟรีโดยไม่ต้องส่งค่าไปให้แต่ละหน้า
🚨 **ต้องถอดคลาสเก่าออกก่อนใส่ตัวใหม่เสมอ** ไม่งั้นซ้อนกันแล้วอันที่เขียนทีหลังใน CSS ชนะ

## ⑤ จำระดับที่เลือกไว้ถาวร

เก็บในที่เก็บถาวรของเบราว์เซอร์ ไม่ใช่ที่เก็บของหน้าต่าง — คนที่ชอบแถวแน่นจะได้ไม่ต้องกดใหม่ทุกวัน
🚨 เริ่มที่ **โปร่ง** เสมอตอนวาดครั้งแรก แล้วค่อยอ่านค่าที่จำไว้ทีหลัง
(ฝั่งเซิร์ฟเวอร์ไม่มีที่เก็บของเบราว์เซอร์ เดาไปก่อนแล้วสองฝั่งจะวาดไม่ตรงกัน)

ตาอ่านได้ทันทีว่าหมายถึงแถวห่างแค่ไหน ไม่ต้องแปลจากคำ

🚨 **ต้องมี `title` กับ `aria-label` เสมอ** เขียนให้ครบว่า *"แถวสูง 34 จุด เห็นเพิ่มราว 7 แถว"*
🚨 **สีตอนเอาเมาส์ชี้ต้องทำตามสกิล `button-feedback`** — ตัวที่เลือกอยู่เข้มขึ้นนิดเดียว
   ตัวที่ยังไม่เลือกเปลี่ยนเป็นสีจางของธีม ไม่ใช่เทาเข้มขึ้น

## ⑦ วางที่ไหน

วางข้าง**ปุ่มหลักของหน้านั้น** (ปุ่มเพิ่ม · ปุ่มส่งออก) ไม่ใช่ในแถบค้นหาปนกับชิปตัวกรอง

# 📐 ตารางกว้างเกินจอ — จอเล็กเลื่อนได้ จอใหญ่เต็มจอ (เจ้าของงานสั่งตั้งเป็นสกิล 22 ก.ย. 2569)

> ต้นฉบับอยู่ที่เว็บคลินิก warfarin หน้าคลังยา 15 คอลัมน์ 419 แถว
> *"ที่เราให้เธอต้องเลื่อนแถบซ้ายขวา เหตุผลเดียวคือที่มันไม่พอ และจอเราเล็ก
>  ดังนั้นถ้าเราใช้จอ 1080 2k 4k มันก็ควรจะดูตารางได้เต็มจอ แม้จะเปิดแถบเมนู"*

🔑 **หัวใจของข้อนี้** — การเลื่อนซ้ายขวาไม่ใช่สิ่งที่ต้องการ มันคือการยอมรับว่าจอไม่พอ
เว็บจึงต้องเลื่อนเฉพาะตอนที่จำเป็นจริง ไม่ใช่เลื่อนตลอดเพราะตั้งความกว้างคงที่ไว้

## ① ความกว้างของหน้ามีสี่ชั้น แก้ชั้นเดียวไม่ได้

| ชั้น | กว้างเท่าไหร่ | ถ้าทำผิดจะเป็นยังไง |
|---|---|---|
| ① โครงหน้าในตัวครอบแอป | ยืดตามเนื้อหา (`min-width: fit-content`) | ถอดออกแล้วแถบบนสั้นกว่าตาราง เลื่อนขวาไปจะเห็นตารางโผล่ข้างแถบเหมือนเว็บพัง |
| ② การ์ดที่ครอบตาราง | **ค่าที่มากกว่า** ระหว่างพื้นที่ที่เหลือจริงกับความกว้างขั้นต่ำที่ตารางต้องการ | ใช้ `100%` แล้วจอเล็กจะบีบคอลัมน์จนคำขาด · ใช้ค่าคงที่แล้วจอใหญ่จะเหลือที่ว่างทิ้งเปล่า |
| ③ แถบเครื่องมือที่ตรึงไว้ | **ค่าที่น้อยกว่า** ระหว่างความกว้างการ์ดกับพื้นที่ที่ตามองเห็น | คิดจากจออย่างเดียว ปุ่มยื่นเกินการ์ด · คิดจากการ์ดอย่างเดียว ปุ่มหลุดออกนอกจอ |
| ④ ตาราง | เต็มการ์ด | — |

🚨🔴 **สองชั้นกลางใช้ทิศทางตรงข้ามกัน** การ์ดเอาค่ามากกว่า แถบเอาค่าน้อยกว่า
จำสลับเมื่อไหร่พังทันทีทั้งสองทาง เคยพลาดมาแล้วทั้งคู่ในวันเดียว

## ② สูตรของการ์ด

```css
width: max(<ความกว้างขั้นต่ำที่ตารางต้องการ>px, calc(100vw - var(--nav-w) - <ระยะขอบหน้าสองข้าง>px));
min-width: 0;
```

| สภาพ | ผลที่ได้ |
|---|---|
| พื้นที่เหลือ **มากกว่า** ขั้นต่ำ เช่นจอ 1080 2K 4K แม้เปิดแถบเมนู | การ์ดเต็มพื้นที่ ไม่มีแถบเลื่อน |
| พื้นที่เหลือ **น้อยกว่า** ขั้นต่ำ เช่นจอ 1366 ตอนเปิดแถบเมนู | การ์ดหยุดที่ขั้นต่ำ แล้วเลื่อนซ้ายขวาแทน คอลัมน์ไม่ถูกบีบ |

🚨 **ต้องอ่าน `--nav-w` ไม่ใช่ฝังความกว้างแถบเมนูเป็นตัวเลข**
ฝังตัวเลขแล้วการ์ดจะไม่รู้ว่าแถบเมนูกางอยู่หรือย่ออยู่ จอใหญ่แค่ไหนก็ล้นเท่าเดิมตลอด

## ③ 🔴🔴 ค่าขั้นต่ำต้องเอาระดับแถวที่ตารางกว้างที่สุด ไม่ใช่ระดับที่แถวสูงที่สุด

**กับดักที่เสียเวลาไปหนึ่งรอบเต็ม** — ระดับที่แถวเตี้ยกว่ากลับใช้คอลัมน์ **กว้างกว่า**
เพราะปุ่มท้ายแถวเล็กลงตามระดับ แล้วที่ว่างที่ได้คืนถูกยกให้คอลัมน์อื่น

ตัวอย่างจริงจากหน้าคลังยา

```
โปร่ง    คอลัมน์ข้อมูล 1107 + ปุ่มท้ายแถว 110 = ตาราง 1217
แน่น     คอลัมน์ข้อมูล 1130 + ปุ่มท้ายแถว 102 = ตาราง 1232   ← กว้างกว่า
แน่นมาก  คอลัมน์ข้อมูล 1142 + ปุ่มท้ายแถว  90 = ตาราง 1232   ← กว้างกว่า
```

ตั้งขั้นต่ำจากระดับโปร่งอย่างเดียว พอผู้ใช้สลับไประดับแน่น **ตารางทะลุออกนอกการ์ด**
ปุ่มในคอลัมน์ท้ายแถวยื่นเลยขอบ เจ้าของงานเห็นทันที

🚨 **สูตร** ขั้นต่ำ = ค่าที่มากที่สุดในทุกระดับ + เส้นกรอบสองข้าง + ระยะขอบในการ์ดสองข้าง

## ④ เกลาชุดคอลัมน์ให้ลงตัวกับจอจริง ไม่ใช่ปล่อยตามใจ

ถ้าขั้นต่ำที่คำนวณได้ **มากกว่า** พื้นที่ที่จอเป้าหมายให้ตอนย่อแถบเมนู
แปลว่าตอนย่อแถบเมนูจะยังมีแถบเลื่อน ซึ่งผิดตรรกะ

**ให้เกลาชุดคอลัมน์ลงจนขั้นต่ำเท่ากับพื้นที่นั้นพอดี** วิธีหาว่าเฉือนคอลัมน์ไหนได้

```js
// ที่ว่างที่แต่ละคอลัมน์ยังเหลือ = ความกว้างคอลัมน์ ลบ ความกว้างเนื้อหาที่ยาวที่สุดจริง
[...tb.querySelectorAll('thead th')].map((h, i) => {
  let มากสุด = 0;
  for (const r of แถว) { const rg = document.createRange();
    rg.selectNodeContents(r.children[i]); มากสุด = Math.max(มากสุด, rg.getBoundingClientRect().width); }
  return { คอลัมน์: ชื่อ[i], กว้าง: h.getBoundingClientRect().width, เหลือ: h.getBoundingClientRect().width - มากสุด };
}).sort((a, b) => b.เหลือ - a.เหลือ);
```

⚠️ **คอลัมน์ที่เหลือที่ว่างเยอะ ไม่ได้แปลว่าเฉือนได้เสมอ**
ส่วนใหญ่เหลือเยอะเพราะ **หัวคอลัมน์กว้างกว่าเนื้อหา** เฉือนแล้วหัวโดนตัดแทน
ให้เฉือนจากคอลัมน์ที่เนื้อหายอมตกบรรทัดได้ เช่นคอลัมน์ชื่อ ซึ่งมีช่องว่างให้ตัดบรรทัด

## ⑤ 🚨 วิธีตรวจ — วัดหกอย่างพร้อมกัน ทุกระดับแถว คูณทุกสถานะแถบเมนู

วัดทีละอย่างแล้วรายงานคือสาเหตุที่ของพังโผล่ทีหลังทุกครั้ง **ต้องวัดพร้อมกันในคำสั่งเดียว**

| ตรวจอะไร | ต้องได้ |
|---|---|
| แถบเลื่อนซ้ายขวาตอนย่อแถบเมนู | 0 |
| แถบเลื่อนซ้ายขวาตอนขยายแถบเมนู | มีได้ ถ้าพื้นที่ไม่พอจริง |
| ตารางทะลุออกนอกการ์ด | ไม่ |
| ปุ่มท้ายแถวเลยขอบตาราง | ไม่ |
| หัวคอลัมน์โดนตัด | ไม่มี |
| คำถูกหั่นกลางคำ | ไม่มี |

```js
// นับคำที่ถูกหั่นกลางคำ — ข้ามค่าที่มีช่องว่าง เพราะตกบรรทัดที่ช่องว่างเป็นเรื่องปกติ
const lh = parseFloat(getComputedStyle(td).lineHeight) || 20;
const rg = document.createRange(); rg.selectNodeContents(td);
const ถูกหั่น = !/\s/.test(td.textContent.trim()) && rg.getBoundingClientRect().height > lh * 1.4;
```

🚨 **ต้องวนครบ ระดับแถว × สถานะแถบเมนู** หน้าคลังยามีสามระดับ สองสถานะ เท่ากับหกกรณี
ผ่านห้ากรณีแล้วตกหนึ่ง = ยังไม่ผ่าน

## ⑥ 🚨🔴 ห้ามทดลองด้วยการแก้สไตล์ที่ตัวกล่องโดยตรง

เขียน `el.style.xxx = ...` แล้วคืนค่าด้วย `setAttribute("style", ของเดิม)` **คืนไม่กลับ**
เบราว์เซอร์คืนสตริงที่ถูกแปลงรูปแล้ว ค่าเส้นขอบกลายเป็นว่างเปล่า **เส้นขอบตารางหายทั้งสี่ด้าน**
เจ้าของงานเห็นก่อนแล้วถามว่า *"เส้นขอบตารางเราหายไปไหน"*

✅ **ให้เพิ่มกฎ CSS ชั่วคราวแล้วลบทิ้ง**

```js
const st = document.createElement('style');
st.textContent = '.card{width:1270px !important}';
document.head.appendChild(st);
// ...วัด...
st.remove();
```

# 📏 ระยะที่ตาเห็น ไม่เท่ากับตัวเลขที่เขียนในโค้ด (23 ก.ย. 2569)

> 🔴🔴🔴 **ข้อนี้ทำให้เสียเวลาสองวันเต็มที่เว็บ warfarin** และเจ้าของงานต้องมาทักเองสามรอบ
> *"จาก 6 มันมา 32 จากไหน"* · *"คือมัน 4+6 คือ 10 ไม่ใช่ 6"* · *"ที่ว่างบน มันไม่ใช่ 15 แฮะ มันดูใหญ่"*

## ① ตัวอักษรมีอากาศติดมาทั้งบนและล่างเสมอ และตาคนเห็นอากาศนั้นเป็นช่องว่างด้วย

```
ระยะที่ตาเห็น  =  อากาศเหนือหรือใต้ตัวอักษร  +  ระยะที่ตั้งไว้ระหว่างแถบ
```

ตั้ง `gap: 6` แล้ววัดจากขอบกล่องได้ 6 **แต่ตาเห็น 7 หรือ 9 หรือ 20** เพราะกล่องตัวอักษร
สูงกว่าตัวอักษรจริงเสมอ ส่วนที่เกินคือที่ว่างที่ฟอนต์เผื่อไว้ให้สระบนกับหางตัวอักษร

**ตัวเลขจริงที่วัดได้จากหน้าคลังวิธีบริหารยา**

| จุด | อากาศของตัวอักษร | ระยะที่ตั้งไว้ | ตาเห็น |
|---|--:|--:|--:|
| ใต้หัวเรื่อง ขนาด 20 จุด | 1 | 6 | **7** |
| เหนือหัวเรื่อง ขนาด 20 จุด | 6 | 9 | **15** |

🚨 **ห้ามวัดจากขอบกล่องแล้วรายงานว่าถูก** เคยวัดได้ 15 แล้วบอกเจ้าของงานว่าตรงแล้ว
เจ้าของงานมองด้วยตาแล้วบอกว่ามันใหญ่กว่านั้น **ซึ่งถูก เพราะที่ว่างจริงคือ 20**

## ② วิธีวัดที่ถูก — วัดถึงตัวอักษรจริง ไม่ใช่ถึงขอบกล่อง

```js
// ฐานอักษรจริง — แทรกตัวอักษรความกว้างศูนย์เข้าไปแล้ววัดขอบล่างของมัน
const ฐานอักษร = (el) => {
  const s = document.createElement('span');
  s.textContent = 'x';
  s.style.cssText = 'display:inline-block;width:0;overflow:hidden';
  el.appendChild(s);
  const y = s.getBoundingClientRect().bottom;
  s.remove();
  return y;
};

// ยอดตัวอักษรจริง — ต้องวัดด้วยฟอนต์ของตัวนั้นเอง ฟอนต์ต่างกันอากาศไม่เท่ากัน
const cs = getComputedStyle(el);
const c = document.createElement('canvas').getContext('2d');
c.font = `${cs.fontStyle} ${cs.fontWeight} ${cs.fontSize} ${cs.fontFamily}`;
const ยอด = ฐานอักษร(el) - c.measureText(ข้อความจริงบนจอ).actualBoundingBoxAscent;
```

🔑 **ต้องวัดด้วยข้อความจริงที่อยู่บนจอ** ไม่ใช่ตัวอักษรตัวอย่าง
คำที่มีสระบนกับคำที่ไม่มี ยอดอยู่คนละระดับ

## ③ แก้ด้วยการหักอากาศทิ้ง ไม่ใช่ลดระยะที่ตั้งไว้

เจ้าของงานเคาะวิธีนี้เอง 22 ก.ย. 2569 หลังลองอีกวิธีแล้วบีบเกินจนต้องถอยกลับ

| วิธี | ผล |
|---|---|
| ลดทั้งอากาศและระยะอย่างละครึ่ง | 🔴 **บีบเกิน** เจ้าของงานสั่งถอยทันที |
| **หักอากาศทิ้งอย่างเดียว ระยะที่ตั้งไว้ไม่แตะ** | ✅ **ตาเห็นตรงตามตัวเลขพอดี** |

```jsx
// อากาศใต้ตัวอักษร 1 จุด หักทิ้งด้วยระยะขอบล่างติดลบ ระยะ gap ที่ตั้งไว้ไม่ต้องแตะ
<div style={{ marginBottom: -1 }}>
```

🚨 **ตัวเลขที่หักต้องมาจากการวัดจริงของฟอนต์นั้นที่ขนาดนั้น** ห้ามคำนวณจากสูตร
ฟอนต์ต่างกัน ขนาดต่างกัน อากาศไม่เท่ากัน

## ④🔴 เขียนตัวกันไว้ ไม่ใช่เขียนแค่คำเตือน

> เจ้าของงานสั่ง 23 ก.ย. 2569 — *"ลบทิ้ง แล้วเขียน code คลุมไว้เลย ห้ามแก้จุดนี้อีก"*
> และ *"คนที่ให้แก้ ต้องถามเราทั้งนั้น เอาไปเขียนในโค้ดเลยว่าถ้าไล่มาถึงบรรทัดนี้
>   แล้วมันต้องมีการปรับเลื่อน เธอต้องหยุดแล้วมาถามเรา"*

คำเตือนในโค้ดเป็นแค่ตัวหนังสือ คนอ่านแล้วเชื่อ แต่ไม่มีอะไรจับได้ตอนค่าจริงเพี้ยน
**ของจริงที่เคยเกิด** — เขียนคำเตือนไว้แล้ว ระยะก็ยังหายไปอีกรอบโดยไม่มีใครรู้

**ต้องมีสองชั้นคู่กัน**

| ชั้น | ทำอะไร |
|---|---|
| คำเตือนในโค้ด | บอกว่าห้ามแก้ และ **ให้หยุดไปถามเจ้าของงานก่อน** |

# 🎚 แถบเลื่อนในกล่องที่มีหัวตารางตรึง ต้องเริ่มใต้หัว (23 ก.ย. 2569)

> เจ้าของงานเห็นเองแล้วสั่ง — *"มันควรเริ่มใต้หัวคอลัมน์นี่"*

หัวตารางที่ตรึงไว้จะลอยทับอยู่บนสุดของกล่องตลอดเวลา
ถ้าแถบเลื่อนเริ่มที่ขอบบนของกล่อง มันจะไปเริ่มระดับเดียวกับหัวคอลัมน์
**ซึ่งดูเหมือนแถบพาดทับหัวตาราง** ทั้งที่ของที่เลื่อนจริงคือแถวข้อมูลที่อยู่ใต้หัว

```js
/** หัวตารางที่ตรึงในกล่องนี้สูงเท่าไหร่ กล่องที่ไม่มีหัวตรึงจะได้ 0 จึงไม่กระทบหน้าอื่น */
const สูงหัวตรึง = (el) => {
  const th = el.querySelector('thead th');
  if (!th || getComputedStyle(th).position !== 'sticky') return 0;
  return Math.round(th.getBoundingClientRect().height);
};

const หัว = สูงหัวตรึง(el);
const ช่อง = Math.max(MIN_LEN, el.clientHeight - หัว);   // พื้นที่ที่แถบเดินได้จริง
const len = Math.max(MIN_LEN, (ช่อง * el.clientHeight) / el.scrollHeight);
const at  = run > 0 ? (el.scrollTop / run) * (ช่อง - len) : 0;
const top = r.top + หัว + at;
```

🚨 **ต้องหักหัวออกจากทั้งความยาวและตำแหน่ง ไม่ใช่แค่เลื่อนจุดเริ่ม**
หักแค่จุดเริ่มแล้วแถบจะยาวเกินกล่อง ล้นออกไปใต้ขอบล่าง

🔑 **แก้ที่ตัววาดกลางได้เลย ไม่ต้องแยกเป็นของหน้าใดหน้าหนึ่ง**
เพราะกล่องที่ไม่มีหัวตารางตรึงจะได้ค่าศูนย์ ผลลัพธ์จึงเหมือนเดิมทุกประการ

# 🔘 ปุ่มทำงานในแถวตาราง ต้องทรงเดียวกันทุกหน้าในเว็บเดียวกัน (23 ก.ย. 2569)

> เจ้าของงานทักเอง — *"อันนี้ไปเปิดหน้าคลังยาก็รู้ละ ไม่ต้องเปิดเว็บอื่น"*

**ก่อนออกแบบปุ่มในแถวตาราง ให้เปิดหน้าอื่นของเว็บเดียวกันที่มีตารางดูก่อนเสมอ**
คำตอบมักอยู่ในเว็บนั้นแล้ว ไม่ต้องไปหาจากเว็บอื่นหรือคิดขึ้นใหม่

**ของจริงที่เกิด** — เว็บ warfarin หน้าคลังยาใช้ปุ่มไอคอนในกรอบ 30 จุด มีคลาสกลางชื่อ `icon-btn`
พร้อมสีตอนชี้ครบทุกโทน แต่หน้าคลังวิธีบริหารกลับทำปุ่มข้อความเปล่าไม่มีกรอบขึ้นมาใหม่
**สองหน้าในเว็บเดียวกันจึงใช้คนละทรง** ทั้งที่เป็นปุ่มทำงานเดียวกันในตารางเหมือนกัน

🚨 **ท่าตรวจก่อนลงมือ** — ค้นว่าเว็บนี้มีคลาสปุ่มในแถวอยู่แล้วหรือยัง

```bash
grep -rn "icon-btn\|rowbtn\|ปุ่มในแถว" app/globals.css | head
```

เจอแล้วให้ใช้ตัวนั้น **ห้ามสร้างคลาสใหม่ซ้อน** เจอสองชุดเมื่อไหร่ต้องรวมให้เหลือชุดเดียว
