## 24. เบราว์เซอร์ห้ามถือกุญแจฐานข้อมูล

```
❌ NEXT_PUBLIC_SUPABASE_KEY   ← เบราว์เซอร์เห็น = ใครก็แก้ฐานข้อมูลได้
✅ SUPABASE_SERVICE_ROLE_KEY  ← ฝั่งเซิร์ฟเวอร์เท่านั้น ผ่าน API route
```

**ทำครบทั้งสามเว็บแล้ว** — ME-DRP ย้ายเป็นเว็บสุดท้าย 3 ก.ย. 2569 (v0.9.24.0)

**บทเรียนจากการย้าย ME-DRP ที่เว็บอื่นยังไม่มี**
1. **เขียนไฟล์ตัวคุยข้อมูลใหม่โดยคงชื่อฟังก์ชันเดิมทุกตัว** → หน้าจอทั้งเว็บไม่ต้องแก้เลย งานกระจุกที่ไฟล์เดียว
2. **`import "server-only"` ในไฟล์ที่ถือกุญแจ** เผลอ import จากฝั่งเบราว์เซอร์เมื่อไหร่ พังตั้งแต่ build ไม่ใช่ไปรู้ตอนกุญแจหลุดขึ้นเว็บจริง (เว็บพี่น้องยังไม่มีตัวนี้)
3. **ปิด RLS เป็นขั้นสุดท้ายเสมอ** ปิดก่อนย้ายเสร็จ = เว็บใช้ไม่ได้ทั้งห้องยาทันที
4. 🚨 **เงื่อนไขที่เคยฝากไว้กับกฎของฐาน ต้องย้ายมาเขียนเองฝั่งเซิร์ฟเวอร์** กุญแจ service role ผ่านทุกกฎ ตาข่ายนั้นหายไปเงียบ ๆ (ME-DRP เคยมีกฎ "ลบได้เฉพาะแถวในถังขยะ")
5. **พิสูจน์ด้วยการยิงจริงด้วยกุญแจเก่า** ทั้งอ่าน เขียน แก้ ลบ แล้วตรวจฐานซ้ำว่าข้อมูลไม่ขยับ — ไม่ใช่แค่ดูว่า policy หายไปจากตาราง

**ประตูรหัสผ่าน — ME-DRP ทำแล้ว 2 ก.ย. 2569 (v0.9.23.0)** ยกกลไกจาก HCV มาทั้งชุด
`middleware.ts` (ด่านที่ 1 กั้นทุกหน้า/ทุก API) + `lib/requireAuth.ts` (ด่านที่ 2 route เรียกเอง)
+ `lib/auth.ts` (คุกกี้ `httpOnly` ลงลายเซ็น อายุ 7 วัน **นับจากครั้งสุดท้ายที่ใช้** ต่ออายุอัตโนมัติ)
🚨 **ต้องมีปุ่มออกจากระบบที่ล้างข้อมูลในเครื่องด้วย** ล็อกประตูอย่างเดียวไม่พอ
   สำเนารายงานที่ค้างใน `localStorage` ยังอยู่ ใครเปิดเครื่องต่อก็เห็น
   🚨 **ยังมีรายงานค้างส่ง = ห้ามให้ออก** รายงานพวกนั้นอยู่ในเครื่องนั้นที่เดียว ล้างแล้วหายถาวร


### 🚨 บัตรผ่านต้องนับอายุจาก "ครั้งสุดท้ายที่ใช้" ไม่ใช่ "วันที่ออกบัตร"

**เป็นกฎของทุกเว็บ** (ยกขึ้นเป็นกฎ 2 ก.ย. 2569 · ML-DRP ทำก่อน · มูลค่ายาคืนตามแล้ว)

คอมห้องยาเปิดเว็บทุกวัน แต่ถ้านับจากวันที่ออกบัตร **จู่ ๆ วันหนึ่งก็ถูกเด้งออกกลางงาน**
เภสัชกรที่กำลังกรอกยาคืนค้างอยู่ต้องหยุดไปตามหารหัส ซึ่งไม่มีใครจำได้

```js
// lib/auth.js — ใกล้หมดอายุแล้วหรือยัง
export function authCookieStale(value) {
  const at = Number(String(value || '').split('.')[0]);
  if (!Number.isFinite(at)) return false;
  return Date.now() - at > (AUTH_DAYS * 24 * 60 * 60 * 1000) / 2;
}
```
```js
// middleware — ต่ออายุให้เองตอนบัตรผ่านด่าน
const res = pass();
if (authCookieStale(got.value)) {
  res.cookies.set(AUTH_COOKIE, await issueAuthCookie(), authCookieOpts());
}
return res;
```

🚨 **ต่อเมื่อใช้ไปเกินครึ่งอายุแล้วเท่านั้น ไม่ใช่ต่อทุกคำขอ**
ต่อทุกคำขอ = เขียนคุกกี้ใหม่หลายสิบครั้งต่อนาทีโดยไม่ได้อะไรเพิ่ม และตามรอยยากเพราะเวลาขยับตลอด

🚨 **ตัวเลือกของคุกกี้ต้องอยู่ที่เดียว** (`authCookieOpts()`) เพราะมีสองที่ที่เขียนคุกกี้ —
ตอนล็อกอิน กับ ตอนต่ออายุ · เขียนแยกแล้วแก้ที่หนึ่งลืมอีกที่
= บัตรที่ออกกับที่ต่ออายุมีคุณสมบัติไม่เหมือนกัน ซึ่งไม่มีอะไรจับได้เลย

🚨 **ต้องทดสอบด้วยบัตรที่ "แก่" จริง ๆ** สร้างบัตรย้อนเวลาแล้วดูว่าระบบตัดสินยังไง
ไม่ใช่อ่านโค้ดแล้วเชื่อว่าถูก (ยาคืนทำไว้ที่ `scripts/auth-renew-check.mjs` 8 ข้อ)

เว็บที่มี **HN / AN (ข้อมูลผู้ป่วย)** ต้องล็อกเสมอ อย่างน้อยรหัสผ่านร่วม 1 ชั้น
ห้ามใส่ HN ในที่อยู่เว็บ (URL)

## 34. 🔴 ทุกอย่างในโฟลเดอร์ `public/` คนนอกโหลดได้ ไม่ผ่านหน้าล็อกอิน

> *"**ทุกอย่างใน `public/` เสิร์ฟออกไปโดยไม่ผ่านการลงชื่อเข้าใช้**
>  ก่อนขึ้นใช้จริงต้องย้ายออกจาก `public/` แล้วเสิร์ฟผ่านเส้นทางฝั่งเซิร์ฟเวอร์
>  ที่ตรวจว่าลงชื่อเข้าใช้แล้วก่อนส่งไฟล์"*

**ประตูตรวจรหัสผ่านไม่ได้กั้นโฟลเดอร์นี้** ใครรู้ชื่อไฟล์ก็เปิดได้ตรง ๆ

### 🔴 เคยเกิดจริง — มอคอัปที่มี HN คนไข้จริงวางอยู่ในนี้

HCV เคยมีไฟล์มอคอัปที่ใส่ HN จริง วางใน `public/mockups/` **คนนอกโหลดได้ตลอดเวลา**
และเรื่องมอคอัปวางผิดที่นี้ **เจอซ้ำ 2 เว็บแล้ว**

| ของแบบไหน | วางที่ไหน |
|---|---|
| ไอคอน · โลโก้ · ฟอนต์ · รูปประกอบทั่วไป | `public/` ได้ |
| **มอคอัป · เอกสารตัวอย่าง · ไฟล์ที่มีข้อมูลคนไข้** | ❌ **ห้ามอยู่ใน `public/`** |
| ไฟล์ที่ต้องล็อก | เสิร์ฟผ่านเส้นทางฝั่งเซิร์ฟเวอร์ที่ตรวจสิทธิ์ก่อน |

🚨 **มอคอัปห้ามใช้ HN จริงเด็ดขาด** ไม่ว่าจะวางที่ไหน
🚨 **ก่อนขึ้นเว็บจริงต้องไล่ดูว่าใน `public/` มีอะไรที่ไม่ควรอยู่**

```bash
find public -type f | grep -vE "\.(ico|png|jpg|svg|woff2?|webmanifest)$"
```

## 35. 🚨 `run_worker_first: true` — ไม่ตั้งแล้วมีทางเข้าที่ไม่ผ่านหน้าล็อกอิน

> *"`wrangler.jsonc` เพิ่ม **`run_worker_first: true`** ห้ามเอาออก —
>  ค่าตั้งต้นของ Cloudflare คือ `false` ซึ่งแปลว่าตัวจ่ายไฟล์นิ่งทำงาน**ก่อน**โค้ดเรา
>  = มีทางเข้าที่ไม่ผ่านหน้าล็อกอิน"*

Cloudflare มีตัวจ่ายไฟล์นิ่ง (รูป ไอคอน ไฟล์ที่สร้างไว้ล่วงหน้า) แยกจากโค้ดของเรา
**ค่าตั้งต้นให้ตัวนั้นทำงานก่อน** — คำขอที่ตรงกับไฟล์นิ่งจะถูกตอบทันที **ไม่ผ่านด่านตรวจรหัสของเราเลย**

เท่ากับเว็บที่คิดว่าล็อกอยู่ **มีประตูหลังเปิดค้าง**

```jsonc
// wrangler.jsonc
{ "run_worker_first": true }   // ห้ามเอาออก
```

🚨 **ต้องตั้งทุกเว็บที่มีหน้าล็อกอิน** และตรวจซ้ำทุกครั้งที่แตะไฟล์ตั้งค่านี้

## 36. 🚨🔴 `rls_enabled_no_policy` เป็นสถานะที่ตั้งใจ — ห้ามไป "แก้"

**นี่คือกับดักที่ Claude ตัวถัดไปจะเดินเข้าแน่นอน**

> *"**เปิด RLS ทุกตารางและไม่ใส่ policy เลย** คือปฏิเสธทุกคำขอจากเบราว์เซอร์
>  ตัวตรวจของ Supabase จะขึ้น `rls_enabled_no_policy` ระดับ INFO
>  **อันนี้คือสถานะที่ตั้งใจ ห้ามไปเพิ่ม policy ให้ `anon`**"*

### ทำไม Supabase ถึงเตือน แต่เราไม่ต้องแก้

Supabase คิดว่าเราลืมใส่กติกาการเข้าถึง เลยเตือนว่า "เปิดยามไว้แต่ไม่มีกฎให้ยาม"
**แต่ของเราตั้งใจ** — ไม่มีกฎเลยแปลว่ายามปฏิเสธทุกคน ซึ่งคือสิ่งที่ต้องการ

เว็บของเราเข้าฐานผ่านหลังบ้านด้วยกุญแจระดับผู้ดูแลเท่านั้น **เบราว์เซอร์ไม่เคยคุยกับฐานโดยตรง**

🚨 **เห็นคำเตือนนี้แล้วห้ามไปเพิ่มกติกาให้กุญแจฝั่งเบราว์เซอร์เด็ดขาด**
เพิ่มเมื่อไหร่ = **เปิดประตูให้ใครก็ได้แก้คลังยาที่ใช้ร่วม 3 เว็บ**

⚠️ ถ้าวันหนึ่งเว็บไหนจำเป็นต้องให้เบราว์เซอร์คุยกับฐานตรง ๆ **ต้องคุยกับพี่กันก่อน**
ไม่ใช่เพิ่มกติกาเงียบ ๆ เพราะตัวตรวจบอกให้เพิ่ม

# 🚪 ทางเข้าฐานข้อมูล — ต้องมีประตูเดียว

**ตั้งหัวข้อ 5 กันยายน 2569** จากบทเรียนที่กระจายอยู่ใน ME-DRP กับเว็บยาคืน

## ①🔴 ห้ามยัดก้อนข้อมูลจากเบราว์เซอร์ลงฐานตรง ๆ

ทุกอย่างที่ส่งมาจากเบราว์เซอร์ **ต้องผ่านตัวแปลงกลางก่อนเสมอ**
ตัวแปลงนั้นทำหน้าที่สองอย่างพร้อมกัน

| หน้าที่ | ทำไมต้องมี |
|---|---|
| แปลงชื่อช่องและชนิดข้อมูล | ฝั่งจอกับฝั่งฐานเรียกชื่อไม่เหมือนกัน |
| **เป็นรายการช่องที่อนุญาต** | ช่องที่ไม่ได้อยู่ในรายการจะถูกทิ้ง **คนส่งช่องแปลกปลอมมาจึงแก้อะไรไม่ได้** |

```js
// ✅ ถูก — ทุกเส้นทางเรียกตัวเดียวกัน
const row = toRow(body);
// ❌ ผิด — ส่งอะไรมาก็เขียนลงฐานตามนั้น
await db.insert(body);
```

## ②🔴 เส้นทางที่มีรหัสในที่อยู่ ต้องยึดรหัสจากเส้นทาง ห้ามเชื่อรหัสในตัวข้อมูล

```

```

**ถ้าเชื่อรหัสในตัวข้อมูล คำขอเดียวแก้รายการของคนอื่นได้ทันที**
🚨 **ยึดรหัสจากเส้นทางเสมอ และตัดรหัสที่ปนมาในตัวข้อมูลทิ้ง**

## ③🔴 หน้าตรวจสุขภาพระบบ ห้ามคืนค่ากุญแจ

หน้าที่บอกว่าระบบพร้อมไหม (`GET /api/health`) **ต้องมีบัตรผ่าน** และตอบได้แค่

# 🔐 ประตูรหัสผ่าน — ชุดกฎครบ 6 ข้อ

## ①🚨 ไม่ได้ตั้งรหัสผ่าน = ต้องพังแบบเห็นชัด

**เว็บจริงที่ไม่ได้ตั้งรหัส ต้องตอบ 503 ทั้งเว็บ** ตั้งใจให้พังให้เห็น
**ดีกว่าเปิดโล่งเงียบ ๆ โดยไม่มีใครรู้**

🔑 **นี่คือวิธียืนยันว่าตั้งตัวแปรลับสำเร็จจริงด้วย** — ยิงเข้าไปแล้วดูรหัสตอบกลับ

| ได้ | แปลว่า |
|---|---|
| **503** | ยังไม่ได้ตั้งรหัส |
| **401** | ตั้งแล้ว ประตูทำงาน แค่ยังไม่ได้ใส่รหัส |

## ②🚨 ห้ามทำทางลัดปลดล็อกตอนรันในเครื่อง

เว็บยาคืนเคยมีแล้วถอดทิ้ง **เพราะทำให้เครื่องทดสอบไม่เหมือนเว็บจริง**
บั๊กของประตูจึงไม่มีวันโผล่ตอนทดสอบ

## ③🚨🔴 กัน "รหัสว่าง" ด้วย ไม่งั้นได้รูที่ใหญ่กว่าเดิม

**กับดักที่เกือบพลาดจริง** — แก้แค่ตัวเช็คว่าเปิดประตูไหม ยังไม่พอ

```
ลายเซ็นของ('')  ตรงกับ  ลายเซ็นที่คาดหวังของ('')  พอดี
→ กรอกช่องว่างแล้วเข้าเว็บได้
```

🚨 **ต้องปฏิเสธรหัสว่างที่ตัวรับรหัสด้วย ไม่ใช่แค่ที่ตัวเช็คว่าเปิดประตูไหม**

## ④🚨 รายการเส้นทางที่ประตูคุ้ม มีรูให้เลี่ยงด้วยนามสกุลไฟล์

**พิสูจน์รูจริงมาแล้ว** — เส้นทางที่ลงท้ายด้วยนามสกุลไฟล์ข้ามประตูไปได้

## ⑤🔴 ค่าตั้งค่าที่เปลี่ยนได้ ห้ามเอามาผสมในลายเซ็นบัตรผ่าน

ที่อยู่ฐานข้อมูลถูกเอามาผสมในลายเซ็น **แก้ค่านั้นทีเดียวทุกคนหลุดออกจากระบบพร้อมกัน**
แม้แต่การเติม `/` ต่อท้ายก็นับเป็นคนละค่า

🚨 **ลายเซ็นต้องผสมจากค่าที่ตั้งใจให้เป็นความลับเท่านั้น** ไม่ใช่ค่าตั้งค่าทั่วไป

## ⑥ บัตรผ่านของเครื่องที่ใช้ร่วมกันต้องอายุสั้น

**คอมในห้องทำงานเป็นเครื่องใช้ร่วมกัน** มีคนล็อกอินทิ้งไว้แล้วลืมเสมอ

| เหตุผล | สิ่งที่เกิดถ้าบัตรอายุยาว |
|---|---|
| เครื่องใช้ร่วมกัน | ใครเปิดเครื่องนั้นอีกหลายสัปดาห์ก็เห็นข้อมูลโดยไม่ต้องรู้รหัส |
| **วันที่ต้องเปลี่ยนรหัสเพราะสงสัยว่ารหัสหลุด** | **เครื่องที่ค้างไว้ยังเข้าได้ต่อจนครบอายุบัตร การเปลี่ยนรหัสจึงไม่ได้ปิดประตูจริง** |

## ⚠️ ประตูรหัสผ่านปิดหน้าเว็บ ไม่ได้ปิดฐานข้อมูล

กุญแจสาธารณะที่เคยฝังในหน้าเว็บ **ยังยิงเข้าฐานตรงได้โดยไม่ผ่านหน้าเว็บ**
🚨 **ต้องปิดสองชั้นเสมอ** — ประตูหน้าเว็บ **และ** กติกาของตารางในฐาน
