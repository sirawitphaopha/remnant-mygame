# ส่วน 1 — แตะแล้วรู้สึก (ชุดที่ 1)

## แตะปุ่มแล้วปุ่มยุบลง — จอสัมผัสไม่มี :hover จึงต้องมี :active แทน

**ที่ไหน** `app/mobile.css:25-47`

**โค้ดจริง**
```css
/* ── ชุด 1 · แตะปุ่มแล้วปุ่มยุบลง ────────────────────────────────────────────

   ปัญหาเดิม: globals.css ปิด -webkit-tap-highlight-color ทิ้งทั้งเว็บ
   แล้วสีที่ทำไว้ทั้งหมด (.hv-*) เป็น :hover ล้วน ซึ่งจอสัมผัสไม่มี
   ผลคือแตะปุ่มบนมือถือแล้วเงียบสนิท ไม่รู้ว่านิ้วโดนหรือยัง

   🚨 ต้องใช้ [role="button"] ไม่ใช่ button — ทุกปุ่มในเว็บนี้เป็น <div> ที่ใส่ kb()
      (ดูข้อ 3.8) เขียน button เฉย ๆ จะไม่มีผลกับปุ่มสักตัวเดียว
   🚨 ใช้ property `scale` ไม่ใช่ `transform` — ปุ่มหลายตัวมี transform อยู่แล้ว
      (เช่นปุ่ม ✕ ในช่องค้นหาที่ใช้ translateY จัดกึ่งกลาง) ทับแล้วปุ่มจะกระโดด */
.mrv-mobile [role="button"],
.mrv-mobile button,
.mrv-mobile a,
.mrv-mobile label[for],
.mrv-mobile summary {
  transition: background 0.18s ease, background-color 0.18s ease, border 0.18s ease,
    color 0.18s ease, box-shadow 0.18s ease, scale 0.11s ease, opacity 0.18s ease;
}

.mrv-mobile [role="button"]:active,
.mrv-mobile button:not(:disabled):active {
  scale: 0.97;
}
```

**แก้ปัญหาอะไร** — แตะปุ่มบนมือถือแล้วไม่มีอะไรตอบสนองเลย ผู้ใช้ไม่รู้ว่านิ้วโดนปุ่มหรือยัง เลยกดซ้ำ

**เหตุผลจากคอมเมนต์** (คำต่อคำ)
> ปัญหาเดิม: globals.css ปิด -webkit-tap-highlight-color ทิ้งทั้งเว็บ
> แล้วสีที่ทำไว้ทั้งหมด (.hv-*) เป็น :hover ล้วน ซึ่งจอสัมผัสไม่มี
> ผลคือแตะปุ่มบนมือถือแล้วเงียบสนิท ไม่รู้ว่านิ้วโดนหรือยัง

> 🚨 ต้องใช้ [role="button"] ไม่ใช่ button — ทุกปุ่มในเว็บนี้เป็น <div> ที่ใส่ kb()
>    (ดูข้อ 3.8) เขียน button เฉย ๆ จะไม่มีผลกับปุ่มสักตัวเดียว
> 🚨 ใช้ property `scale` ไม่ใช่ `transform` — ปุ่มหลายตัวมี transform อยู่แล้ว
>    (เช่นปุ่ม ✕ ในช่องค้นหาที่ใช้ translateY จัดกึ่งกลาง) ทับแล้วปุ่มจะกระโดด

**ผูกกับเว็บนี้แค่ไหน** — **ยกไปใช้ได้เลย** ค่า `scale: 0.97` กับ `0.11s` ใช้ได้ทุกเว็บ
⚠️ ตัวเลือก `[role="button"]` เป็นเพราะเว็บนี้ทำปุ่มเป็น `<div>` ทั้งเว็บ (107 จุด) · เว็บที่ใช้ `<button>` จริงก็ยังครอบคลุมอยู่แล้วเพราะกฎเขียนทั้งสองแบบ
🔑 **บทเรียนที่ยกไปได้เต็ม ๆ: ใช้ property `scale` ไม่ใช่ `transform`** เพราะ `transform` ทับของเดิมที่ปุ่มอาจมีอยู่แล้ว

## `touch-action: manipulation` บนปุ่ม — ปุ่มตอบไวขึ้นเพราะไม่ต้องรอว่าจะแตะสองครั้งไหม

**ที่ไหน** `app/mobile.css:57-63`

**โค้ดจริง**
```css
/* ปิดการซูมตอนแตะสองครั้ง เฉพาะบนปุ่ม — ปุ่มตอบไวขึ้นเพราะเบราว์เซอร์ไม่ต้องรอ
   🚨 ห้ามใส่ที่ body — เภสัชกรที่สายตายาวต้องซูมอ่านชื่อยาได้ (WCAG 1.4.4)
      และห้ามใช้ user-scalable=no ที่ viewport เด็ดขาดด้วยเหตุผลเดียวกัน */
.mrv-mobile [role="button"],
.mrv-mobile button {
  touch-action: manipulation;
}
```

**แก้ปัญหาอะไร** — เบราว์เซอร์รอ ~300ms หลังแตะ เผื่อว่าจะเป็นการแตะสองครั้งเพื่อซูม ปุ่มจึงรู้สึกหน่วง

**เหตุผลจากคอมเมนต์** (คำต่อคำ)
> 🚨 ห้ามใส่ที่ body — เภสัชกรที่สายตายาวต้องซูมอ่านชื่อยาได้ (WCAG 1.4.4)
>    และห้ามใช้ user-scalable=no ที่ viewport เด็ดขาดด้วยเหตุผลเดียวกัน

🔴 **หมายเหตุสำคัญ — คอมเมนต์นี้ขัดกับสิ่งที่ทำจริงในภายหลัง**
คอมเมนต์นี้เขียนไว้ตอนแรก ห้ามใช้ `user-scalable=no` เด็ดขาด **แต่ต่อมาเจ้าของงานสั่งกลับ** (ดูหัวข้อ "ห้ามซูมทุกทาง" ข้างล่าง และ `layout.js`) จนตอนนี้เว็บนี้ **ห้ามซูมจริง** ทั้ง `maximumScale: 1` และ `userScalable: false` · คอมเมนต์เดิมไม่ได้ถูกลบ

**ผูกกับเว็บนี้แค่ไหน** — `touch-action: manipulation` บนปุ่ม **ยกไปใช้ได้เลย ปลอดภัยที่สุดในบรรดากฎ touch-action ทั้งหมด** (ไม่ห้ามซูมทั้งหน้า ห้ามแค่บนปุ่ม)

## เครื่องที่ตั้งค่าลดการเคลื่อนไหว — ปิดจังหวะทั้งหมด

```css
/* เครื่องที่ตั้งค่าลดการเคลื่อนไหว (เจ้าหน้าที่ที่เวียนหัวง่าย) — ปิดจังหวะทั้งหมด
```

> เครื่องที่ตั้งค่าลดการเคลื่อนไหว (เจ้าหน้าที่ที่เวียนหัวง่าย) — ปิดจังหวะทั้งหมด

# ส่วน 2 — เปลี่ยนหน้าแล้วไม่วาบ

## เปลี่ยนแท็บแล้วภาพไล่จางแทนการกระพริบ (View Transition)

**ที่ไหน** `app/mobile.css:81-101`

**โค้ดจริง**
```css
/* ── ชุด 4 · เปลี่ยนหน้าแล้วไม่วาบ ──────────────────────────────────────────

   กดแท็บแล้วเบราว์เซอร์ถ่ายภาพหน้าเดิมไว้ แล้วไล่จางสลับกับหน้าใหม่ให้เอง
   ตัวสั่งอยู่ที่ handlers/ui.js → app.viewSwap ซึ่งเรียกเฉพาะตอนมีคลาส .mrv-mobile

   🚨 กฎชุดนี้เขียนที่ระดับ :root ไม่ใช่ใต้ .mrv-mobile เพราะเป็น pseudo-element
      ของทั้งเอกสาร ซ้อนใต้คลาสไม่ได้ จึงล้อมด้วย :has() แทนเพื่อคงกติกาเดิมไว้
   🚨 เดสก์ท็อปไม่มีทางโดน 2 ชั้น — ทั้งตัวสั่งที่ไม่เรียก และ :has() ที่ไม่ตรง */
:root:has(body.mrv-mobile)::view-transition-old(root),
:root:has(body.mrv-mobile)::view-transition-new(root) {
  animation-duration: 0.2s;
}

/* เครื่องที่ตั้งค่าลดการเคลื่อนไหว — ตัดจังหวะจางทิ้ง (ตัวสั่งก็ข้ามให้อยู่แล้ว
   กฎนี้เป็นตาข่ายอีกชั้นเผื่อมีทางเข้าอื่นในอนาคต) */
@media (prefers-reduced-motion: reduce) {
  :root:has(body.mrv-mobile)::view-transition-old(root),
  :root:has(body.mrv-mobile)::view-transition-new(root) {
    animation: none;
  }
}
```

**แก้ปัญหาอะไร** — กดแท็บแล้วหน้าเปลี่ยนแบบกระพริบทันที รู้สึกเหมือนเว็บ ไม่เหมือนแอป

**เหตุผลจากคอมเมนต์** (คำต่อคำ)
> 🚨 กฎชุดนี้เขียนที่ระดับ :root ไม่ใช่ใต้ .mrv-mobile เพราะเป็น pseudo-element
>    ของทั้งเอกสาร ซ้อนใต้คลาสไม่ได้ จึงล้อมด้วย :has() แทนเพื่อคงกติกาเดิมไว้
> 🚨 เดสก์ท็อปไม่มีทางโดน 2 ชั้น — ทั้งตัวสั่งที่ไม่เรียก และ :has() ที่ไม่ตรง

**ผูกกับเว็บนี้แค่ไหน** — **ยกไปใช้ได้เลย** ต้องมี 2 ส่วนคู่กัน: ฝั่ง JS ต้องเรียก `document.startViewTransition()` (อยู่ที่ `components/handlers/ui.js` → `app.viewSwap`) และฝั่ง CSS กำหนดความยาวจังหวะ · ระยะ **0.2 วินาที** เป็นค่าที่ยกไปได้
🔑 **เทคนิคที่ยกไปได้: ล้อม `:root` ด้วย `:has(body.<คลาสมือถือ>)`** เพื่อให้กฎที่ต้องเขียนระดับเอกสารยังคงกติกา "มือถือเท่านั้น" ไว้

# ส่วน 3 — การเลื่อนหน้าจอ

## ดึงหน้าลงเพื่อโหลดใหม่ — ต้องปิดตัวรีเฟรชของเบราว์เซอร์ก่อน

**ที่ไหน** `app/mobile.css:103-113`

**โค้ดจริง**
```css
/* ── ดึงหน้าลงเพื่อโหลดใหม่ ─────────────────────────────────────────────────
```

> 🔴 ที่ยังซูมได้ทั้งที่ตั้ง touch-action ไปแล้ว เพราะ **touch-action ไม่สืบทอดลงไปยังลูก**
>    เบราว์เซอร์ดูค่าของ element ที่นิ้วแตะโดยตรง ใส่ที่ตัวหน้าเว็บอย่างเดียวจึงไม่พอ

|---|---|

3. **ห้ามให้ `<input>` เป็น `display:flex`** ข้อความในช่องจะเพี้ยน
4. มีตัวตรวจอัตโนมัติ `scripts/tap-check.mjs` ที่รายงาน **2 อย่าง** — ปุ่มเล็กเกิน **และ พื้นที่กดที่ทับกัน** (อย่างที่สองอันตรายกว่า)

```js
    if (typeof window === 'undefined') return;
    const vv = window.visualViewport;
    const cands = [
      vv && vv.width ? vv.width : 0,
      window.innerWidth || 0,
      document.documentElement ? document.documentElement.clientWidth : 0

    if (!cands.length) return;
```

# ส่วน 15 — สรุปจุดตัดจอ (breakpoint) ทั้งเว็บ

เว็บนี้ใช้จุดตัดจอ **แค่ค่าเดียว** ในไฟล์ CSS

| ค่า | ที่ไหน | ทำไมเลือกค่านี้ |
|---|---|---|
| **1180** | `components/vals/derive.js` → `wide = st.vw >= 1180 && !st.forceNarrow` | ตัวตัดสินหลัก **แต่เป็นฝั่ง JS ไม่ใช่ CSS** · CLAUDE.md ข้อ 7 บอกว่า *"เดิม 960 แต่คอลัมน์ในตารางบีบจนเหลือ 34px เลยขยับขึ้น"* |
| **1179** | `app/mobile.css:196` · `225` · `255` · `301` (ใช้ 4 ที่) | = 1180 − 1 · *"1179px = ต่ำกว่าจุดสลับ (1180) หนึ่งจุด เดสก์ท็อปจริงจึงไม่มีทางโดน"* |
| **1180** | `components/MedReturnApp.jsx` → `_isNarrowNow()` | ด่านสำรองฝั่ง JS ที่ไม่พึ่งคลาส |

🔴 **ไม่มี breakpoint อื่นเลยในไฟล์ CSS** — ไม่มี 768 · 480 · 375 · เว็บนี้แบ่งแค่ "มือถือ/แคบ" กับ "คอม/กว้าง" สองสถานะเท่านั้น
📌 **เว็บนี้แยก markup สองชุดจริง ๆ ไม่ใช่ responsive ตัวเดียว** (CLAUDE.md ข้อ 7) — 1 ไฟล์ต่อ 1 หน้า มี 2 ฟังก์ชันข้างใน เช่น `renderRecordNarrow` / `renderRecordWide`
📌 **จอเตี้ยมีตัวตัดสินแยกต่างหาก** `components/vals/derive.js` → `tight = (st.vh || 900) < 700` (บีบแถวยาจาก 11px เหลือ 6px · สูง 50 → 40) — **เป็นฝั่ง JS ไม่ใช่ media query**

**ผูกกับเว็บนี้แค่ไหน** — ⚙️ **ต้องปรับ** ค่า 1180 เป็นของเว็บนี้ล้วน ๆ (ตัดสินจากความกว้างที่ตารางฝั่งคอมยังอ่านได้)
🔑 **แต่หลักการยกไปได้: ตัวเลขใน `@media` ต้องเป็น "จุดสลับ − 1" เสมอ ไม่ใช่ตัวเลขที่คิดขึ้นใหม่** ไม่งั้นมีช่วงความกว้างที่ได้กฎทั้งสองฝั่ง หรือไม่ได้เลย

# หมายเหตุ · สิ่งที่ยังไม่แน่ใจ

1. **`.mrv-xscroll` มีแค่ครึ่งเดียวใน `mobile.css`** — ไฟล์มีเฉพาะส่วนซ่อนแถบเลื่อน (`scrollbar-width:none` ฯลฯ) · ตัว `overflow-x: auto` และ `overscroll-behavior-x` ที่คอมเมนต์ (`mobile.css:355`) พูดถึง **ไม่มีในไฟล์นี้** น่าจะเขียนเป็นสไตล์ฝังในแท็ก JSX — **ตัวที่ 2 ควรตรวจจุดนี้ต่อ**
2. **`--tbl-top`** ใช้ใน `.tbl thead th` (`globals.css:687`) แต่ยังไม่ได้ไล่ดูว่าแต่ละหน้าตั้งค่านี้ที่ไหน (คอมเมนต์บอกว่า *"แต่ละหน้าตั้ง top เองผ่านตัวแปร --tbl-top เพราะมีแถบกรองสูงไม่เท่ากัน"*)
3. **`overscroll-behavior: contain` ที่กรอบผลค้นยา 3 จุด** (CLAUDE.md ข้อ 3.72 ④) — ไม่พบใน `mobile.css` หรือ `globals.css` น่าจะอยู่ในสไตล์ฝังในแท็ก
4. **การ์ดฝั่งมือถือของหน้าประวัติ/รายการ Lot** (แทนตาราง) และ **แถบบันทึกฝั่งมือถือ 186px** อยู่ในไฟล์ `components/pages/*.jsx` — **นอกขอบเขตของตัวที่ 1**
