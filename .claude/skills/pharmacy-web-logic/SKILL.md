## 9. แช่ข้อมูลไว้ในแถว (snapshot)

เคส/รายการที่บันทึกแล้วต้องเก็บ **ชื่อยา · หน่วย · ราคา** ไว้ในแถวของตัวเอง


🚨 **แก้รายการเก่าห้ามแตะราคาที่แช่ไว้** แก้ได้แค่จำนวนกับสถานะ

### 🔴🔴 ชื่อยาเป็นข้อยกเว้น — แสดงผลใช้ "ชื่อปัจจุบัน" เสมอ

**พี่กันเคาะเอง 8 กันยายน 2569** ตอนถูกถามว่าจะเอาแบบไหน

> *"ชื่อยาควรเปลี่ยนนะ เพราะชื่อยาที่เปลี่ยนควรเป็นปัจจุบัน เพราะไม่งั้นมันไม่สวย
>  และการเปลี่ยนชื่อยา **เราไม่ได้เปลี่ยนชนิดยาสักหน่อย เราอาจจะแค่ใส่บางคำเพิ่มแค่นั้น**"*

🔑 **การเปลี่ยนชื่อยาในคลัง = แก้คำให้ครบขึ้น ไม่ใช่เปลี่ยนตัวยา**
เติมความแรง เติมรูปแบบ เติมตัวย่อ — ยาตัวเดิมทั้งนั้น
ประวัติที่ค้างชื่อเก่าไว้จึงไม่ได้ "ตรงกับความจริงวันนั้น" แต่กลายเป็น **ชื่อที่ยังไม่ครบ ค้างอยู่ตลอดไป**

| เก็บอะไร | ใช้ตอนไหน |
|---|---|
| **รหัสยา** (`drug_id`) | **เอาไปดึงชื่อปัจจุบันจากคลังมาแสดง** ← ทางหลัก |
| **ข้อความชื่อยา** ที่แช่ไว้ | **ตาข่ายสำรอง** — ใช้เมื่อไม่มีรหัส (พิมพ์เอง · เคสเก่าก่อนมีคลัง) หรือยาถูกลบจากคลังไปแล้ว |
| **ราคา · หน่วย** | ยังต้องแช่ไว้เหมือนเดิม **ห้ามดึงของปัจจุบันมาใช้** |

🚨 **แยกให้ออกระหว่างชื่อกับราคา**
ราคาเปลี่ยน = **มูลค่าเปลี่ยนจริง** ตัวเลขย้อนหลังต้องไม่ขยับ
ชื่อเปลี่ยน = **คำเรียกของสิ่งเดิม** ทุกที่ควรเรียกให้ตรงกัน

⚠️ **กฎข้อนี้เคยเขียนกลับด้าน** — เดิมเขียนว่า *"ยาเปลี่ยนชื่อ → ประวัติยังเห็นชื่อที่ใช้ตอนนั้น"*
เขียนไว้ตอนออกแบบเว็บมูลค่ายาคืน โดยเอาเหตุผลของ**ราคา**มาใช้กับ**ชื่อ** ทั้งที่คนละเรื่องกัน
เว็บยาคืนแก้ตามแล้ว 8 ก.ย. 2569 — ทำที่ชั้นฐานผ่าน `mr_drug_label()` ครบทุกทาง

⚠️ **ข้อ 1 กับข้อ 9 อยู่ด้วยกันได้ ต้องเก็บทั้งสองอย่าง**

| เก็บอะไร | ไว้ทำอะไร |
|---|---|
| `drug_id` | จับกลุ่มสถิติ (ข้อ 1) |
| `drug_name` | **ตาข่ายสำรอง** — ใช้เมื่อไม่มีรหัสยา หรือยาถูกลบจากคลัง |

| `unit` | หน่วยนับ ณ ตอนนั้น |

### ข้อ 21 — UUID สำรอง 🔴

```js
export function newUuid() {
  if (typeof crypto !== 'undefined' && crypto.randomUUID) return crypto.randomUUID();
  return 'xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx'.replace(/[xy]/g, (c) => {
    const r = (Math.random() * 16) | 0;
    return (c === 'x' ? r : (r & 0x3) | 0x8).toString(16);
  });
}
```

**`crypto.randomUUID` มีเฉพาะ https กับ localhost**
เปิดเว็บผ่าน `http://192.168.x.x` (เทสจากมือถือในวงแลนโรงพยาบาล) จะเป็น `undefined`
→ ฐานข้อมูลตีกลับเพราะ id ไม่ใช่ uuid → **ถ้าดัก error เงียบจะขึ้น "บันทึกแล้ว" หลอก ทั้งที่ข้อมูลไม่เข้า**

## 🔴🔴 ห้ามเดาข้อมูลยาแล้วเขียนลงตารางนี้

> **บทเรียนหนัก 12 ส.ค. 2569 — พี่กันโกรธมาก**

แคลร์ใส่ตัวย่อยา **127 ตัว** ลงช่อง `abbrev` เอง โดยพี่กันยังไม่ได้ตรวจ
ในนั้นมีที่ **คิดขึ้นเองล้วน ๆ** — `METRO` · `AMLO` · `SIM` · `OME` · `WAR` · `DICLO`
ซึ่งไม่ใช่ตัวย่อที่เภสัชกรใช้จริง แค่ตัดคำให้สั้น
และใส่ `PARA` ทั้งที่พี่กันสั่งชัดว่าไม่ต้องใส่

**ตารางนี้ใช้ร่วม 3 เว็บ ข้อมูลมั่วกระจายทุกที่ทันทีที่รันคำสั่ง**

### กฎ

- 🚨 **ข้อมูลยาที่ไม่มีแหล่งอ้างอิง = ห้ามใส่** ให้ถามพี่กัน (เภสัชกร) เสมอ
- 🚨 **"ลิสต์มาให้ดู" = ให้เสนอ ไม่ใช่ให้ลงมือ** ต้องรอเคาะก่อน
- 🚨 **แก้ข้อมูลจริงต้องขออนุมัติเป็นรายการ** แสดงตาราง "จากอะไร → เป็นอะไร" แล้วรอ "โอเค"
- 🚨 ข้อมูลผิดในระบบยา = **เลือกยาผิดตัว** ไม่ใช่แค่หน้าจอไม่สวย

**ตัวอย่างที่ผิดพลาดจริง** — `FeSO4` ถูกใส่ให้ `Ferrous fumarate`
แต่ FeSO4 คือ ferrous **sulfate** เป็นคนละเกลือกัน

### 🏷 ช่อง `brand` ใส่อะไร — กติกาที่พี่กันเคาะ (11 ก.ย. 2569)

### อย่างที่ 1 — ตัวช่วยกลาง `lib/apiError.ts`

```ts
import { NextResponse } from 'next/server';
import { maskHn } from './maskHn.ts';

/** ข้อความมีตัวอักษรไทยไหม — ใช้แยกว่าเป็นข้อความที่ตั้งใจเขียนให้คนอ่าน */
const เป็นภาษาไทย = (s: string) => /[฀-๿]/.test(s);

export function apiFail(where: string, e: unknown, fallback: string, status = 500) {
  const raw = e instanceof Error ? e.message : String(e);

  console.error(`[${where}] ${maskHn(raw)}`);
  if (e instanceof Error && e.stack) console.error(maskHn(e.stack));

  // 🚨 ข้อความจากฐานเป็นภาษาช่าง มีชื่อตาราง ชื่อคอลัมน์ ชื่อกฎอยู่ข้างใน
  //    ส่งกลับทั้งดุ้นแล้วผู้ใช้อ่านไม่รู้เรื่อง และคนที่จะเจาะเว็บได้แผนผังฐานฟรี
  //    ข้อความไทยที่ตั้งใจเขียนให้คนอ่าน ส่งต่อได้ เช่น "HN นี้มีอยู่แล้ว"
  //
  // 🚨🔴 ต้องปิดบังฝั่งที่ส่งกลับด้วย ไม่ใช่ปิดบังแค่ตอนเขียนบันทึก
  //    ข้อความที่ฐานสร้างเองมีตัวอักษรไทยปนได้ (ชื่อสถานที่ ชื่อคน ที่อยู่ในกฎของตาราง)
  //    มีไทยแม้ตัวเดียว ทางนี้จะส่งข้อความดิบกลับทั้งดุ้น พร้อมเลขผู้ป่วยที่ติดมา
  //    ไปโผล่บนหน้าจอผู้ใช้ = รูรั่วอีกทางที่การปิดบังฝั่งบันทึกกันไม่ถึง
  const msg = เป็นภาษาไทย(raw) ? maskHn(raw) : fallback;

  return NextResponse.json({ isOk: false, error: msg }, { status });
}
```

### อย่างที่ 2 — ปิดบัง HN `lib/maskHn.ts`

```ts
export function maskHn(s: string): string {
  return s
    // เลขที่ตามหลังคำว่า HN
    // รับทั้ง "HN 14820" · "HN14820" · "hn: 14820" · "(hn)=(14820)"
    // 🚨 ห้ามใส่ \b ปิดท้าย hn — "HN14820" ตัว N ติดกับ 1 ซึ่งเป็นอักขระคำทั้งคู่
    //    จึงไม่มีขอบเขตคำให้จับ แล้วเลขจะหลุด (ชุดทดสอบจับได้ตอนเขียนรอบแรก)
    .replace(/\bhn\s*[:=)(]*\s*[0-9]+/gi, 'HN ***')
    // เลขล้วน 4 หลักขึ้นไปที่ลอยอยู่ในข้อความ (HN ของที่นี่เป็นตัวเลขล้วน 4-6 หลัก)
    // ตัวตรวจหน้าหลังกันไม่ให้ไปโดนเลขบรรทัด ชื่อไฟล์ หรือรหัสสุ่มที่ปนตัวอักษร
    .replace(/(?<![0-9a-zA-Z_.\-:])[0-9]{4,}(?![0-9a-zA-Z_.\-:])/g, '***');
}
```

🚨 **แยกเป็นไฟล์ของตัวเอง ห้ามรวมกับ `apiError.ts`** เพราะตัวนั้น import `next/server`
ซึ่งชุดทดสอบที่รันด้วย `node` ตรง ๆ เรียกไม่ได้

| จุดที่เงียบ | เกิดอะไรถ้าล้ม |
|---|---|
| โหลดร่างจากเซิร์ฟเวอร์ | แถบล็อตค้างไม่ขึ้น โดยไม่มีใครรู้ |

### `lib/clientLog.js` — ฉบับฝั่งเบราว์เซอร์

```js
import { safeErrLine } from './maskHn';

/** ผู้ใช้เสียประโยชน์จริง — ของที่ควรได้ไม่ได้ หรือได้ของเก่าโดยไม่รู้ตัว */
export function logFail(where, e) {
  try { console.error('[' + where + '] ' + safeErrLine(e)); } catch (err) {}
}

/** ล้มได้ตามปกติ แต่ยังอยากเห็นตอนไล่บั๊ก — ที่เก็บเต็ม · โหมดส่วนตัว · ปิดสิทธิ์ */
export function logWarn(where, e) {
  try { console.warn('[' + where + '] ' + safeErrLine(e)); } catch (err) {}
}
```

🚨 **แยก `logFail` กับ `logWarn` ให้ชัด** ใช้ `logFail` กับทุกอย่างจะทำให้คอนโซลเต็มไปด้วยเสียงรบกวน
แล้วเรื่องที่สำคัญจริงจะจมหายไป

🚨 **ปิดบังเลขผู้ป่วยก่อนร้องเสมอ** คอนโซลก็เป็นที่ที่คนอื่นเปิดดูได้
(ยืมเครื่อง · ส่วนขยายที่อ่านคอนโซล · ภาพหน้าจอที่ส่งต่อกัน)

### 🔴🔴 กับดักที่ 4 — ร้องออกมาแล้วได้ "[object Object]" (2 ก.ย. 2569 ที่ ME-DRP)

เขียนตัวช่วยกลางเสร็จ ทดสอบด้วยฐานที่ต่อไม่ติดจริง แล้วได้บรรทัดนี้

```
[useRecords.loadRecords (ดึงรายงานจากฐานไม่สำเร็จ)] [object Object]
```

**ต้นเหตุ:** `supabase-js` ไม่ได้โยน `Error` แต่โยน**ก้อนข้อมูลธรรมดา** `{ message, code, details, hint }`
โค้ดในสกิลนี้เขียนว่า `e instanceof Error ? e.message : String(e)` — ตกมาทาง `String(e)` ได้ `"[object Object]"`
**ร้องแล้วอ่านไม่รู้เรื่อง = ไร้ประโยชน์พอ ๆ กับเงียบ** แต่หลอกให้คิดว่าทำเสร็จแล้ว

**ต้องดึงเนื้อในออกมาเอง**

```ts
if (typeof e === "object") {
  const o = e as { message?: unknown; code?: unknown; details?: unknown; hint?: unknown };
  // 🚨 ช่อง code ห้ามปิดบัง — รหัสของ Postgres เป็นเลข 5 ตัว (23505 บันทึกซ้ำ · 42P01 ไม่มีตาราง)
  //    ตัวปิดบังจะมองว่าเป็นเลขผู้ป่วยแล้วกลบทิ้ง ทั้งที่เป็นกุญแจดอกแรกของการไล่บั๊ก
  const เนื้อความ = [o.message, o.details, o.hint].filter(Boolean).map((x) => maskHn(String(x)));
  return (o.code ? ["รหัส " + String(o.code), ...เนื้อความ] : เนื้อความ).join(" · ");
}
```

## 32. 🔴🔴 ฐานส่งข้อมูลให้แค่ 1,000 แถวแล้วหยุดเงียบ ๆ

**ทุกเว็บที่ใช้ Supabase เจอเหมือนกันหมด** และเป็นเรื่องที่จะกัดวันที่ข้อมูลโต

> *"**ทุกเส้นที่ข้อมูลโตได้ต้องวนดึงทีละ 1,000 แถว** —
>  PostgREST ตัดที่ 1,000 แถว **แบบเงียบ ๆ ไม่มี error**"*

### ทำไมอันตราย

ไม่ใช่ความผิดพลาด **เป็นการตั้งใจของ Supabase** เพื่อกันคนเผลอดึงทั้งตารางจนเซิร์ฟเวอร์ล่ม
แต่วิธีเตือนแย่มาก — **ส่ง 1,000 แถวมาเฉย ๆ เหมือนข้อมูลมีแค่นั้นจริง ๆ**
ไม่มีคำเตือน ไม่มีอะไรผิดพลาด **โค้ดทำงานปกติทุกอย่าง**

เหมือนสั่งยา 3,000 เม็ด บริษัทส่งมา 1,000 พร้อมใบส่งของที่เขียนว่า "ครบถ้วน"

**อาการคือตัวเลขในหน้าสรุปจะเริ่มขาดหายไปเงียบ ๆ ตอนข้อมูลแตะ 1,000**
ไม่มีใครรู้จนกว่าจะมีคนสังเกตว่ายอดมันแปลก

### วิธีแก้ — วนดึงจนหมด ไม่ใช่ตั้งเพดานให้สูงขึ้น

```ts
export async function ดึงครบทุกแถว<T>(ดึง: (เริ่ม: number, จบ: number) => any): Promise<T[]> {
  const ทั้งหมด: T[] = [];
  for (let หน้า = 0; ; หน้า++) {
    const { data, error } = await ดึง(หน้า * 1000, หน้า * 1000 + 999);
    if (error) throw error;
    ทั้งหมด.push(...(data ?? []));
    if (!data || data.length < 1000) break;     // ได้ไม่ครบพัน = หมดแล้ว
  }
  return ทั้งหมด;
}
```

🚨 **ตั้งเพดานให้สูงขึ้นแทนไม่ได้** — ไม่ว่าตั้งเท่าไหร่ วันหนึ่งข้อมูลก็จะโตเกินอยู่ดี
🚨 **ใช้กับทุกเส้นที่ข้อมูลโตได้** — รายการยาคืน · รายงาน · ประวัติ · บันทึกการแก้
ยกเว้นตารางที่จำกัดจำนวนแน่นอน (เช่นการตั้งค่าที่มีแถวเดียว)

**ตรวจว่าเว็บนี้เสี่ยงไหม**
```bash
grep -rn "\.from(" app/api/ lib/ | grep -v "\.range(\|\.limit(\|\.single()"
```

## 33. 🔴🔴 `upsert` กับตารางคอลัมน์เยอะ ล้างช่องที่ไม่ได้ส่งเป็นค่าว่าง

**ผิดครั้งเดียว ชื่อยา 417 ตัวหายพร้อมกันทั้ง 3 เว็บ**

> *"`/api/prices` เดิมใช้ `upsert` กับ `mr_drug_price` ซึ่งมีแค่ 6 คอลัมน์
>  พอย้ายมา `drugs` ที่มียี่สิบกว่าคอลัมน์ **ช่องที่ไม่ได้ส่งไปจะโดนล้างเป็น NULL ทั้งหมด**
>  = ชื่อยา ความแรง รูปแบบ หายเกลี้ยงทั้งตาราง"*

### กลไก

`upsert` แปลว่า "มีอยู่แล้วก็แทนที่ ไม่มีก็สร้างใหม่" — คำสำคัญคือ **แทนที่**
ส่งไป 3 ช่อง แถวนั้นจะเหลือ 3 ช่อง **อีก 17 ช่องถูกล้างเป็นค่าว่าง**

ตอนตารางมี 6 คอลัมน์แล้วส่งครบ 6 จึงไม่มีปัญหา **พอตารางโตขึ้นแต่โค้ดยังส่งเท่าเดิม = พัง**

### กฎ

| จะทำอะไร | ใช้อะไร |
|---|---|
| แก้บางช่องของแถวที่มีอยู่แล้ว | **`update` รายแถว** |
| เพิ่มแถวใหม่ | `insert` |
| จำเป็นต้องใช้ `upsert` จริง ๆ | **ส่งทุกคอลัมน์ให้ครบเสมอ** |

🚨 **ตารางที่ใช้ร่วมหลายเว็บ ห้ามใช้ `upsert` เด็ดขาด** เพราะเว็บอื่นอาจเพิ่มคอลัมน์
โดยที่เว็บนี้ไม่รู้ แล้ววันหนึ่งคำสั่งที่เคยถูกก็กลายเป็นคำสั่งล้างข้อมูล

⚠️ **ตระกูลเดียวกับบั๊กส่งหลายแถวพร้อมกัน** — PostgREST รวมรายชื่อช่องจากทุกแถวเป็นชุดเดียว
แถวไหนไม่มีช่องนั้นถูกเติมค่าว่าง **ถ้าแถวมีชุดช่องไม่เท่ากันต้องแยกกลุ่มก่อนเสมอ**

## 37. 🔴🔴 ตัวนับที่อยู่ใน `case` ถูกคิดทุกครั้ง — การแปลงค่าที่ล้มได้ต้องทำนอกตัวนับ

**เจอจริง 17 ก.ย. 2569 ที่ warfarin** — ตัวกรองกลุ่มเดียวทำให้อีก 14 กลุ่มในหน้าเดียวกันพังทั้งหมด

```sql
-- ❌ ดูเหมือนแปลงวันที่เฉพาะตอนเป็นกลุ่มวันนัด แต่จริง ๆ แปลงทุกครั้ง
select jsonb_build_object(...)
  || case when p_band ~ '^day_[0-9]{4}-[0-9]{2}-[0-9]{2}$'
       then jsonb_build_object(p_band, count(*) filter (where next_visit = to_date(substr(p_band, 5), 'YYYY-MM-DD')))
       else '{}'::jsonb end
from base
```

### กลไก

ฐาน (Postgres) **คิดตัวนับทุกตัวก่อน** แล้วค่อยเอาผลไปตัดสิน `case`
`case` จึงกันการคิดตัวนับไม่ได้ — ต่างจากนิพจน์ธรรมดาที่ `case` ข้ามทางที่ไม่ใช้ได้จริง
ส่ง `p_band = 'today'` มา ฐานก็ยังพยายามแปลง `'y'` เป็นวันที่ → ล้มทั้งคำขอ ตารางโหลดไม่ขึ้น

### กฎ

- 🚨 **ค่าที่แปลงแล้วอาจล้ม (วันที่ · ตัวเลข · รหัส) ห้ามแปลงข้างในตัวนับ** (`count` `sum` `avg` `min` `max` `filter` ทุกแบบ)
- ✅ **แปลงครั้งเดียวในส่วนแยก** ด้วย `case` ธรรมดาที่ตรวจรูปแบบก่อน แล้วให้ตัวนับกับตัวกรองใช้ค่าที่แปลงแล้ว
  ```sql
  fb as (
    select case when p_band ~ '^day_[0-9]{4}-[0-9]{2}-[0-9]{2}$'
                then to_date(substr(p_band, 5), 'YYYY-MM-DD') end as day
  ),
  cnt as (
    select ... || case when p_band ~ '^day_...'
                       then jsonb_build_object(p_band, count(*) filter (where next_visit = fb.day))
                       else '{}'::jsonb end
    from base cross join fb        -- 🔴 ห้ามใส่ group by ค้นไม่เจอใครแล้วตัวนับจะไม่คืนแถวเลย
  )
  ```
- 🚨 **แก้ฟังก์ชันแบบนี้แล้ว ต้องยิงทุกค่าที่มันรับ** ไม่ใช่เฉพาะค่าที่เพิ่ม (สกิล `testing-proof`)
  บั๊กตัวนี้ผ่านการตรวจมาได้เพราะค่าที่เลือกตรวจสั้นพอจนแปลงแล้วไม่ล้ม

ตัวจริงที่แก้แล้ว — `warfarin-dash/scripts/007_wf_patient_page.sql` ส่วน `fb` · รันเข้าฐานเป็น `wf_023_band_count_fix`
